S1. 100dvh 面板限高在旧 iOS 没有 100vh 兜底
文件/行：styles.css:1016（.tutorial-panel max-height:100dvh）、
:1108（.rules-sheet）、:1177（≤560 两块）、:1318（横屏两块）。
现象：只有 body 在 18-19 行有 100vh + 100dvh 双行；这四处面板只有
100dvh。iOS 15.0–15.3 不支持 dvh 时 max-height 整条失效，教程/规则面板
可能超出视口，关闭按钮/底部操作被裁掉。交接注意事项只写“body 两行并存”，
不能推出面板也退化。
建议二选一：
- 每处 100dvh 前加一行 max-height:100vh（最直接）；或
- 用 .tutorial-overlay { overflow:auto } + 面板 max-height:100% /
  height 兜底，避免依赖 dvh。
这是兼容性修复，不影响现代浏览器。

S2. 640×360 横屏 Q3 的题干/金额输入需滚动，验收口径不明确

兼容性风险：
- interactive-widget=resizes-content 只有 Chromium 支持；Android Chrome
  弹键盘时布局视口缩小，sticky 吸顶区通常留在顶部，但软键盘+sticky 的
  实际位置需要真机确认；iOS Safari 忽略该键，键盘可能覆盖底部，
  当前无 JS（T12 正确）也没有 visualViewport 监听。可接受的做法是保留
  交接里的真机清单并逐项记录；若要主动缓解，可评估 CSS-only 的
  focus-within/scroll-margin 方案，但不能在本轮擅自加 JS 滚动。
- iOS 15.0–15.3 没有 dvh：body 有 100vh 兜底，教程/规则面板没有（S1）。
- env()=0 的桌面标签页安全：所有 env 有 0px 兜底，变量存在，T3 通过。
- 所有 10 个 <input> 都带 class="input"（金额输入带 "input amount-input"），
  src 中没有裸 input/select/textarea；16px 规则覆盖了所有 input，
  但 .amount-input 被覆盖成 16px（M1）。
- 固定 footer 和 fixed 覆盖层的 safe-area 见 M2；这两处是纯 CSS 可修的，
  不需要 JS。
