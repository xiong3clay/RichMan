二、数据流（判定顺序不可换）
HTTP POST /api/rooms：
  Origin 403 {ORIGIN_NOT_ALLOWED}
  → 非空非 JSON 415 {UNSUPPORTED_MEDIA_TYPE}（空 body 仍按 {}）
  → IP 建房桶 429 {RATE_LIMITED}
  → roomCount >= maxRooms 503 {ROOM_LIMIT}
  → createRoomPersisted 201 {ok,roomCode}
WS upgrade：
  Origin 403（不升级）→ guard.admit 503（不升级）→ 升级 → init
WS 消息：
  每连接 60/s 粗限流 → 大厅消息/游戏命令分流
  游戏命令：全局命令桶 10/s( burst 20, key=房间码|玩家ID ) →
            经济命令桶 5/s( burst 10, key=房间码|玩家ID|type ) → 处理器
  join/resume：IP/房间桶 → transact（含身份/epoch 校验）→ bind
HTTP 未知 /api/*：404 {NOT_FOUND}（不回退 index.html）。

三、协议 / 存档格式
- 消息形状与 PROTOCOL_VERSION 不变。
- 存档 schema 不变；NicknameSchema 只在 join 时校验，历史快照里的昵称不重新校验，
  不需要迁移；不会因新校验导致旧房载入失败。
- 新增错误码（JSON error / WS error）：
    ORIGIN_NOT_ALLOWED（403）
    UNSUPPORTED_MEDIA_TYPE（415）
    RATE_LIMITED（429 HTTP / WS error）
    ROOM_LIMIT（503）
    TOO_MANY_CONNECTIONS / TOO_MANY_UNAUTHENTICATED（WS 升级 503 reason）
    INVALID_MESSAGE "连接超时，请重新加入" + WS close code 4003 AUTH_TIMEOUT
  既有错误码（ROOM_NOT_FOUND / ROOM_FULL / INVALID_NICKNAME / NOT_JOINED /
  UNAUTHORIZED / REPLACED / ERROR_PAUSED 等）语义未变。

四、环境变量（运维必读）
  RICHMAN_ALLOWED_ORIGINS   逗号分隔完整 origin，如 https://abc.trycloudflare.com
  RICHMAN_TRUST_PROXY=1     仅此时读 X-Forwarded-For 第一段；默认关
  RICHMAN_MAX_CONNECTIONS   总连接上限，默认 200；非正整数忽略
  RICHMAN_MAX_CONNECTIONS_PER_IP  单 IP 上限，默认 20；非正整数忽略
  RICHMAN_MAX_ROOMS         房间上限，默认 50；非正整数忽略
  非法值一律回退默认，不阻止服务启动。
隧道/反向代理部署时：若需要按真实客户端 IP 限流，必须同时设置 RICHMAN_TRUST_PROXY=1
且保证代理会覆盖/清洗 X-Forwarded-For；直连公网不要开。

七、不可破坏的不变量（09B 及以后）
1) 默认阈值必须与规格一致（200/20/60/50/60s/60/20/10/10/5/10/10/10/20/5/10/30）。
2) HTTP 判定顺序 Origin → Content-Type → 限流 → 房间上限；WS 升级必须先 Origin
   后配额，失败都不得升级。
3) 未认证超时 close code 4003、reason AUTH_TIMEOUT；错误消息只带 code/固定文案，
   不输出 token、恢复码、原始消息。
4) 命令限流发生在 processor 之前，超限不得改状态/version；命令桶 key 必须含
   房间码|玩家ID，经济命令桶再含 type（跨房间不得共用额度）。
5) ConnectionGuard release(ip, authenticated) 幂等且必须传真实的 conn.authenticated；
   bind 只 markAuthenticated 一次；init 必须把 Connection 创建包进 try 并恰好释放一次；
   guard.admit 之后必须有唯一归属：握手失败由 socket.once("close") 回收，
   成功回调认领后交给 Connection；onUpgrade catch 用 releaseIfUnclaimed；
   403/503 不得新增释放；任何终止路径结束后 guard 必须归零；
   HTTP 与 WS 必须共用 startServer 创建的同一 runtime。
6) 安全头对所有 JSON 与静态响应生效，不能只给 /health。
7) API 命名空间必须用 decodedPath 路由，且只接受 url.pathname===decodedPath 的原样路径；
   未知 /api/*、/api、编码路径（%2F 等）一律 JSON 404，不得回退 index.html。
8) 昵称控制字符校验错误文案固定为"昵称不能包含控制字符"；码点上限仍 20。
9) 满房 join 必须消耗 fullJoinBucket；前 joinBurst 次仍 ROOM_FULL，之后 RATE_LIMITED；
   rooms.test 第 11 人契约不得破。
10) TokenBucket 必须保留 tryTake 的惰性 prune（size>=1024 清 10 分钟未用 key），
    不得退回只增不减。
11) 旧 731 条测试不得删改跳过；新增测试只能追加。
