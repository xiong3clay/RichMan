一、F1（M1）移动端金额输入必须保持 18px
事实：apps/web/src/styles.css:711-717 `.amount-input{font-size:18px}`；
:1276-1283 的 @media(max-width:560px) 里 `.input, select, textarea{font-size:16px}`
特异性相同且更靠后，导致 360/390 金额框实为 16px（Qoder 用真实 build 的 computed
style 复现）。交接文档还写成“18px 不动”，必须一起改正。
修法（在 08B 段落末尾追加，特异性 0,2,0 稳定胜过 .input）：
  .input.amount-input {
    font-size: 18px;
  }
验收：360×640 与 390×844 下 getComputedStyle(.amount-input).fontSize === "18px"；
桌面不变；.input 非金额仍 16px（≤560）。

二、F2（M2）安全区补全：固定 footer、规则页顶部、覆盖层左右
事实（Qoder 实测）：.footer（styles.css:435-449）fixed + padding:10px 18px，无
safe-bottom/left/right；.rules-sheet（:1104-1119）只有 08B 追加的 padding-bottom，
没有 safe-top；.tutorial-overlay（:999-1008，≤560 时 :1169-1172 padding:0）没有
safe-left/right，横屏 640 宽时刘海可能压内容。
修法（全部写在 08B 段落末尾，按此顺序）：
  .footer {
    padding: 10px max(18px, var(--safe-right)) calc(10px + var(--safe-bottom)) max(18px, var(--safe-left));
  }

  .rules-sheet {
    padding-top: calc(18px + var(--safe-top));
  }

  .tutorial-overlay {
    padding: max(16px, var(--safe-top)) max(16px, var(--safe-right))
      max(16px, var(--safe-bottom)) max(16px, var(--safe-left));
  }

  @media (max-width: 560px) {
    .tutorial-overlay {
      padding: var(--safe-top) var(--safe-right) var(--safe-bottom) var(--safe-left);
    }
  }
注意：最后这个 560 块必须放在上面 .tutorial-overlay 覆盖之后（文件顺序靠后），
否则原 :1169 的 padding:0 会被提前覆盖、窄屏不再通栏。环境变量全部有 0px 兜底，
无刘海时行为与现在一致（footer 18px、规则页 18px、覆盖层 16px/0）。
