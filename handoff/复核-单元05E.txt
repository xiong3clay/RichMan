【级别 should-fix】多条反馈横幅会把事件通知架挤到接近 0 高
— apps/web/src/styles.css:409-423、426-430、432-442；apps/web/src/GameView.tsx:1281-1300
— 现状代码：
  .game-sticky { max-height:45vh; overflow-y:auto; gap:6px; ... }        (styles.css:415-417)
  .game-top { flex:none; ... }                                           (styles.css:426-430)
  .notice-shelf { flex:0 1 auto; min-height:0; max-height:32vh;
                  overflow-y:auto; margin:6px 0 10px; }                  (styles.css:432-442)
  {feedback} 是 .game-sticky 的直接子项，结果/error/notice 可同时渲染三条 (GameView.tsx:1281)。
— 为什么有问题：
  .game-sticky 总高被 45vh 封顶（360×640 时 288px），操作卡因此始终在 288px 以下，主目标“操作卡可见”成立；
  但 feedback 横幅没有被限制为“只显示一条”。每个横幅因 44px 关闭按钮至少约 64px 高；header 约 90–106px
  （且 styles.css:251 的 margin-bottom:16px 未在 sticky 内复位），两条反馈横幅 + gap 后，留给
  .notice-shelf 的高度只剩约 20–40px，小于单条事件的 64px。由于 .notice-shelf 是 flex:0 1 auto 且
  min-height:0，它会先被压缩到接近 0，用户必须先在 sticky 内部滚动才能看到事件通知。
  当前 360×640 截图只覆盖了“1 条失败横幅 + 通知架”，没有覆盖“结果横幅 + 本地 notice + 4 条事件”的组合，
  所以该挤压未被截图发现。
  交接文档 handoff/单元05E-注意事项.txt:6 写“子项 flex:none”，但实际只有 .game-top 是 flex:none；
  .notice-shelf 明确是 flex:0 1 auto（styles.css:436），该描述与实现不一致。
— 建议改法（任选其一，不要抬高 45vh）：
  a. feedback 同时只渲染一条，按“本地 notice > error > result”优先级取一条；
  b. 或给 .notice-shelf 保留最小可见高度（如 min-height:64px），让 feedback 自己进入 sticky 内滚动；
  c. 降低移动端 banner 内边距/关闭按钮占位，减少每条横幅高度；
  d. 补一张 360×640 下“结果横幅 + 本地 notice + 4 条事件”同时存在的截图，并同步修正注意事项:6 的
     “子项 flex:none”描述。

【级别 should-fix】吸顶/触控/换行没有自动化契约测试，改坏 CSS 仍会 404 全绿

    expect(classes.indexOf("game-top")).toBeLessThan(classes.indexOf("banner fail"));                    (311)
    expect(mounted.container.querySelector(".stage .banner")).toBeNull();                                 (318)
  tests/dom-harness.ts 中没有 getBoundingClientRect / scroll / clientHeight / offsetHeight，
  gameview.test.ts 也没有 import "../src/styles.css"（grep 均无结果）。
— 为什么有问题：

  删除 max-height:45vh、删除 .banner .link 的 44×44、删除 overflow-wrap:anywhere，404 条测试仍会全部通过。
  换句话说，05E 的核心修复（吸顶、上限、触控尺寸）没有回归保护。

  b. 把已用于验收的 Edge headless 截图脚本固化为可重复的视觉测试（至少覆盖 360×640），并在交接中记录运行命令。

【级别 should-fix】反馈横幅没有 live-region 语义，所有关闭按钮可访问名都叫“关闭”
— apps/web/src/GameView.tsx:1227-1260、1283-1298
— 现状代码：
  结果横幅：<div className={"banner " + ...}>(1228) ... <button type="button" className="link" ...>关闭</button>(1234-1236)
  error：<div className="banner fail">(1240) ... 关闭(1244-1250)
  本地 notice：<div className="banner fail">(1254) ... 关闭(1256-1258)
  事件架：<div className="notice-shelf" role="status">(1283) ... 每条内也有“关闭”(1287-1296)
— 为什么有问题：
  只有 .notice-shelf 带 role="status"；命令结果、服务端 error、本地校验 notice 这三类最关键提示没有
  role="alert"/aria-live，屏幕阅读器不会主动播报。多个按钮的可访问名完全相同（全部为“关闭”），
  在同时存在结果/错误/本地提示/事件通知时无法区分。把可交互 button 放在 role="status" 的 live region 内，
  部分阅读器会在播报时连按钮一起读出，语义也不理想。
— 建议改法：
  a. 结果/error/本地 notice 的失败类横幅加 role="alert"（成功类可用 role="status"），或给 feedback 外层
     加 aria-live="polite"/"assertive"；
  b. 关闭按钮加 aria-label，例如 aria-label={"关闭结果提示：" + 文本摘要} / "关闭错误提示" / "关闭事件通知"；
  c. .notice-shelf 可考虑 role="log" 或 role="region" + aria-live，避免把按钮当作状态内容播报。
