单元 05F 注意事项：借款额度提示
日期：2026-11-05

一、规则与额度语义（不得回退）
1) bankBorrowLimitCents 是“真能借到”的上限，不是理论 50%：
   必须 min(floor(金币/2), MAX_MONEY_CENTS - 金币)。engine.ts:1340-1345 的 assertCentsRange 是硬约束，
   不要为了显示好看而放宽引擎上限，也不要在前端偷偷截断金额。
2) 银行借款前置条件仍是三条同时成立：credit === "GOOD"、cents > 0、无任何 status !== "REPAID" 的银行贷款。
   REPEATED 的已结清记录（REPAID）不能挡住再次借款——views.test.ts 有专门用例。
3) lenderLimits 取 min(对方金币, MAX - 本人金币)，与 acceptLoanRequest 的真实校验一致；
   出借人金币为 0 时该条为 0，前端必须禁用该候选，不能让它进入金额页后无路可走。
4) 额度为 0 的三种来源要区分文案：失信/有未结清贷款（bankBlockedReason 原因）、金币为 0（原因）、
   金币 1 分导致 floor(1/2)=0（“可借 0 分（当前金币不足以产生贷款额度）”）。

二、前端约定
1) bankLimitText 是唯一额度文案入口，优先级固定：blocked 原因 > 缺字段兜底 > 额度 0 > 数字。
   不要在 GameView 里再写一套“可借 0 分”的分支，否则会出现两段结论不一致。
2) withinLimit 只做“合法整数分是否超上限”的判断；非规范写法（1e4、0x1389、+5001、5001.0）返回 true，
   交回原有表单校验（会提示“必须是整数”），不要在这里判超限，也不要顺手把它们规范化。
3) 任何额度为 0 的入口（银行“是，输入金额”、Q1 候选）必须 disabled，并在同屏给出原因；
   允许进入再拦会复现 Qoder S3 的死路。
4) 行内红字固定用 p.step-hint.danger-text，且必须位于 .stage 内；测试用 .stage .danger-text 断言，
   基础提示里本来就有“最多可借 X 分”字样，不能用整页文本断言（否则删掉红字测试仍绿）。

三、隐私取舍（已知并接受）
- Q1 候选显示“最多可借 X 分”，在正常区间内 X 等于对方金币，等于向借款人披露对方当前资金。
  这是方案 V1.3.3 第六节 3.1 的明确要求，Qoder 复核已确认；若要隐藏，删掉 lenderLimits 并把 Q1 文案
  回退为“金额上限以服务端为准”，不影响其他逻辑。

四、运行与进程
- 服务器/隧道由 Windows 计划任务托管，创建时必须带 -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries，
  否则笔记本电池模式下任务不运行。
- DSH 命令结束时可能给同进程组发 Ctrl+C（exit 3221225786），不要用 Start-Process 直接拉长驻进程。
- 校园网 sdu_net 客户端隔离，手机只能用隧道域名，不能直连 10.25.241.x:8000；换域名后旧 token 失效，
  用「房间码 + 恢复码」恢复。
