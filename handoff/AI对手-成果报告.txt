RichMan 单人练习（AI 对手）成果报告
=====================================
日期：2026-11-15
范围：为 RichMan 增加「单人练习：AI 对手」模式，一个人（无第二位玩家、无第二台设备）
      也能完整玩完一局。规则口径以 V1.3.2 为准，AI 与真人完全同规则。

一、结论
--------
1. AI 不新增引擎入口：所有动作都是标准 GameCommand，actorId = AI 的 playerId，
   经 apps/server/src/rooms/command-queue.ts 的 GameCommandProcessor.execute()
   与真人走同一条队列；审计 eventSeq、commandId 幂等、存档/恢复、回放天然生效。
2. 引擎仍是纯函数；AI 只读 EngineState，不修改状态、不加钱、不豁免失信/负债/税收/赌博规则。
3. 金额全部是整数分（Cents），未引入任何新依赖。
4. 新增 5 个测试文件、30 条测试；既有测试的断言未改。
5. tsc 与 build 通过；本地 pnpm dev 实测：建房(bots=1) → 入座自动准备 → 自动开局 →
   AI 连续行动到第 3 轮，无卡死、无非法命令、无服务端错误。

----------------
服务端（规则外，不碰 packages/game-core）：
- packages/shared/src/protocol.ts
    LobbyPlayerSchema 增加可选 isBot（人类省略该字段，保持旧消息形状）；
    LOBBY_ERROR_CODES 增加 INVALID_BOTS。

    大厅房主转移只交给真人；只剩 AI 的房间直接回收；
    restoreRoom 不把 AI 占位串写进 token 索引；
    viewOf 只对 AI 输出 isBot: true。
- apps/server/src/http.ts
    POST /api/rooms 支持 bots 字段（缺省 0）；非整数/越界（含 null）返回 400 INVALID_BOTS，

    start/rematch/resume_game 也 notify；destroy_room 调 cancelRoom；close() 调 botDriver.close()；
    snapshot 从大厅成员取 AI 标记，注入 me.isBot / publicPlayers[].isBot（仅展示，不参与规则）。
- apps/server/src/bots/policy.ts（新）
    纯函数 decideBotCommand(state, botPlayerId, nowMs, rng): GameCommandDraft | null。
    阶段策略：INTEREST 无命令；BANK_DUE 结清/拒绝；ACTION 依次私人还款 → 临期银行还款 →
    低现金借最小额度 → END_ACTION；BETTING rng<0.6 跳过，否则押 1 点、金额 min(10分, 现金10%)；
    TAX 只应答当前等待窗口的私人借款请求。所有命令先自查金额/额度/信用/轮次，
    不产生会被引擎拒绝的非法命令。
- apps/server/src/bots/driver.ts（新）
    监听房间提交；对每个 isBot 成员决策，延迟 700–1500ms（构造可配，测试传 0）后
    经 processor.execute 提交；同一 (gameId, phaseInstanceId, botId[, loanId/requestId/seat])
    只驱动一次；执行前用最新状态复核阶段/座位/请求并刷新 expectedGameVersion；
    任何异常只记日志，不阻塞房间，既有超时推进兜底；cancelRoom/close 清理定时器与幂等记录。
- apps/server/src/storage/types.ts
    RoomSnapshot.players 增加可选 isBot；
    discardPendingDeliveries 只在 hostId 非空时重新选房主，且只选真人。
- apps/server/src/storage/file-store.ts
    validateSnapshot 支持 AI 座位：tokenDigest 允许占位串、会话数按真人计、
    sessions 不得引用 AI、房主必须是真人、纯 AI 大厅允许 hostId=null；
    loadAll 恢复时只有真人置离线，AI 保持在线。

三、新增消息字段（协议版本不变，仍是 1）
----------------------------------------
1. HTTP 建房请求：POST /api/rooms
   body: { "nickname": "…", "bots": 1 }   // bots 可选，0..9 的整数，缺省 0
   失败：400 { "ok": false, "error": "INVALID_BOTS" }
2. 服务端 room 消息的玩家项：
   { playerId, nickname, seatId, ready, online, isBot?: true }
   只对 AI 座位输出 isBot；人类玩家不写该字段（旧客户端/旧断言形状不变）。
3. 服务端 snapshot 视图：
   view.me.isBot?: true
   view.publicPlayers[].isBot?: true
4. 没有新增 WebSocket 消息类型；AI 命令复用现有 GameCommand 信封与全部错误码。
   注意：浏览器提交命令时金额字段必须是规范十进制字符串（既有协议要求）；
   AI 在服务端进程内直接构造整数分（number），processor.toEngineCommand 会统一处理。

四、AI 第一版策略（简单但合理，不做搜索/评估）
----------------------------------------------
- INTEREST：无需命令。
- BANK_DUE：只处理自己为借款人的待决策贷款；现金足够就 REPAY，不足则 REFUSE（引擎只接受
  这两种，且引擎在现金不足时会直接按失信结算）。
- ACTION（仅自己回合，且未先应答请求）：
  ① 有 ACTIVE 私人债且现金够 → REPAY_PRIVATE（一次还清）；
  ② 有 ACTIVE 银行债且下一轮到期（dueRound=round+1）且现金够 → REPAY_BANK；
  ③ 现金 < 100 分、信用 GOOD、无未结清银行贷款 → BORROW_BANK，
     金额 = min(floor(现金/2), 100-现金)，即补到 1 元的最小额度；
  ④ 否则 END_ACTION。
- BETTING：未下注时 rng()<0.6 跳过（betCents=0，合法）；否则 guess=1、leverage=1，
  金额 = min(10 分, floor(现金/10))。
- TAX：不主动发起请求；只对当前等待窗口的私人借款请求作答。
- 私人借款请求：自己闲置现金 - 本金 >= 500 分且借款人当前信用 GOOD 且存活 → ACCEPT；
  否则 REFUSE。第一期不主动向真人借钱。
- 失信（credit=DEFAULTED）不会新增普通银行贷款；DEFAULTED 贷款不产生 REPAY_BANK。

七、已知问题 / 环境限制（与本功能无关）
--------------------------------------
1. 本执行环境（Trae 命令沙箱）会重定向 junction 目标：
   PowerShell 创建 junction 后 Target 指向 Trae 的 shadow 路径，Node 的
   fs.symlink(...,"junction") 也不产生可 lstat 的链接（lstat → ENOENT）。
   因此 3 条既有测试在本环境失败：backup.test.ts T21/T23、scripts.test.ts T26。
   这些文件与断言本次未改动；在正常 Windows 环境应恢复通过。
2. 进程/PowerShell 子进程类既有测试在并行高负载下会撞 5s/10s 测试超时
   （本次全量里是 backup T16、scripts T5；crash-recovery、stability、review06-crash、
   release-lib 等此前也出现过）。单独或小批量运行时这些测试均通过，本次已逐个复跑确认。
   在正常空闲环境跑 `corepack pnpm -s test` 应得到 972/972 全绿。
3. 未做真人真机验收：单人练习需要一个人实际从开局点到结束（见第五节步骤）。
