单元 05F：借款额度提示（施工规格）
版本：2026-11-05 / Lead 编写 / 依据：用户截图反馈 + 方案 V1.3.3 第六节 3.1

一、问题与目标
用户反馈（2026-11-05，附 Q1/Q2 截图）：“这些地方提示一下最多可以借到的钱”。
现状：Q1 私人金额步只写“金额上限以服务端为准”，Q2 银行金额步只写“上限为当前金币的 50%，最终以服务端为准”，
玩家看不到具体数字，只能试错。
方案 3.1 已要求：Q1“输入金额（0～对方可出借上限）”、Q2“显示可用额度区间（0～可借上限）”、
自身信息区含“可借额度”，且“所有金额范围与可用性以服务端快照为准”。
原版 C++（docs/reference/大富翁.cpp:520-527）银行借款也会打印“本次最多可向银行贷款 X 金币”。
目标：由服务端在每人快照中下发权威额度，前端 Q1/Q2/自身信息区显示具体数字；不改任何游戏规则。

二、服务端额度（唯一改动点：packages/game-core/src/views.ts）
在 PlayerFinanceView 增加两个字段（都用 Cents 整数）：

1) bankBorrowLimitCents: Cents
   - 仅当全部成立时 = min(ordinaryLoanCap(me.cents), MAX_MONEY_CENTS - me.cents)：
     a) me.credit === "GOOD"
     b) me.cents > 0
     c) 本人没有任何 status !== "REPAID" 的银行贷款（bank.ts 的 ACTIVE_LOAN_EXISTS 条件）
     其中 ordinaryLoanCap 见 packages/game-core/src/money.ts，等于 floor(cents/2)。
   - 为什么取 min（Qoder 复核 M1）：engine.ts:1340-1345 assertCentsRange 要求借款入账后余额 ≤ MAX_MONEY_CENTS，
     金币 999999999500 时 50% 上限 499999999750 会被服务端以 INVALID_AMOUNT 拒绝；只给 500 才是真能借到的数。
     不放宽引擎上限，也不在前端截断。
   - 任一不成立则为 0（不可借原因仍由前端 bankBlockedReason 文案给出，不在这里返回错误）。
   - 金币只有 1 分时 floor(1/2)=0：额度为 0 但 bankBlockedReason 为 null，前端必须按“额度 0”禁用入口（见 3.2）。

2) lenderLimits: { playerId: PlayerId; maxCents: Cents }[]
   - 对 state.players 中 alive === true 且 playerId !== viewerId 的每个玩家给一条：
     maxCents = max(0, min(该玩家 cents, MAX_MONEY_CENTS - me.cents))
   - 为什么取 min：acceptLoanRequest 要求出借人余额 ≥ 本金（否则请求 FAILED），且借款人余额 + 本金 ≤ MAX_MONEY_CENTS
     （private-loans.ts 会抛 INVALID_AMOUNT）。取两者较小值，前端显示的上限才真正可成。
   - 只给上限，不给对方 cents，不新增任何他人的金额、合同、下注字段。

注意：
- apps/server/src/ws.ts:55-58 的 wireCopy 会把 key === "cents" 或 key 以 "Cents" 结尾的数字转成十进制字符串，
  lenderLimits[].maxCents 会自动转换，不需要改 ws.ts / server。
- 不要改引擎行为、不要改 acceptLoanRequest/createLoanRequest 校验、不要改 shared 协议与 SNAPSHOT_SCHEMA_VERSION。
