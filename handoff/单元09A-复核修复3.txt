1) 单次握手失败：
   GET /ws + Upgrade: websocket 但缺 Sec-WebSocket-Key
   → 服务返回 400 "Missing or invalid Sec-WebSocket-Key header"
   → 之后 guard.stats() = {"total":1,"unauthenticated":1,"perIp":{"127.0.0.1":1}}

   → guard.stats() = {"total":20,"unauthenticated":20,"perIp":{"127.0.0.1":20}}
   （撞到 maxConnectionsPerIp=20 才停）
   → 同一 IP 的正常 WebSocket 连接被 503 拒绝：
     "Unexpected server response: 503"
   即 20 次无效握手就能把单个来源 IP 打满；换多个 IP 可把 maxUnauthenticated

根因：apps/server/src/ws.ts:508-520。guard.admit(ip) 在 handleUpgrade 之前，

initialized 永远为 false，配额无人释放。

F13（must）握手失败也必须释放配额，且只释放一次
----------------------------------------------------------------
文件：apps/server/src/ws.ts:508-520。

把 admit 之后到握手完成之间的配额做成“有唯一归属”：
- 握手未完成时，socket 的 close 负责回收；
- 握手成功后，归属转交 Connection，由 init catch / disconnected 释放；
- 任何路径都恰好一次，不允许双重 release。

建议实现（语义照此，写法可微调）：

    const ip = clientIp(req, security.limits);
    const admission = security.guard.admit(ip);
    if (!admission.ok) {
      rejectUpgrade(socket, 503, admission.code ?? "TOO_MANY_CONNECTIONS");
      return;
    }
    // 握手失败时 ws 内部 abortHandshake 直接写 400 并 destroy，不抛错也不回调；
    // 因此配额必须挂到 socket 的 close 上回收。
    let released = false;
    const releaseIfUnclaimed = (): void => {
      if (released) return;
      released = true;
      security.guard.release(ip, false);
    };
    socket.once("close", releaseIfUnclaimed);
    try {
      wss.handleUpgrade(req, socket, head, ws => {
        released = true;                                  // 认领：后续由 conn 释放
        socket.removeListener("close", releaseIfUnclaimed);
        init(ws, url.searchParams.get("room"), ip);
      });
    } catch {
      releaseIfUnclaimed();
      socket.destroy();
    }

要求：
1) 成功握手路径不得改变现有行为：init 仍负责 markAuthenticated，
   disconnected 仍按 conn.authenticated 释放一次（F1 语义不变）。
2) init 抛错路径仍由 init 的 catch 释放（F7，测试 39 必须继续绿）。
3) 403（Origin 拒绝）与 503（admit 失败）路径本来就没 admit/已提前 return，
   不得新增释放，避免减到别人的额度。
4) socket 已是 destroyed 时 removeListener 不抛错。

必测（新增 49）：
- 真实服务 + 原始 TCP：发缺 Sec-WebSocket-Key 的 upgrade，读回 400；
  waitFor guard.stats().total === 0 且 unauthenticated === 0；
- 连续 60 次无效握手后 guard 仍为 0，随后开一条正常 Peer join 成功
  （证明配额没有泄漏、正常连接不再 503）；
- 不要用 sleep 猜测，统一 waitFor。
