2. V1.3 相比 V1.2 改了四处：三处实现方式，一处数值边界；另补齐了首版漏写的可执行条款。
（1）金额内核：bigint 整数分 -> number 整数分（受 Number.isSafeInteger 约束），乘除只在 money.ts 内部用 BigInt 算一次再落回 number。
     理由：初始 100 金币、最多 10 人，金额离 2^53 差着几个数量级；全链路 bigint 会让每个 UI/JSON/测试断言都多一层转换，收益为零。
     保留的：金额仍以十进制字符串过协议与存档（未来真要换 bigint 不必改协议）。
     真问题不是精度上限，而是源码里的 float：0.1+0.2 会把利息算错，所以「整数分」这条必须留。
（2）存档：SQLite 事务 -> 单文件 JSON 快照作提交点 + 事件审计日志（原子重命名 + fsync）。
     理由：需要一个「提交点」而不是需要一个数据库。单文件重命名本身原子，事件日志只做审计，备份就变成复制一个文件。
     保留的：RoomStore 接口不变，先给内存实现和文件实现两种；将来要换 SQLite 只换实现，不动引擎和协议。
（3）阶段粒度：14 个子阶段 -> 10 个单元（合并 2A+2B、3B+3C、3D+4、5+6）。大单元允许拆成「04A/04B」这样的小任务，编号不变。
     理由：2A/2B 改的是同一批房间与会话文件，3B/3C 改的是同一套操作面板，分开交接只会让两次 AI 会话互相踩文件。

（4）金额容量边界：随内核一起下调。MAX_MONEY_CENTS 由 V1.2 的 10^30-1 分改为 10^12 分（100 亿金币），协议金额由 30 位改为最多 13 位。
     这是规则数值变更，不是实现细节，按规则变更处理：写进决策表、改对应测试、在单元 00 报告里点名。
     另外去重表不再设“最近 N 条”窗口，改为整局累积（见第五节），因为截断窗口会让旧命令重新可执行。

3. 四处保留的“贵”条款，不砍
- 身份与重连前移（原 2B）：晚做等于把前面所有页面重写。
- 命令去重与分命令版本校验：这是账务系统唯一能防“重发两次就扣两次钱”的机制。
- 去重整局累积而不是滑动窗口：10 人局每轮约 30 条命令，60 轮约 2000 条，含载荷摘要与结果约 0.5 MB，存得起。
- 「代码验证通过，真人验收待完成」这个中间状态：防止用 10 个自动化页面冒充 10 个真人。

4. 本文件的效力边界
本文是开发计划。不表示游戏已实现、测试通过或公网可用。文中命令是未来工程应提供的入口。
源码未定义之处，本版采用「修订版默认规则」（第三节），标注来源，不冒充原代码行为或用户逐条指定。

一、项目边界与联机形态
============================================================

1. 当前代码的本质
不是走地图买地产的大富翁，而是 2～10 人回合制金融生存游戏：每人初始 100 金币，最后一名未破产者获胜，全员破产则无人获胜。
每轮依次结算利息、银行到期、玩家行动、共同赌博，每三轮纳税。玩家可向银行或其他玩家借款、还款、催债。
信用、债务、放贷、危险自救和破产构成主要策略。
开局每人 100 金币、信用 GOOD、无贷款无债务。
第一阶段不新增地图、地产、道具、排行榜、账号体系。
首版必须交付：规则正确、电脑/手机联机、财务与债务查询、配乐、可跳过的新手教程、逐单元交接文件。

2. 沿用坦克大战的“自建服务器”，但权威必须上移
- 开服电脑运行 Node，同一进程提供静态网页、/health、/ws 和房间管理。默认端口 8000，可用 PORT 修改。
- 局域网访问 http://内网IP:8000/，4～8 位数字房间码开房或加入。
- 公网用 cloudflared 临时隧道，访问 https://xxx.trycloudflare.com；HTTPS 页面自动用 WSS，地址每次启动可能变化。
- 页面由自建服务器提供时，客户端从 location.origin 推导 ws/wss，不需要另填地址。
- 服务器监听 0.0.0.0；启动后打印实际 PORT、本机地址与 LAN 地址，并打印适用网络的二维码（公网二维码只含公开邀请地址）。绑定 127.0.0.1 会让手机永远连不上。
- 房间码按字符串保存并允许前导零；比较、展示、日志都保留补零形式，避免 "0042" 与 "42" 归一后撞码。
- 玩家只需要浏览器，不必安装 Node.js 或 cloudflared；只有开服电脑需要。
- 参考 tank-battle-git 的 server/relay.js、server/start-lan.bat、server/start-tunnel.bat、net.js、README.md。

关键差异：坦克大战的 Node 只做消息中继，房主浏览器算规则；Richman 涉及账务，规则判定必须在 Node 服务端执行，否则开房者可以改金币、改债务、改赌博结果。
只复用连接方式、房间骨架和启动体验，不复制浏览器权威，也不复用手写 WebSocket 帧解析。

3. 服务器权威的能力边界
静态目录只挂 apps/web/dist 这类专用构建目录；不得把仓库、数据库、配置或交接文档挂到公网。
服务器权威能约束普通客户端，不能防服务电脑的操作者改程序。本版按“朋友间可信开服”设计，不承诺反作弊运营。

4. 最终使用方式
你的电脑开服，本机 http://localhost:8000 进入，其他设备用局域网或隧道地址加入。
服务停机期间不能游玩，存档只用于下次恢复。不做主机迁移。

二、技术选择、目录与关键接口
============================================================

1. 技术选择
- 前后端 TypeScript；Node 用实施时仍受支持的 LTS，在单元 00 固定并记录实际版本。
- WebSocket 用浏览器原生 API + 服务端 ws；心跳、重连、身份恢复按第四节实现。
- Zod 校验协议；共享类型只描述契约，服务器秘密不进入客户端构建产物。
- 存档：单文件 JSON 快照 + 事件日志（第五节）。首版单进程、每房间串行执行，不做多副本分布式。
- Howler.js 播放随包音频；Vitest 验证规则与服务，Playwright 验证多页面。
- pnpm workspaces 管依赖，提交锁文件，记录 Node/pnpm 版本，复现用 pnpm install --frozen-lockfile。

2. 目录与职责
apps/web/src/pages/：大厅、游戏、结算。
apps/web/src/components/：我的财务、玩家列表、债务查询、当前操作与通知。
apps/web/src/net/：连接、认证、重试、恢复码入口、快照版本管理。
apps/web/src/audio/、tutorial/：音频生命周期、教程。
apps/web/public/audio/：随客户端发布的授权音频。
apps/server/src/http.ts：静态目录、/health、WebSocket 升级入口。
apps/server/src/rooms/：房间、身份、会话、每房间队列、命令调度、计时调度。
apps/server/src/storage/：RoomStore 接口、内存实现、文件快照实现、备份与恢复。
packages/game-core/src/：money.ts、bank.ts、private-loans.ts、gamble.ts、tax.ts、engine.ts、views.ts。
packages/shared/src/：数据类型、协议 schema、错误码、规则配置、金额序列化。
tests/core/、tests/server/、tests/e2e/：规则、服务集成、浏览器端到端。
scripts/：安装检查、启动、停止、验证、备份。
handoff/：规则决策表、项目当前状态、各单元四类交接 TXT。
artifacts/test-logs/：真实命令输出与测试证据；assets/audio/许可证清单.txt：素材来源与许可。
data/：本地存档与备份，加入 Git 忽略，绝不作为静态资源公开。

职责边界：game-core 不访问 socket、文件系统、系统时钟或浏览器；网络层不复制规则计算；UI 不维护第二套账本。
文件职责在单元 00 细化；之后改名或移动必须同步入口说明与测试，不允许交接文档指向失效路径。

3. 关键接口（单元 00 固定）
- createInitialState(config: RoomConfig, players: PlayerSeed[]): GameState
- applyCommand(state: GameState, command: GameCommand, context: CommandContext): TransitionResult
- getPlayerView(state: GameState, viewerId: PlayerId): PlayerView
- encodeSnapshot(state: GameState): StoredSnapshot；decodeSnapshot(s: StoredSnapshot): GameState
- RoomStore.commit(transition: PersistedTransition): Promise<void>，提供内存与文件快照两种实现
- mulDivFloor(a: Cents, b: number, c: number): Cents；mulDivRound(a, b, c)：金额乘除的唯一入口

CommandContext 注入服务器时间；开奖结果由服务端生成后作为内部命令字段输入，测试注入固定值。
TransitionResult 返回下一状态、事件、操作结果、下一计时目标或明确错误；引擎不得直接产生网络/文件副作用，不得原地修改已发布状态。
引擎只判规则是否合法；服务端另负责认证、命令去重、排队、持久化、按人发视图。

4. 统一脚本（单元 00 建立）
pnpm dev：本地开发；文档说明开发访问方式，不把前端开发端口当正式联机入口。
pnpm build：构建全部包与静态客户端。
pnpm start：运行构建后的同源 HTTP+/ws 服务，默认 PORT=8000。
pnpm typecheck：全工程类型检查。
pnpm test:core / test:server / test:e2e / test：规则、服务、端到端、全部已建立的自动化测试，均非 watch 模式。
尚未建到的测试命令必须报告“尚未实现”，不能用空测试或 echo 成功伪装覆盖。

1. 私人负债是否影响普通银行贷款资格（本版默认：不影响）。
2. 失信欠款停止计息、还清后信用仍不恢复（本版默认：接受）。
3. 破产后的私人债务记为坏账 BAD_DEBT（本版默认：接受）。

这些默认值在后续单元的责任归属：借款撞截止 -> 02/03/07；同时下注与应答丢失 -> 04/06/07；崩溃与重复计时 -> 06/09；换域名与旧连接 -> 04/09；大额复利/失信/破产债权 -> 01/02/03。

R01 身份、轮次与金额
- 人数 2～10，初始 100 金币、初始信用 GOOD、无贷款无债务；1 金币=100 分。round 指完整一轮。seatId 由服务器分配且整局固定；昵称不作身份主键。
- 金额内核：Cents = number，必须 Number.isSafeInteger；上限 MAX_MONEY_CENTS = 10^12 分（100 亿金币）。该值是异常防护边界，不是余额截断规则。
- 单笔金额、余额绝对值、玩家债务合计、应收合计都在 [-MAX_MONEY_CENTS, MAX_MONEY_CENTS] 内校验；汇总越界按不变量失败进 ERROR_PAUSED，不截断、不归零。
- 乘除只经 mulDivFloor/mulDivRound：内部用 BigInt 计算后转回 number，再校验安全范围；禁止在其他文件里直接写 * 0.1 这类浮点运算。
- 协议与存档用规范十进制字符串：零为 "0"，无前导零、无正号，只有允许负余额的字段可带负号，禁止 "-0"；最多 13 位数字，且数值不超过 10^12 分。
- 利率用整数基点 0～10000，10%=1000。非负余额本轮利息 = mulDivRound(余额分, 基点, 10000)，即四舍五入到分。
- 每笔贷款复利计入剩余本息，记录 lastInterestRound。N 轮生效的贷款最早 N+1 轮计息，单笔同轮只计一次。
- 金额输入最多两位小数；借/还/催至少 0.01 金币，下注允许 0；拒绝负额、指数格式、NaN、Infinity、精度超出的输入。
- 余额只有税收自救期间可为负；杠杆亏损在同一结算内转透支贷款。
- 客户端超额/格式非法：拒该命令，不暂停全房。合法命令可预见地越界：拒绝且不部分执行。内部自动计息无法完成或账务不变量失败：保留最后一致状态，房间置 ERROR_PAUSED 并说明原因。
- 不许越界后归零、截断、丢借条或凭空补钱。显示格式化也不先转浮点。

R02 一轮流程与允许操作
1）INTEREST：为 ACTIVE 贷款自动计息。
2）BANK_DUE：处理本轮到期银行贷款，按座位、到期轮、loanId 的稳定次序，一次只呈现一笔待决定贷款。
3）财务快照更新：自动展示，不设逐个“已看完”点击。
4）ACTION：存活玩家按座位各执行一次主要行动。
5）BETTING：所有存活玩家同时私下锁注，全部完成或超时后统一开奖。
6）TAX：仅第 3、6、9……轮，按座位逐人扣税并处理该人危险状态。
7）轮末结算：本轮应处理的税全部处理完，再检查存活人数，进入下一轮或 GAME_OVER。
- 查看本人信息、允许查看的债务和规则随时可用，不占行动；破产者保留身份只读查看，不得经济操作。
- ACTION 允许：银行借款、发起私人借款、还一笔债、催收一笔债、结束行动。成功的经济操作消耗一次主要行动；通过校验建立私人请求即消耗行动。非法/失败且未产生有效请求的不消耗行动，原倒计时不重置。
- 同意/拒绝私人借款只允许请求指定的出借人，不消耗其自己的主要行动；银行到期选择只允许借款人。
- BETTING 只接受下注；禁止借款、同意借款、还款、催债。系统计息、税收只在指定阶段执行。
- DANGER 只允许当前危险玩家紧急借款、催债、放弃，以及被请求出借人的同意/拒绝。
- PAUSED/ERROR_PAUSED/GAME_OVER 禁止经济命令；暂停恢复走单独控制命令，游戏结束只允许查看和返回大厅。

R03 银行借款、到期与多笔贷款
- 普通贷款要求信用良好、金币>0、无未结清银行贷款；上限 = 当前金币分除以 2 向下取整。
- 默认私人负债不影响普通银行贷款资格；作为开局前房间配置记录，整局不变，教程如实说明。
- 普通与赌博透支贷款均每轮 10%；N 轮生效，N+1 开始计息，N+3 轮计息后到期（第 1 轮借 50，第 2/3/4 轮债务 55/60.50/66.55，第 4 轮计息后到期处理）。
- 到期可选全额偿还或拒绝；拒绝、超时、余额不足均使该笔失信，不自动扣部分余额。余额不足直接进失信并显示原因，不额外等待无效选择。
- 主动还款：在自己的主要行动中，对一笔 ACTIVE/DEFAULTED 银行贷款部分或全部偿还，金额不超过金币与剩余债务。
- 赌博透支贷款可与其他银行贷款并存；每笔分别保存生效轮、到期轮、剩余本息、状态。
- 一笔失信只把该笔设为 DEFAULTED；其他未到期贷款继续原计息与到期，不提前到期、不失效、不清零。
- “在贷”状态由未结清贷款汇总得出，不用可能失真的布尔值代替借条列表。

R04 信用与失信欠款
- 信用 GOOD/DEFAULTED；本局一旦失信，之后还清仍保持 DEFAULTED，不能再新增普通银行贷款、不能使用赌博杠杆。
- DEFAULTED 贷款停止计息，仍允许存活借款人在自己行动中偿还。
- 银行贷款剩余还至 0 设 REPAID；该笔曾失信的，历史违约记录与玩家本局 DEFAULTED 信用仍保留。
- defaultedBankDebtCents = 所有 DEFAULTED 银行贷款“当前剩余未偿金额”之和，必须随还款递减。
- 失信时原始欠款、原因、轮次保留在不可被还款覆盖的历史事件中，历史金额不再叠加进总负债。
- 例：失信时欠 100，后还 40，公开显示“失信，欠银行 60”；历史仍显示曾失信 100。全部还清显示“失信，银行失信欠款已结清”。
- 其他仍正常计息的银行贷款单独显示，不与公开的失信欠款混淆。

R05 私人借款请求与生效时点
- 请求含 requestId、借款人、出借人、本金、每轮利率、创建轮/阶段、截止时间、状态。
- 双方必须是本局存活玩家，不能向自己借，利率 0～100%，本金>0。
- 普通行动中合法发起即用掉本次行动；该行动保留为“等待出借人答复”，不能立即跳到下一人或赌博。
- 请求截止 = min(发起时刻+请求时限, 当前行动截止)。标准请求时限 45 秒，快速 20 秒（见 R10）；本次行动只剩 5 秒时请求就只有 5 秒，不追加完整时限。
- 同意、拒绝、取消、超时后该普通行动结束；拒绝/取消不退还行动。最多一个待处理请求。
- 出借人必须明确同意；同意时重新校验身份、双方存活、请求仍 PENDING、阶段匹配、未到截止、出借人可用余额足够。
- 校验通过后在同一原子转移中扣出借人、加借款人、建借条、标记 ACCEPTED；任何失败都不能只改一方资金。
- 已过格式校验的同意若因余额等业务条件失败，请求设 FAILED 并结束行动；身份错误/伪造操作只拒消息，不改真实请求。
- 借条在同意成功时生效，issuedRound 取批准所在轮。拒绝、超时、取消、失败不产生借条或转账。
- 行动或危险结束必须消灭对应待办；重复同意返回原结果，迟到同意不得转钱。跨到下一轮或赌博阶段的请求一律无效。
- 请求界面展示借款人信用、银行失信当前欠款、私人债务总额与冻结部分、金额、利率、双方历史借贷、截止时间。出借人的同意/拒绝不消耗其下一次行动。

R06 私人计息、还款与催债
- ACTIVE 私人贷款按约定利率对剩余本息逐轮复利；下一轮才第一次计息。
- “满一轮可催” = currentRound >= issuedRound+1；源码只打印提示却继续催收的行为必须修复。
- 主动还款：借款人在自己行动中，对一笔 ACTIVE 私人贷款支付正金额，不超过金币与剩余本息。
- 催债：出借人在自己行动或本人危险自救中，对一笔可催收 ACTIVE 贷款指定正金额，上限 = min(剩余本息, max(0, 借款人当前金币))。
- 余额不足则拒绝该数额并返回合法上限，不强行让对方负金币，不默默改金额。
- 部分收回 20 时，只对双方金币与该债务增减 20，不能按原总债务扣账。
- 全额结清设 REPAID、剩余为 0，历史本金与事件保留。每个还款动作只针对一笔贷款。

R07 赌博与锁定
- 所有存活玩家同时提交 betCents、guess(0/1)、leverage(1/2)，金额范围 0～提交时金币。
- 一次提交即锁定，不能修改；每轮每人只能锁一次；提交 0 合法。
- GOOD 可用两倍杠杆，DEFAULTED 只能一倍；猜对净增 bet×leverage，猜错净减同额；提交时不预扣本金。
- 全部锁定前对其他玩家隐藏金额、猜测、杠杆；只显示谁已提交与人数。本人重连可看自己的锁定内容。
- 所有人提交后立即结算，不等满倒计时；超时未提交按 0 注、猜 0、杠杆 1 补齐。
- 全体使用同一个服务器等概率 0/1 结果；玩家不能指定，仅测试可注入固定结果。
- 从进入 BETTING 到开奖提交完成，禁止其他经济操作，保证锁定时的余额不被借款、还款、催债改变。
- 杠杆结算致金币<0时，在同一结算中创建缺口金额的赌博透支贷款并把金币归 0；该贷款不受普通贷款 50% 上限限制。
- 未开杠杆出现此类透支视为不变量失败，不能用贷款掩盖错误。
- 开奖、全体金币变化、透支借条、结果事件、阶段推进作为一个一致变更保存后才公布。

R08 税收、危险自救与胜负
- 每三轮每人缴 20 金币，按座位依次处理，保留源码顺序，不改成同时扣税。
- 本轮 TAX 开始时确定应处理座位列表，每人只扣一次；当前玩家危险处理完成后才轮到下一名。
- 扣税后金币>=0 通过；<0 进入 DANGER，自救总窗口按房间配置，标准 60 秒、快速 45 秒。
- 危险玩家可催收符合条件债权、向存活玩家申请紧急借款、放弃；不能向银行借款。自救不受普通行动额度限制。
- 自救期间可多次尝试，最多一个待处理请求；有请求在等答复时只能等、取消该请求或放弃。
- 紧急借款截止 = min(发起时刻+请求时限, 自救截止)。被拒/失败/取消后剩余时间内可再试；同人发起请求间隔至少 2 秒，不重置自救总时间。
- 批准金额只填平部分缺口则继续自救；任何操作后金币>=0 立即完成自救并关闭待办；放弃或超时仍<0 则破产。
- 串行收税意味着后座位玩家可能先借钱救人、随后自己还要纳税，出借确认界面必须提醒其本轮是否尚未纳税。
- 即使中途只剩一人，也先完成本轮全部应收税处理再判胜负，因此仍可能全员破产。

R09 破产后的债务与债权（修订版设计默认）
- 破产不恢复、不换人接管；取消未决请求，不接受新经济命令，不为相关合同计息。
- 欠银行：未结清银行贷款全部转 DEFAULTED，保留当前欠款并公开；已破产者不再允许还款。
- 欠其他玩家：私人合同设 BAD_DEBT，保留剩余金额与历史；出借人可收回应收剔除，坏账单列，不再计息/催收/还款。
- 其他存活玩家欠破产者的：合同设 FROZEN，冻结剩余，停止计息/催收/还款；借款人界面显示“债权人已破产，合同冻结”，不伪装成已偿还。本局不重新激活。
- 冻结合同的借款人后来也破产，转 BAD_DEBT 并保留原冻结事件。
- 私人合同状态 ACTIVE/REPAID/BAD_DEBT/FROZEN；银行 ACTIVE/REPAID/DEFAULTED。BAD_DEBT 与 FROZEN 绝不能误标为 REPAID。
- 总负债 = 本人所有非 REPAID 合同剩余之和，各状态分项展示；冻结/坏账为保留记录，不算当前可操作债务。
- 可收回应收 = 本人作为出借人的 ACTIVE 私人合同剩余之和；冻结应收与坏账损失单列，不计入应收，不计入金币。
- 例：A 借 B 50 后 A 破产，B 仍保留冻结负债 50，本局不能还给 A；B 后来破产则变坏账记录，不出现凭空转账。

R10 倒计时与节奏
- 标准：行动 60 秒；私人请求最多 45 秒且受当前行动/自救剩余约束；每笔银行到期 45 秒；赌博提交 45 秒；危险自救共 60 秒。
- 快速：行动 30、请求 20、到期 20、下注 30、自救 45。开局前可选预设，整局参数固定，默认标准。
- 默认超时动作：普通行动自动结束并取消待办、推进下一座位/下注；私人请求按拒绝；银行到期按拒绝还款；赌博未提交补 0 注；危险仍为负按放弃并破产。全部由服务器执行，不等客户端确认。
- 所有有效操作完成立即推进，不为用完倒计时而等；查询不重置计时，刷新/重连不重新计时。
- 时间以服务器 deadlineAt 为准，客户端只显示估算倒计时；now>=deadlineAt 即截止，先处理到期系统动作，迟到命令不能抢过超时。
- 单元 05/08 记录真人操作耗时与实际等待。10 人标准模式仅行动就可能用 10 分钟；先记录再调整下一局默认值，不在进行中的局里改。

============================================================
四、身份、协议、并发与隐私
============================================================

1. 身份与房间生命周期（单元 04 实现）
- roomId/gameId 用不复用的内部唯一 ID；公开数字房间码只用于找房间，不能作身份或去重唯一范围。
- playerId 稳定，seatId 服务端分配；socket 只是可替换的连接。客户端自称的 playerId、seat、role、from、cap 不构成授权。
- 创建/加入成功时服务端发随机 sessionToken 与独立 recoveryCode，各至少 128 位安全随机熵；服务端只存摘要与身份映射；原始秘密不进快照、日志、URL、二维码、Git。
- sessionToken 在当前 origin 本地保存，用于同源刷新/重连；recoveryCode 只私密展示给本人，可复制，验证后可在另一地址/设备换新 token 并恢复原 playerId。
- “个人恢复码”与“房间码”在界面明确区分。只知道房间码、昵称或 seatId 不能接管座位。
- 恢复成功发最新本人视图，保留金币、合同、已耗行动、原倒计时、已锁定下注；不重新加入成新玩家，不重做旧交易。
- 同一玩家只允许一个有效连接；新连接恢复成功后替换旧连接并绑定递增 connectionEpoch；旧连接命令拒绝，旧 close 回调不能把新连接标离线。
- 被替换的旧页面停止自动重连并提示“已在另一页面恢复”；普通网络重连用指数退避加抖动，避免两标签页互抢。
- 换域名用 recoveryCode 恢复时签发新 token 并作废旧 token；同源自动重连不每次轮换 token，以免响应丢失造成恢复死锁。
- 恢复码遗失且所有会话失效时，首版不允许凭昵称重置或强接管；仍有有效会话时可生成新恢复码并立即作废旧码。该限制写在保存提示里。
- 大厅允许加入/离开，开始时冻结参与身份与座位；进行中只允许原身份恢复，不允许新玩家顶替离线/破产玩家。
- 房间管理者只能准备/开始/继续等控制，不能改账。管理者离线超过 30 秒，服务器可把管理权转给在线存活玩家中座位最小者；大厅按在线已加入玩家选。这不是迁移服务器主机。
- 游戏结束后可只读查看原局；“再来一局”创建新 gameId，不复用旧去重范围，不把旧局恢复码用于新局。
- 单元 04 的身份与去重可暂存内存，界面明确提示“服务重启暂不保留”；单元 06 必须连同身份摘要一起持久化。

2. 命令与消息
- 客户端业务命令含：protocolVersion、gameId、commandId、type、payload，以及所需的 expectedGameVersion/roundId/phaseInstanceId/requestId。
- actorId 由已认证连接注入；相同 commandId 只能重发相同规范化载荷，不允许改金额沿用原 ID。
- 服务端消息：加入/恢复结果、本人快照、阶段变化、操作结果、私人待办、公共事件、错误、离线/重连、游戏结束。
- gameVersion 表示游戏/财务状态版本；在线人数、心跳、连接变化单独通知，不增加 gameVersion。
- 每次已提交的状态转移令 gameVersion 加 1；只读查询、重复命令、不改状态的纯业务拒绝不加；使请求终结、行动或阶段推进的业务失败属完整转移，必须加版本；自动动作同理。
- 快照含 gameId、gameVersion、schemaVersion、serverNow、deadlineAt 与本人权限视图；客户端同一 gameId 只采用不低于已展示版本的状态，旧应答不能覆盖新快照。
- /health 返回 ok、服务标识、程序版本、在线连接数、房间数；不返回昵称、成员、合同、token、恢复码。
- 错误码至少区分：UNAUTHORIZED、REPLACED、NOT_YOUR_TURN、INVALID_AMOUNT、INSUFFICIENT_FUNDS、VERSION_CONFLICT、REQUEST_EXPIRED、ALREADY_LOCKED、ROOM_PAUSED、GAME_OVER、COMMAND_ID_REUSED、STORAGE_FAILURE。
- 操作结果要有中文原因和可执行下一步；UI 可显示等待，但不能在成功确认前自行扣款。

3. 排队、去重与版本
所有改变同一房间状态的玩家命令、计时到期、内部结算进入同一个串行队列；不要用“Node 单线程”代替异步排队约束。
次序：（1）认证与大小/频率校验，把连接映射到真实玩家；（2）按 (gameId,playerId,commandId) 查去重结果，核对类型与规范化载荷摘要；（3）已有相同命令返回原结果，同 ID 不同载荷拒绝，重复命令即使阶段已变也不重新执行；（4）新命令先处理当前已到期的系统动作，再校验阶段、权限、金额与规则；（5）构造下一状态，按第五节保存，然后应答与推送。
分命令校验：
- 行动中的借款/还款/催债/结束行动：严格校验 expectedGameVersion；冲突返回最新本人快照，玩家重新确认后用新 commandId；不得自动按新余额重放旧经济意图。
- 下注：按 gameId+roundId+phaseInstanceId+playerId 校验阶段、是否已锁定、当前余额，不因别人刚下注导致的全局版本变化拒绝正常提交。
- 私人请求同意/拒绝：按 requestId、所属阶段、截止、指定出借人、当前余额校验，不因无关版本变化失败。
- 银行到期选择：按 loanId、当前到期处理实例、借款人、截止校验，并重查余额。
- 系统动作：用服务器生成的唯一 ID，客户端不能发系统命令。示例 gameId/phaseInstanceId/timeout、gameId/loanId/interest/round、gameId/tax/round/playerId。
- 语义重复但换了 commandId（如重复下注）：不得覆盖第一次内容，返回 ALREADY_LOCKED 等明确结果。
- 网络断开时保存未确认命令 ID；恢复后只允许原 ID 原载荷查询/重发。连接恢复不代表该命令必成或必败。
- 单元 04 以内存去重；单元 06 起已认证合法业务命令的终局结果随本局归档；非法 JSON、认证失败、限流不写入业务账本。

4. 权限视图
- 服务端为每名玩家单独生成 PlayerView；不能发全量私密状态让前端隐藏。
- 公开：昵称、座位、存活/危险/离线、信用、当前失信银行欠款、轮次/阶段、允许公开的提交状态与结算结果。
- 自己：全部金币、债务、债权、私密待办、本人锁定赌注、财务事件。
- 私人合同双方：该合同的本金、利率、剩余本息、状态、轮次、交易历史。
- 未参与合同者：首版只能查公共信用与失信银行欠款，不提供第三方私人合同明细。向某人申请借款时，额外给该出借人 R05 规定的风险摘要，不含借款人与他人的逐笔私密合同。
- 若以后要全员查看彼此所有借贷，属明确规则变更，须同步服务端过滤、教程与测试，不能只改 UI。
- 锁定前的保密覆盖快照、事件查询、操作应答、错误详情、重连补发；日志也不得输出全量命令载荷。
- 恢复码/token 永不进普通 PlayerView，只通过专用私密认证响应返回本人。

============================================================
五、持久化：单文件提交点（单元 06 实现）
============================================================

1. 为什么不用数据库
需要的不是数据库，而是一个“原子提交点 + 重启可恢复”。Node 的 fs.rename 在 Windows 上走 MoveFileEx(MOVEFILE_REPLACE_EXISTING)，同卷重命名可视为原子；把整局状态写进一个快照文件再重命名，就得到一个提交点。
代价是整局状态全量写盘（10 人局状态是几十 KB 量级），频率是“每次状态转移一次”。这在朋友局规模下完全够用，且省掉驱动安装与 WAL 语义两类风险。schema 变更仍需要一次性迁移函数（放 migrations/），只是没有数据库迁移那套东西。
换 SQLite 的路径保留：RoomStore 接口不变，只换实现。

2. 目录与文件
data/rooms/<gameId>/snapshot.json：唯一提交点，含 schemaVersion、rulesVersion、protocolVersion、gameId、gameVersion、eventSeq、lastUpdatedAt、房间配置、完整 GameState 编码、身份摘要映射、未决请求、已锁定下注、整局累积的 commandId 去重表、serverNow。
去重表每项为 commandId -> { type, payloadHash, result }。payloadHash 是规范化载荷的摘要，重启后仍能执行“同 ID 不同载荷拒绝”；result 是终局结果，重发直接返回，不重新执行。不设“最近 N 条”窗口：截断会让旧命令重新可执行。
data/rooms/<gameId>/events.ndjson：只做审计，一行一个事件，带 seq；snapshot.eventSeq 之后的行一律不采信（崩溃残留）。
data/rooms/<gameId>/lock：进程独占标记，防止两个进程同时开同一局。

3. 提交流程（房间串行队列内）
（1）在旧状态副本上生成下一状态、事件、操作结果，检查账务不变量。
（2）追加事件到 events.ndjson 并 fsync（只写审计，不影响正确性）。
（3）写 snapshot.tmp，fsync 文件。
（4）rename(snapshot.tmp -> snapshot.json) ——这一步是提交点。
（5）重新打开 snapshot.json 校验可解析、长度非零。rename 抛错时不能直接判定失败：先重读 snapshot.json，按文件里的 gameVersion/commandId 事实裁决；确认已提交就按原结果应答，确认未提交才置 ERROR_PAUSED，不广播成功。
（6）提交成功后替换房间对外可见内存状态，应答玩家并广播过滤后的视图。
- 崩溃语义：在（4）前崩溃，该命令未提交，客户端未收到成功，重发会执行一次（正确，因为之前没生效）；在（4）后、（6）前崩溃，重发同 commandId 命中快照里的去重结果，返回原结果，不重复转账。
- 不改变游戏状态的纯业务拒绝：只追加一条拒绝结果到审计与去重表，不推进 gameVersion。请求设 FAILED、行动结束、阶段推进这类有状态变化的业务失败，必须按完整转移保存后再广播，不能当纯拒绝。
- 存档不可写：暂停该房间经济推进并提示，不悄悄降级成内存模式。
- 禁止先改共享余额/广播再异步补存档；禁止把去重表只放内存。
- Windows 上不能对目录 fsync；不要写“目录已刷盘”这种 Linux 才成立的断言。以重新打开校验为准。

4. 系统命令与随机结果
- 计息、到期默认拒绝、请求过期、默认下注、开奖、扣税、破产、阶段推进，都按确定 ID 进同一提交路径。
- 计时器只是唤醒信号，存档里的 deadlineAt 才是依据；重复唤醒、旧阶段计时器、重连补发都不能重复扣款。
- 用 phaseInstanceId 区分同名阶段的不同实例；阶段变更后清旧计时器，未清的回调到达也必须因过期实例被拒。
- 开奖用服务器安全随机源生成 0/1，与全体结算同一次提交保存后公布；已提交的开奖重试或恢复绝不重抽。
- 进程在开奖提交前崩溃且结果从未公布时，恢复后可重新生成未提交结果；不得提前把未提交结果放进客户端、公共日志或动画。
- 人机测试注入时间与随机；生产客户端无权启用固定随机数。

5. 重启恢复
- 短断网/刷新：服务器未停机，原 deadlineAt 继续有效，不暂停不延长。
- 进程重启：进行中的房间载入为 PAUSED_RECOVERY，只允许恢复身份与查看；不补算停机期间回合，不因旧绝对截止时间立即让全员拒付或破产。
- 管理者恢复身份后点“继续游戏”；管理者缺席时按第四节管理权转交规则，由已恢复的存活玩家继续。
- 继续后：当前未完成的行动/到期选择/下注阶段/危险状态获得该阶段配置的完整时限；未决私人请求重新获得 min(请求时限, 所属窗口时限)。不声称保留断电那一刻的精确剩余秒数。
- 继续动作与新 deadline 先保存再开始计时；已提交下注仍锁定，已转的钱不重转，已完成的计息/税收不重做，未决请求仍须真实双方批准。
- 恢复码摘要、token 摘要、玩家映射、稳定座位、管理者、已接受命令结果、未决请求、已锁定赌注都随档恢复。
- 载入前先校验 schemaVersion/rulesVersion/protocolVersion：不兼容就拒绝载入并提示需要迁移，禁止“新建空局覆盖唯一存档”；迁移前先备份并校验备份可读。
- 恢复时交叉校验事件日志：events.ndjson 至少覆盖到 snapshot.eventSeq 且 seq 连续；行数不足、断号、文件缺失都告警并保留快照，不静默重建日志。
- ERROR_PAUSED 用于不变量/容量故障，不能靠普通“继续游戏”绕过；修复并验证后才回最后一致状态。
- 全员离线但服务器仍在运行时，继续按正常超时规则；这与进程重启暂停是两种明确行为，界面与说明须告知。

6. 备份
- 一致性备份：房间写入暂停后复制 snapshot.json（它自洽），需要审计再一并复制 events.ndjson。
- 升级/schema 变更前备份；恢复不得自动覆盖唯一现存档，先保留原档并校验备份可读。
- 存档损坏、schema 不支持、磁盘满、无写权限必须明确报错，保留诊断与恢复说明。
- 备份含身份摘要，只存本机非公开目录；日志不记录原始秘密。

六、界面、教程、音频与公网
============================================================

1. 自己的信息
- 桌面固定“我的财务”面板；手机底部导航“我的、玩家、债务、记录”，关键金币与当前操作始终易找。
- 展示金币、总负债、可收回应收、信用、存活/危险、冻结合同、坏账分项。
- 银行普通贷款、赌博透支贷款、失信欠款分开显示；逐笔列本金、剩余本息、利率、生效轮、到期轮、状态。
- 私人债务列对方、剩余本息、利率、生效轮、可否催收/还款、不可操作原因。
- 显示轮次、阶段、是否已行动、剩余时间，以及利息、税收、赌博、转账事件。
- 主面板与债务查询共用同一份服务端视图，不自行二次计息或维护独立总账。

2. 玩家与债务查询中心
- 玩家列表显示昵称、座位、存活、危险、离线、信用、失信当前欠款；信用用图标+文字+颜色共同表达。
- 查询中心随时可开，不消耗行动；支持我借入、我借出、待我确认、已结清、冻结、坏账、公共信用。
- 可按借款人/出借人/状态/轮次筛选，结果不得越过第四节权限。
- 别人向我借钱时用明显通知与待办角标；可直接看风险摘要与双方历史，再同意/拒绝；金额变化或请求失效时及时更新按钮。
- 请求等待、已锁注、存档故障、网络断开、恢复中、连接被替换、暂停待继续都要有清楚状态，不能让玩家误以为操作已成功。
- 不把“连接断开”武断显示成“服务器已关闭”；浏览器未必知道是网络、隧道还是服务器故障。

3. 布局与触控
- 桌面：顶部房间/轮次/音频，中间阶段操作，左侧玩家，右侧财务与事件。
- 手机竖屏：顶部简要状态，中间当前操作，底部四个入口；主要按钮适合触控，不横向溢出。
- 转账、借款批准、锁定下注、放弃自救给清楚确认摘要，不层层重复弹窗。
- 动画不阻塞服务端结算；断线后禁用需要在线确认的操作，重连后按服务器状态重建界面。

4. 新手教程
- 首次进入最多 5 页，约 60 秒读完，每页可跳过，可随时重看。
- 内容：目标与流程；银行到期/失信；私人同意、还款/催债；赌博/杠杆与税收自救；财务/债务入口。
- 说明锁定后不能改注、失信还清不恢复信用、冻结/坏账含义；细节放随时可查的规则页，不塞进教程。
- localStorage 记已读状态，换设备/换地址可能重新显示；教程状态不影响权限与身份恢复。

5. 音频
- 大厅、正常回合、危险、结算配置循环 BGM；借款请求、转账、到期、破产、胜利配短音效。
- 总静音、音乐音量、音效音量分别可调并存本机；首个用户点击后再播放，正确处理自动播放限制。
- BGM 平滑切换，不因每次快照重启；锁屏、切后台、重连、回大厅不叠加播放器。
- 只用自制或有明确兼容授权的素材，记录来源、作者、许可证、署名要求；加载失败不阻塞游玩。

6. 公网与个人恢复码
- Cloudflare Quick Tunnel 用于邀请试玩与测试；无在线时长保证，新隧道换域名。固定域名/命名隧道可后续加，不作首版前置。
- 本地存储按 origin 隔离；从局域网切到公网或换随机域名时，不能假定旧 token 可用。
- 新地址进入“恢复本局身份”，输入公开房间码 + 本人恢复码，服务端验证后恢复原座位；不能只凭昵称认领。
- 旧页面可提示断线与“获取新邀请地址”，不保证自动获知新域名；新链接由开服者重发，恢复码不随公开邀请转发。
- 公网二维码只能含公开邀请地址/房间码，不能含个人恢复秘密；手机用蜂窝网络测试时不能给它局域网二维码。
- /health 只能证明本地服务响应；公网验收必须在实际外网设备打开网页并建立 WSS，不能凭隧道打印了 URL 就写“公网通过”。

实现与复核工具可按实际能力互换，但不得无协调同时改同一批文件。

必测：

- crash_after_rename_before_ack：提交点后应答前中止，恢复后重发返回原成功，无重复转账。

- credentials_restored：恢复码在进程重启后仍能找到原身份；快照含精确大额金额字符串。
- write_failure：磁盘/写入失败不广播成功，不改共享账，故障明确（ERROR_PAUSED）。

- stale_payload：重启后同 commandId 换载荷被拒；同载荷返回原结果（验证快照里的 payloadHash 生效）。

八、执行制度与交接
============================================================

1. 角色与粒度
- DeepSeek Harness 每次只选一个单元，核对输入文件、分配实现与复核、收集真实运行证据、检查交付。
- Trae 负责实现与测试；Qorder 独立检查规则偏差、并发/权限、持久化边界、测试缺口；工具能力不同可交换职责。
- 一个单元仍超出单次上下文，就拆成有名字的小任务并写明做到哪一步；单元只有全部必需项通过才算完成。
- 不让两个 agent 无协调改同一文件。复核发现问题由明确负责人修复并重跑受影响测试。
- 源码是规则来源之一，存在已记录 bug 时以决策表为准；不为“忠实移植”重新引入未经同意转账、失信清债、部分催债扣错账。

2. 固定工作顺序
读本版方案/规则表/当前状态/上一交接 → 检查真实工程 → 列本次范围、文件、验收 → 先写失败测试 → 实现 → 跑测试/构建 → 独立复核 → 修复与必要重测 → 所需真机验收 → 提交实现代码 → 写交接并提交文档。
- 记录实际被验证的实现提交号，禁止用后来改过但未验证的代码冒充同一版本。
- 测试日志放 artifacts/test-logs/，注明命令、时间、环境、退出码、日志路径；不复制 token 等秘密。
- 若测试后仅改交接文本，文档提交另存，不要求文档里写它自己尚未产生的提交号。
- 上游关键规则/协议/数据不一致时先修阻塞项；其他改进列待办，不以修复为名扩写玩法。

3. 固定交付文件名（每单元四类 TXT）
（1）handoff/单元04-成果报告.txt：完成项、未完成项、改动文件、测试命令与真实结果、日志路径、复核结论、已知问题、被验证的实现提交号。
（2）handoff/单元04-运行与验收说明.txt：环境/依赖版本、安装启动测试方式、访问地址、建房步骤、逐步操作与预期结果、真机验证记录与未验证项。
（3）handoff/单元04-下一阶段交接.txt：最新架构与入口、数据流、协议/状态/存档格式变化、迁移回退方法、下一单元入口、禁止破坏的不变量。
（4）handoff/单元04-注意事项.txt：限制、兼容问题、临时实现、风险、待办、绝不能重复的错误；未解决项写影响与验证办法。
编号统一：00、01、02、03、04、05、06、07、08、09（拆分任务用 04A 形式，仍归入同一单元）。
同时更新 handoff/项目当前状态.txt（只留最新有效摘要：方案/规则/协议/schema 四个版本号、已完成单元、当前子任务、可运行状态、提交号、启动命令、验证状态、阻塞、下一入口、应读文件）与 handoff/规则决策表.txt（只在规则真变化时更新，标注来源、影响、测试）。
若本轮未做完，仍写四类 TXT，特别指出中间代码是否可运行、哪些命令尚未验证。

4. 状态定义
- “完成”：本单元必需功能实际运行，相关自动化测试/类型检查/构建通过；该单元要求的真机/真人验收已记录；无未解决阻塞；交接齐全；有可回退提交。
- “代码验证通过，人工验收待完成”：自动化通过但缺真实设备或试玩；列出最少需要的人/设备与具体操作，不虚构记录。
- “部分完成/被阻塞”：写清失败原因、已验证部分、下一步，不把未执行的命令标成通过。
- 纯规则单元（00～03）无需机械要求手机验收；05、08、09 涉及实机/真人时才要求对应证据。
- 上一单元必要前置未通过，不开展依赖它的新功能；可继续本单元修复、文档与未完成验证。
- 一个大单元的所有拆分任务满足条件后才标该单元完成；不能因“文件生成完了”宣布可发布。
