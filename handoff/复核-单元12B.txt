一、结论
需修复。
发布包本身可运行、内容干净（47 文件/105846765B，zip 44976792B，SHA256 EE86127F...D79B82，
真实解压/启动/health/建房/停止通过）；但 scripts/verify-release.mjs 的 12 项检查存在两个
可复现的假 PASS：
  M1 zip_extract 只核对 zip 的顶层目录、VERSION、server.mjs 三项；zip 缺
     app/server/backup-cli.mjs 时 verify 仍 exit 0 / 12 PASS（staging 正常即可）。
  M2 secret_scan 只扫描白名单扩展名且只匹配 JSON 风格键值；在无扩展名的 LICENSE 写入
     sessionToken 并同步 SHA256SUMS 后，verify 仍 exit 0 / secret_scan PASS。
这两个问题会让“发布验收全 PASS”不能证明交付 zip 完整/无明文凭据，必须修。
其余 build-info 校验无单测、gitDirty=true、首次 build 的 node.exe 占用等列为 should-fix/nit，
不单独阻塞；当前真实 release/ 内容本身未被发现 token、data/rooms、日志、源码、node_modules、

二、must-fix 列表

M1 zip_extract 未校验 zip 全量文件，缺必需文件的 zip 仍 PASS
   文件:行号：
   - scripts/verify-release.mjs:228-249（zip_extract 仅检查顶层目录、VERSION、server.mjs hash）
   - scripts/release-lib.mjs:159-161（REQUIRED 只在 staging 校验；没有对解压 zip 调 validateStaging）
   问题：
   `zip_extract` 只从 zip 解出一个 server.mjs 并核其 hash；没有把解压目录与
   SHA256SUMS/REQUIRED 全量对照，也没有检查 app/server/backup-cli.mjs、app/web/*、scripts/* 是否在 zip 里。
   而 server_runtime/backup_cli/packaged_check_only 使用的是 **staging**，不是 zip 解压副本，
   所以 staging 正常 + zip 缺文件时 verify 仍绿。
   复现命令（临时目录，不修改仓库）：
   1. 复制 release/RichMan-v0.9.0-win-x64 到临时目录；
   2. 删除临时副本 app/server/backup-cli.mjs；
   3. Compress-Archive 该副本为临时 zip，写一份只含该 zip hash 的 release/SHA256SUMS.txt；
   4. node scripts/verify-release.mjs --dir <原始 staging> --zip <临时 zip>。
   期望：exit 1，报 zip 缺 app/server/backup-cli.mjs（或 SHA256SUMS 缺项/必需文件缺失）。
   实际：exit 0，12 项全 PASS（staging_structure 47 files、zip_extract PASS、server_runtime PASS）。
   建议改法：
   - Expand-Archive 后对 extractedDir 调 `validateStaging(extractedDir, { version, nodeVersion })`，
     让同一 REQUIRED/FORBIDDEN/SHA256SUMS 规则同时约束 staging 和 zip；
   - 或至少遍历 extractedDir 全部文件，与 staging SHA256SUMS 的路径集合+hash 全量比较，并断言 REQUIRED 存在于 zip；
   - 增加“zip 删除 backup-cli/ index.html/启动脚本”的负向单测，证明 verify 必红。

M2 secret_scan 可漏无扩展名文本/非 JSON 写法的明文 token/recoveryCode
   文件:行号：scripts/verify-release.mjs:182-188（textExtensions 白名单、secretPattern 仅 JSON 键值）。
   问题：
   `textExtensions` 只含 .txt/.md/.json/.js/.mjs/.html/.css/.ps1/.bat/.xml/.svg；
   `LICENSE`、`licenses/ws/LICENSE`、`licenses/react/LICENSE` 等无扩展名文件被跳过。
   secretPattern 只匹配 `{ "sessionToken"/"token"/"recoveryCode": "..." }`，不匹配
   `sessionToken=...`、YAML/plain 文本或其它属性名。实际包中恰好没有密钥，但 gate 本身不完整。
   复现命令（临时副本，不修改仓库）：
   1. 复制 staging；
   2. 向根 `LICENSE` 追加 `{"sessionToken":"ABCDEFGH12345678"}`；
   3. 重新计算该 LICENSE 的 SHA256 并更新副本 SHA256SUMS；
   4. node scripts/verify-release.mjs --dir <副本> --zip <原 zip>。
   期望：exit 1，secret_scan FAIL（发现明文 sessionToken）。
   实际：exit 0，secret_scan PASS（12 项全 PASS）。
   建议改法：
   - secret_scan 至少覆盖所有非二进制/小体积文件，包括无扩展名 LICENSE、licenses/**/LICENSE；
     可按 magic/大小跳过 node.exe/mp3/wav，而不是按扩展名白名单跳过文本；
   - 扩展模式到 `(sessionToken|recoveryCode|token)\s*[:=]\s*["']?[A-Za-z0-9_-]{8,}`，并覆盖 JSON/YAML/plain；
   - 增加 extensionless LICENSE 负向测试；同时把 zip 解压副本也纳入 secret_scan（当前只扫 staging）。
