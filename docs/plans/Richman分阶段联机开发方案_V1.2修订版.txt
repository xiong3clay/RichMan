目标：在现有规则基础上，做成由你的 Windows 电脑开服、电脑和手机通过浏览器共同加入的回合制金融生存游戏。
架构：Node.js 服务端统一执行规则、保存账务和判定胜负；浏览器提交操作意图并展示经过权限过滤的状态。规则引擎独立于网络、数据库和 UI。
技术栈：TypeScript、React、Vite、Node.js LTS、ws、Zod、SQLite、Howler.js、Vitest、Playwright、pnpm workspaces。
执行方式：保留 DeepSeek Harness 调用 Trae 实现、Qorder 独立复核的方式；不要求这些工具安装 Codex 的技能或插件。

本文件是完整替代版，不需要把 V1.1 与本版逐条拼接。方案版本 V1.2 与未来游戏发布版本 V1.0 是两个概念。
本文是开发计划，不表示游戏已经实现、测试通过或公网可用。文中命令是未来工程应提供的入口。
涉及源码未定义之处，本版明确采用“修订版默认规则”；它们是本次设计建议，不冒充原代码行为或用户逐条指定的规则。后续以本版和更新后的规则决策表为准。

============================================================
一、本次修订的重点与项目边界
============================================================

1. 相比 V1.1 的主要变化
- 将稳定玩家身份、刷新恢复、基础心跳和个人恢复码前移到第 2 阶段。
- 明确私人借款请求的有效阶段和截止时间，禁止借款与已锁定赌注争用余额。
- 区分命令去重、经济操作版本检查、多人同时下注的校验方式。
- 第 3A 子阶段即落地可靠存档；快照、事件、版本、去重结果同事务提交，再应答或广播。
- 将超时、自动计息、开奖、纳税也纳入统一的系统命令与保存流程。
- 明确失信当前欠款、历史失信金额、多笔银行贷款、破产债权、金额精度和容量边界。
- 为临时公网域名变化设计个人恢复码，明确临时隧道适用于邀请试玩，不承诺持续在线。
- 将较大的阶段拆成独立验收的子阶段，提前加入真人试玩和等待时长记录。
- 统一交接文件名，区分代码验证通过、真人验收待完成和阶段完成。

2. 玩法与首版范围
这不是走地图、买地产的大富翁，而是 2～10 人的回合制金融生存游戏：
- 每人初始 100 金币，信用良好，最后一名存活者获胜；全员破产则无人获胜。
- 每轮依次处理利息、银行到期、玩家行动、共同赌博，每三轮纳税。
- 核心操作为银行借贷、私人借贷、主动还款、催债、下注和危险自救。
- 所有金额均为游戏币，不接入真实支付、充值、提现。
- 首版不做地图、地产、道具、账号注册、聊天、好友、排位、观战、原生 App、服务器主机迁移或重型 3D 引擎。
- 游戏规则、电脑/手机联机、财务与债务查询、配乐、可跳过的新手教程、交接文件均属于必须交付的范围。

3. 首要复核点及负责子阶段
- 借款确认撞上截止时间或阶段结束：1B、1C、3B。
- 多人同时下注、响应丢失后重发：2B、3A、3C。
- 提交前后崩溃、超时重复触发、重启恢复：3A、5。
- 换域名/换设备后恢复原座位，旧连接继续发命令：2B、6。
- 大额复利、失信还款、破产双方债权债务：1A、1B、1C。

============================================================
二、联机方式与工程结构
============================================================

1. 复用坦克大战的连接体验
- 你的电脑运行 Node.js，同一服务提供静态网页、/health、/ws 和房间管理。
- 本机访问 http://localhost:8000/；局域网设备访问 http://内网IP:8000/。
- 默认端口 8000，可通过 PORT 修改；若与坦克大战冲突，提示修改端口，不自动杀进程。
- 服务器监听 0.0.0.0，启动后打印实际端口、本机/LAN 地址和适用网络的二维码。
- 使用 4～8 位数字房间码与昵称加入，房间码应以字符串保存，允许前导零。
- 公网邀请试玩使用 cloudflared 临时 HTTPS 隧道；客户端以同源 WSS 连接 /ws。
- 普通玩家只需浏览器，不必安装 Node.js 或 cloudflared。
- 页面从 location.origin 推导 ws/wss 地址，首版不需要玩家手填另一套 WebSocket 地址。
- 服务电脑必须开机且运行服务；服务停机期间不能游玩，存档用于下次恢复。

参考坦克大战 server/relay.js、server/start-lan.bat、server/start-tunnel.bat、net.js 和 README.md。
仅复用连接方式、房间概念和启动体验。Richman 的规则权威必须是 Node.js 服务端，不能复制浏览器房主算账的模式，也不复用手写 WebSocket 帧解析。
静态目录只允许 apps/web/dist 等专用构建目录；不得把整个仓库、数据库、配置或交接文档挂到公网。
服务器权威可约束普通客户端，不等于能防止服务器电脑的操作者篡改程序；本版按朋友间可信开服场景设计。

2. 技术选择
- 前后端使用 TypeScript；Node.js 采用实施时仍受支持的 LTS，在第 0 阶段固定并记录实际版本。
- WebSocket 使用浏览器原生 API 和服务端 ws；重连、心跳、身份恢复按本文实现。
- Zod 校验协议；共享类型只描述契约，不把服务器秘密混入客户端构建产物。
- SQLite 保存房间最新快照、事件和命令结果。首版使用单服务进程、每房间串行执行，不设计多副本分布式服务。
- SQLite 具体驱动在第 0 阶段以 Windows 安装成功、事务和备份验证为依据固定，记录版本与安装条件，后续不得随意更换。
- Howler.js 播放本地随包音频；Vitest 验证规则/服务，Playwright 验证多页面交互。
- pnpm workspaces 管理依赖，提交锁文件，记录 Node/pnpm 版本；复现安装使用 pnpm install --frozen-lockfile。

3. 建议目录与职责
apps/web/src/pages/：大厅、游戏、结算页面。
apps/web/src/components/：我的财务、玩家列表、债务查询、当前操作与通知。
apps/web/src/net/：连接、认证、重试、恢复码入口、快照版本管理。
apps/web/src/audio/、tutorial/：音频生命周期、教程。
apps/web/public/audio/：实际随客户端发布的授权音频。
apps/server/src/http.ts：静态目录、/health、WebSocket 升级入口。
apps/server/src/rooms/：房间、身份、会话、每房间队列、命令调度、计时调度。
apps/server/src/storage/：内存实现、SQLite 实现、迁移、备份、恢复。
packages/game-core/src/：money.ts、bank.ts、private-loans.ts、gamble.ts、tax.ts、engine.ts、views.ts。
packages/shared/src/：数据类型、协议 schema、错误码、规则配置、金额序列化。
tests/core/、tests/server/、tests/e2e/：规则测试、服务集成测试、浏览器端到端测试。
scripts/：安装检查、启动、停止、验证、备份脚本。
handoff/：规则决策表、项目当前状态、各子阶段四类交接 TXT。
artifacts/test-logs/：真实命令输出和测试证据；assets/audio/许可证清单.txt：素材来源及许可。
data/：本地数据库及备份，加入 Git 忽略，绝不作为静态资源公开。

职责边界：game-core 不访问 socket、数据库、系统时钟或浏览器；网络层不复制规则计算；UI 不维护另一套独立账本。
文件职责可在第 0 阶段细化，之后改名或移动必须同步入口说明和测试，不允许交接文档指向失效路径。

4. 关键接口与统一命令入口
第 0 阶段固定以下概念及 TypeScript 类型；接口的具体字段在协议文档中完整定义：
- createInitialState(config: RoomConfig, players: PlayerSeed[]): GameState。
- applyCommand(state: GameState, command: GameCommand, context: CommandContext): TransitionResult。
- getPlayerView(state: GameState, viewerId: PlayerId): PlayerView。
- encodeSnapshot(state: GameState): StoredSnapshot；decodeSnapshot(snapshot: StoredSnapshot): GameState。
- RoomStore.commit(transition: PersistedTransition): Promise<void>，提供内存和 SQLite 两种实现。
CommandContext 注入服务器时间；随机开奖结果由服务端生成后作为内部命令字段输入，测试提供固定结果。
TransitionResult 返回下一状态、事件、操作结果、下一计时目标或明确错误；引擎不得直接产生网络/数据库副作用，也不得原地修改已发布状态。
引擎保证规则是否合法；服务端另负责认证、命令去重、排队、持久化及按人发送视图。

============================================================
三、修订版默认规则与明确边界
============================================================

第 0 阶段把本节整理到 handoff/规则决策表.txt，每条列出：规则编号、源码行为、V1.2 默认行为、原因、对应测试。
规则来源分别标注“沿用源码”“修复源码缺陷”“联机必须补充”“修订版设计默认”。存在用户明确的新要求时更新决策表和相关测试；不要把建议伪称用户亲自选定。

R01. 身份、轮次与金额
- 人数 2～10，初始 100 金币；1 金币=100 分。round 指完整一轮，seatId 固定，昵称不作身份主键。
- 金额内核采用 bigint 整数分；JSON、网络和 SQLite 快照使用规范十进制字符串：零为"0"，其余不带前导零、不带正号，只有允许负余额的字段可带负号，禁止"-0"。禁止用 Number/parseFloat 经手完整金额，禁止先转浮点再转 bigint。
- 利率为整数基点，0～10000；10%=1000 基点。非负余额的本轮利息=(余额分×基点+5000)/10000，使用 bigint 整数除法，即四舍五入到分。
- 每笔贷款复利计入剩余本息；记录 lastInterestRound。N 轮生效的贷款最早 N+1 轮计息，单笔同轮只能计一次。
- 金额输入最多两位小数，借款/还款/催债必须至少 0.01 金币，下注允许 0；禁止负额、指数格式、NaN、Infinity 和精度超出的输入。余额只有税收自救期间可以为负，杠杆亏损在同一结算内转透支贷款。
- 规定金额容量 MAX_MONEY_CENTS=10^30-1；单笔、余额绝对值及玩家债务/应收汇总均校验。协议金额字符串最多 30 位数字，余额可额外带负号。该值是异常防护边界，不是余额截断规则。
- 客户端超额或格式非法：拒绝该命令，不暂停全房。合法命令可预见地导致越界：拒绝且不部分执行；内部自动计息等无法完成或账务不变量失败：保留最后一致状态，将该房间置 ERROR_PAUSED，说明原因。
- 不允许越界后归零、截断、丢借条或凭空补钱。SQLite 不用 SUM/CAST REAL 计算金额；显示格式化也不先转 Number。

R02. 一轮流程与允许操作
1）INTEREST：自动为 ACTIVE 贷款计息。
2）BANK_DUE：处理本轮到期银行贷款，按座位、到期轮、loanId 的稳定次序；一次只呈现一笔待决定贷款。
3）财务快照更新：自动展示，不设置逐个点击“已看完”的步骤。
4）ACTION：存活玩家按座位依次执行一次主要行动。
5）BETTING：所有存活玩家同时私下锁定赌注，全部完成或超时后统一开奖。
6）TAX：仅第 3、6、9……轮，按座位逐人扣税和处理该人的危险状态。
7）轮末结算：完成本轮全部应收税玩家的处理后，检查存活人数并进入下一轮或 GAME_OVER。
- 查看自己的信息、允许查看的债务和规则随时可用，不占行动；破产玩家保留本人身份作只读查看，不允许经济操作。
- ACTION 允许当前玩家银行借款、发起私人借款、还一笔债、催收一笔债或结束行动。成功的经济操作消耗一次主要行动；通过校验建立私人请求时即消耗行动。非法/失败且未产生有效请求的命令不消耗行动，原倒计时不重置。
- 同意/拒绝私人借款只允许请求指定的出借人，不消耗其自己的主要行动；银行到期选择只允许借款人。
- BETTING 只接受下注；禁止借款、同意借款、还款和催债。系统计息、税收只能在指定阶段执行。
- DANGER 只允许当前危险玩家紧急借款、催债或放弃，以及被请求出借人的同意/拒绝。
- PAUSED/ERROR_PAUSED/GAME_OVER 禁止经济命令；暂停恢复走单独控制命令，游戏结束只允许查看和返回大厅。

R03. 银行借款、到期和多笔贷款
- 普通贷款要求信用良好、金币>0、没有未结清银行贷款；上限为当前金币分除以 2 向下取整。
- 默认私人负债不影响普通银行贷款资格；作为开局前房间配置记录，整局不变，教程如实说明。
- 普通和赌博透支贷款均每轮利息 10%；N 轮生效，N+1 开始计息，N+3 轮计息后到期。
- 到期可选择全额偿还或拒绝；拒绝、超时或余额不足均使该笔失信，不自动扣部分余额。余额不足时直接进入失信处理并显示原因，不额外等待无效选择。
- 主动还款可在自己的主要行动中对一笔 ACTIVE/DEFAULTED 银行贷款部分或全部偿还，金额不超过金币和剩余债务。
- 赌博透支贷款可以与其他银行贷款并存；每笔分别保存生效轮、到期轮、剩余本息和状态。
- 一笔贷款失信只将该笔设为 DEFAULTED；其他未到期贷款继续原计息与到期安排，不提前到期、不失效、不清零。
- 银行是否“在贷”由未结清贷款汇总得出，不使用一个可能失真的布尔值代替借条列表。

R04. 信用与失信欠款
- 信用为 GOOD/DEFAULTED；本局一旦失信，之后还清仍保持 DEFAULTED，不能新增普通银行贷款或使用赌博杠杆。
- DEFAULTED 贷款停止继续计息，仍允许存活借款人在自己的行动中偿还。
- 银行贷款剩余金额还至 0 后设 REPAID；若该笔曾失信，历史违约记录与玩家本局 DEFAULTED 信用仍保留。
- defaultedBankDebtCents 是所有 DEFAULTED 银行贷款“当前剩余未偿金额”之和，必须随还款递减。
- 失信时原始欠款、原因和轮次保留在不可被还款覆盖的历史事件中；历史金额不再次叠加到总负债。
- 例：失信时欠 100，后偿还 40，公开显示“失信，欠银行 60”；历史仍显示曾失信 100。全部还清后显示“失信，银行失信欠款已结清”。
- 其他仍正常计息的银行贷款单独显示，不与公开的失信欠款金额混淆。

R05. 私人借款请求与生效时点
- 请求内容包括 requestId、借款人、出借人、本金、每轮利率、创建轮/阶段、截止时间与状态。
- 借款人和出借人必须都是本局存活玩家，不能向自己借款，利率 0～100%，本金>0。
- 普通行动中，合法发起请求即用掉本次行动；当前行动保留为“等待出借人答复”，不能立即跳到下一人或赌博。
- 请求截止时间=min(发起时刻+房间配置的请求时限，当前行动截止时间)。标准请求时限为45秒，快速为20秒，以R10为准；本次行动只剩5秒时请求就只有5秒，不另行追加完整时限。
- 同意、拒绝、取消或超时后该普通行动结束；拒绝/取消不退还行动。最多一个待处理请求。
- 出借人必须明确同意；同意时重新校验身份、双方存活、请求仍 PENDING、当前阶段匹配、未到截止时间、出借人当前可用余额足够。
- 验证通过后同一原子转移中扣出借人、加借款人、创建借条并标记请求 ACCEPTED；任何失败都不能只改变一方资金。
- 已通过格式校验的同意若因余额等业务条件失败，将请求设 FAILED 并结束普通行动；身份错误/伪造操作只拒绝消息，不改变真实请求。
- 借条在同意成功时生效；用批准所在轮作为 issuedRound。拒绝、超时、取消、失败不产生借条或转账。
- 行动结束或危险结束必须消灭对应待办；重复同意返回原结果，迟到同意不得转钱。跨到下一轮或赌博阶段的借款请求一律无效。
- 请求界面展示借款人信用、银行失信当前欠款、私人债务总额及冻结部分、借款金额、利率、双方历史借贷和截止时间。出借人同意/拒绝不消耗其下一次行动。

R06. 私人计息、还款与催债
- ACTIVE 私人贷款按约定利率对剩余本息逐轮复利；下一轮才第一次计息。
- “满一轮可催债”统一解释为 currentRound >= issuedRound+1；源码只打印提示却继续催收的行为必须修复。
- 主动还款：借款人在自己的行动中，对一笔 ACTIVE 私人贷款支付正金额，不超过当前金币和剩余本息。
- 催债：出借人在自己的行动或本人危险自救中，对一笔可催收 ACTIVE 贷款指定正金额，上限为 min(剩余本息,max(0,借款人当前金币))。
- 余额不足则拒绝该数额并返回合法上限，不强行让对方进入负金币，不默默改成另一金额。
- 部分收回 20 时，只对双方金币和该债务减少/增加 20；不能按原总债务扣账。
- 全额结清设 REPAID、剩余金额为 0，历史本金与事件保留。每个还款动作只针对一笔贷款。

R07. 赌博与锁定
- 所有存活玩家同时提交 betCents、guess(0或1)、leverage(1或2)，金额范围 0～提交时金币。
- 一次提交即锁定，不能事后修改；每轮每名玩家只能锁定一次。提交 0 合法。
- GOOD 可选两倍杠杆，DEFAULTED 只能一倍；猜对净增加 bet×leverage，猜错净减少同额，下注提交时不预扣本金。
- 全部锁定之前，对其他玩家隐藏金额、猜测和杠杆；只显示谁已提交及提交人数。自己的锁定内容可重连查看。
- 所有人提交后立即结算，不等满倒计时；超时未提交按下注 0、猜测 0、杠杆 1 补齐。
- 全体使用同一个服务器等概率 0/1 结果。玩家不能指定结果，测试环境才可注入固定结果。
- 从进入 BETTING 到开奖提交完成，禁止其他经济操作，保证锁定时的余额不会被借款、还款或催债改变。
- 杠杆结算导致金币<0时，在同一结算中创建缺口金额的赌博透支贷款，并把金币归 0；特殊贷款不受普通贷款 50% 上限限制。
- 未开杠杆出现此类透支应视为规则不变量失败，不能悄悄用贷款掩盖错误。
- 开奖、全体金币变化、透支借条、结果事件和阶段推进作为一个一致变更保存后才公布。

R08. 税收、危险自救与胜负
- 每三轮每名存活玩家缴 20 金币，按座位依次处理，保留原规则的顺序；不能中途改为同时扣税。
- 本轮 TAX 开始时确定应处理座位列表，每人只扣一次；当前玩家的危险处理完成后才轮到下一名。
- 扣税后金币>=0则通过；金币<0进入 DANGER，自己的总自救窗口按房间配置计算，标准60秒、快速45秒，以R10为准。
- 危险玩家可催收符合条件的债权、向存活玩家申请紧急借款或放弃；不能向银行借款。自救不受普通行动一次额度限制。
- 自救期间可依次多次尝试，最多一个待处理借款；有请求待处理时，只能等答复、取消该请求或放弃，不同时发起其他经济操作。
- 紧急借款截止时间=min(发起时刻+房间配置的请求时限，自救截止时间)。被拒/失败/取消后，剩余时间内可以再试；每名玩家发起请求至少间隔 2 秒，不重置自救总时间。
- 批准金额只填平部分缺口时继续自救；任何操作后金币>=0立即完成自救并关闭相关待办；放弃或超时且仍<0则破产。
- 串行税收意味着后座位玩家可能先借钱救人、随后自己还要纳税，出借确认界面必须提醒其本轮是否尚未纳税。
- 即使中途暂时只剩一人，也先完成本轮全部应收税处理，再判胜负，避免末位玩家漏交税；因此仍可能全员破产。

R09. 破产后的债务与债权（修订版设计默认）
- 破产不恢复、不换人接管该身份；取消其未决请求，不接受新经济命令，不继续为相关合同计息。
- 破产者欠银行的钱：全部尚未结清银行贷款转 DEFAULTED，保留当前欠款，公开显示；已破产者不再允许还款。
- 破产者欠其他玩家的钱：私人合同设 BAD_DEBT，保留剩余金额和历史；出借人可收回应收中剔除，坏账栏目单独列示，不再计息、催收或还款。
- 其他存活玩家欠破产者的钱：合同设 FROZEN，冻结剩余金额，停止计息、催收和还款；借款人账上显示“债权人已破产，合同冻结”，不伪装为已经偿还。冻结合同本局不重新激活。
- 如果冻结合同的借款人后来也破产，转 BAD_DEBT，并保留原冻结事件。
- 私人合同状态为 ACTIVE/REPAID/BAD_DEBT/FROZEN；银行为 ACTIVE/REPAID/DEFAULTED。BAD_DEBT 与 FROZEN 绝不在界面上误标为 REPAID。
- 总负债=本人所有非 REPAID 合同剩余金额之和，各状态分项展示；其中冻结/坏账为保留记录，不能当作当前可操作债务。
- 可收回应收=本人作为出借人的 ACTIVE 私人合同剩余金额之和；冻结应收和坏账损失单列，不计入可收回应收，不计入金币。
- 例：A 借给 B 50 后 A 破产，B 仍保留冻结负债 50，本局不能还给 A；B 后来也破产则变坏账记录，不出现任何凭空转账。

R10. 倒计时与游戏节奏
- 默认：普通行动 60 秒；私人请求最多 45 秒且受当前行动/自救剩余时间约束；每笔银行到期选择 45 秒；赌博提交 45 秒；危险自救总共 60 秒。
- 默认超时动作：普通行动自动结束，取消关联待办并推进下一座位/下注；私人请求按拒绝处理；银行到期按拒绝还款；赌博未提交者补0下注；危险状态仍为负则按放弃并破产。所有超时动作由服务器执行，不等待客户端确认。
- 所有有效操作完成立即推进，不为了用完倒计时而等待；查询不重置计时，刷新/重连不重新计时。
- 时间使用服务器记录的 deadlineAt，客户端只显示估算倒计时。处理时 now>=deadlineAt 即截止，先处理到期系统动作，迟到命令不能抢过超时。
- 房间开局前可选择“标准”或“快速”预设；快速模式分别为行动30秒、请求20秒、到期20秒、下注30秒、自救45秒。首版标准为默认，整局参数固定。
- 第 2C/3D 子阶段记录真人操作耗时和实际等待。10人标准模式仅行动就可能用10分钟；先验证体验，再依据记录调整下一局默认值，不能未记录就改正在进行的局。

============================================================
四、身份、协议、并发与隐私
============================================================

1. 身份与房间生命周期（第 2 阶段实现）
- roomId/gameId 使用不复用的内部唯一 ID；公开数字房间码只用于找房间，不能作为玩家身份或命令去重的唯一范围。
- playerId 稳定，seatId 服务端分配；socket 只是可替换的连接。客户端自称的 playerId、seat、role、from、cap 不构成授权。
- 创建/加入成功时服务端发随机 sessionToken 和独立 recoveryCode，均至少 128 位安全随机熵。服务端只存摘要及身份映射；所有原始秘密不进公共快照、日志、URL、二维码或 Git。
- sessionToken 在当前 origin 本地保存，用于同源刷新/重连；recoveryCode 只向本人私密展示，提示保存，可复制，验证后能在另一地址/设备取得新 sessionToken 并恢复原 playerId。
- “个人恢复码”与“房间码”在界面明确区分。只知道房间码、昵称或 seatId 不能接管座位。
- 恢复成功发最新本人视图，保留金币、合同、已耗行动、原倒计时和已锁定下注；不重新加入成新玩家，不重做旧交易。
- 同一玩家只允许一个当前有效连接；新连接恢复成功后替换旧连接，并绑定递增 connectionEpoch。旧连接的命令拒绝，旧连接 close 回调不能把新连接标成离线。
- 被替换的旧页面停止自动重连，提示“已在另一页面恢复”；普通网络重连使用指数退避和抖动，避免两个标签页互相抢占。
- 换域名用 recoveryCode 恢复时签发新 sessionToken 并使旧 token 失效；同源自动重连不必每次轮换 token，以免响应丢失造成恢复死锁。
- 个人恢复码遗失且所有有效会话也丢失时，首版不允许凭昵称重置或强行接管；仍有有效会话可生成新的恢复码并立即废止旧码。此限制在保存提示中说明。
- 大厅允许加入/离开，开始时冻结参与身份和座位；进行中只允许原身份恢复，不允许新玩家顶替离线/破产玩家。
- 房间管理者只能准备/开始及重启暂停后的继续等控制，不能改账。管理者离线超过 30 秒后，服务器可将管理权转给在线存活玩家中座位最小者；大厅按在线已加入玩家选择。这不是迁移服务器主机。
- 游戏结束后可只读查看原局；“再来一局”创建新 gameId，不复用旧命令去重范围，也不把旧局恢复码直接用于新局。
- 第 2 阶段身份和去重可暂存内存，并明确提示“服务重启暂不保留”；第 3A 阶段必须连身份摘要一起持久化。

2. 命令与消息
- 客户端业务命令包含：protocolVersion、gameId、commandId、type、payload，以及该命令需要的 expectedGameVersion/roundId/phaseInstanceId/requestId。
- actorId 由已认证连接注入；相同 commandId 只能重发相同规范化载荷，不允许改金额后沿用原 ID。
- 服务端消息包括：加入/恢复结果、本人快照、阶段变化、操作结果、私人待办、公共事件、错误、离线/重连、游戏结束。
- 持久化 gameVersion 表示游戏/财务状态版本；在线人数、心跳和网络连接变化单独通知，不增加 gameVersion，以免制造无关版本冲突。
- 每次已提交的游戏状态转移令 gameVersion 增加1；只读查询、重复命令和不改变游戏状态的纯业务拒绝不增加。使请求终结、行动或阶段推进的业务失败仍是完整状态转移，必须增加版本；自动动作也遵守该规则。
- 快照包含 gameId、gameVersion、schemaVersion、serverNow、deadlineAt 及本人权限视图；客户端按同一 gameId 只采用不低于已展示版本的状态，旧应答不能覆盖新快照。
- /health 返回 ok、服务标识、程序版本、在线连接数和房间数，不返回昵称、房间成员、合同、token 或恢复码。
- 错误码至少区分 UNAUTHORIZED、REPLACED、NOT_YOUR_TURN、INVALID_AMOUNT、INSUFFICIENT_FUNDS、VERSION_CONFLICT、REQUEST_EXPIRED、ALREADY_LOCKED、ROOM_PAUSED、GAME_OVER、COMMAND_ID_REUSED、STORAGE_FAILURE。
- 操作结果应有中文原因和可执行下一步；UI 可显示等待，但不能在成功确认前自行扣款。

3. 排队、去重与版本规则
所有改变同一房间状态的玩家命令、计时到期和内部结算进入同一个串行队列；不要以“Node 单线程”代替异步排队约束。
处理次序：
（1）认证和大小/频率校验，将连接映射到真实玩家。
（2）按 (gameId,playerId,commandId) 查询去重结果，核对类型和规范化载荷摘要。
（3）已有相同命令返回原结果；同 ID 不同载荷拒绝。重复命令即使当前版本/阶段已变化也不重新执行。
（4）对新命令先处理当前已到截止时间的系统动作，再校验该命令的阶段、权限、金额与规则。
（5）构造下一状态，执行第四、五节规定的保存流程，然后应答和推送。

分命令校验：
- 当前行动中的借款/还款/催债/结束行动：严格校验 expectedGameVersion。冲突返回最新本人快照，玩家重新确认后使用新 commandId；不可自动按新余额重放旧经济意图。
- 下注：按 gameId+roundId+phaseInstanceId+playerId 校验本轮阶段、是否已锁定和当前余额，不因其他玩家刚下注导致的全局版本变化拒绝正常提交。
- 私人请求同意/拒绝：按 requestId、请求所属阶段、截止时间、指定出借人及当前余额校验，不因无关状态版本变化失败。
- 银行到期选择：按 loanId、当前到期处理实例、借款人、截止时间校验，并重新检查余额。
- 系统动作：使用服务器生成的唯一 ID，客户端不能发送系统命令。示例 gameId/phaseInstanceId/timeout、gameId/loanId/interest/round、gameId/tax/round/playerId。
- 下注等语义重复且用了不同 commandId：不得覆盖第一次内容，返回 ALREADY_LOCKED 等明确结果。
- 暂时网络断开时保存未确认命令 ID；恢复后只允许原 ID 原载荷查询/重发。连接恢复不代表待处理命令必定失败，也不代表必定成功。
- 第 2 阶段以内存记录去重；第 3A 阶段起，已认证合法业务命令的终局成功/拒绝结果保存至本局归档。非法 JSON、认证失败、限流等不写入业务账本。

4. 权限视图
- 服务端每次为每名玩家生成独立 PlayerView；不能发送全量私密状态后让前端隐藏。
- 公开：昵称、座位、存活/危险/离线、信用、当前失信银行欠款、轮次/阶段、允许公开的提交状态和结算结果。
- 自己：全部金币、债务、债权、私密待办、本人锁定赌注与财务事件。
- 私人合同双方：该合同的完整本金、利率、剩余本息、状态、轮次和交易历史。
- 未参与合同者：首版仅能查询公共信用和失信银行欠款，不提供第三方私人合同明细。向某人申请借款时，额外向该出借人提供 R05 规定的风险摘要；不包含借款人与其他人的逐笔私密合同。
- 此查询范围沿用 V1.1 默认。若以后希望全员查看彼此所有借贷，必须作为明确规则变更，同步服务端过滤、教程和测试，不能只改 UI。
- 下注锁定前，保密要求同时覆盖快照、事件查询、操作应答、错误详情和重连补发；日志也不能把全量命令载荷直接输出。
- 恢复码/token 永远不进入普通 PlayerView，只通过专用私密认证响应返回本人。

============================================================
五、持久化、自动动作与恢复
============================================================

1. 第 3A 阶段建立的一致提交流程
在房间串行队列中完成认证、去重和规则校验后：
（1）在旧状态的副本上生成完整下一状态、事件和操作结果，检查账务不变量。
（2）一个 SQLite 事务同时写入：最新快照、gameVersion、事件、commandId/载荷摘要/操作结果，以及本操作相关身份或房间元数据。
（3）COMMIT 成功后，替换房间对外可见内存状态，应答玩家并广播过滤后的新视图。
（4）失败则回滚，保持旧状态，不应答“成功”；无法确认提交结果时先重读数据库并以其事实裁决，不能继续凭猜测推进。
- 不改变游戏状态的纯业务拒绝只保存命令结果，不推进版本；重复该 ID 返回同一个拒绝。请求设为FAILED、行动结束或阶段推进等有状态变化的业务失败，须同事务保存快照、事件、版本和结果，再广播，不能按纯拒绝处理。存储暂时不可用不能冒充业务拒绝已持久化。
- 数据库不可写时暂停该房间经济推进并提示，不允许悄悄降级成内存模式；其他健康房间是否继续由存储故障范围决定。
- 禁止先改共享余额/广播，再异步补存档；禁止把去重表只存在内存；禁止仅靠事件日志回放又重复随机或计息。
- 数据模型可包含 rooms、players、events、processed_commands 等表；最新一致快照为恢复依据，事件用于审计，不要求首版做完整事件溯源框架。
- schemaVersion、协议版本、rulesVersion、房间配置和更新时间一并保存；不兼容版本必须明确拒绝载入或执行已验证迁移，不能静默开新局覆盖。

2. 系统命令与随机结果
- 计息、到期默认拒绝、请求过期、默认下注、开奖、扣税、破产、阶段推进，都按确定 ID 进入与玩家命令相同的提交路径。
- 计时器只是唤醒信号，数据库状态与 deadlineAt 才是依据。重复唤醒、旧阶段计时器、重连补发都不能重复扣款。
- 使用 phaseInstanceId 区分同名阶段的不同实例；阶段变更后清理旧计时器，即使未清理的回调到达也必须拒绝过期实例。
- 开奖使用服务器安全随机源生成 0/1，随机结果与全体结算同事务保存，提交后公布；已提交的开奖重试或恢复绝不重新抽取。
- 若进程在开奖提交前崩溃且结果从未公布，恢复后重新生成未提交结果可以接受；不得把未提交结果提前放入客户端、公共日志或动画。
- 人机测试使用注入的时间和随机结果，生产客户端无权启用固定随机数。

3. 服务器重启后的默认恢复策略
- 网络短断/页面刷新：服务器未停机，原 deadlineAt 继续有效，不暂停或延长。
- 服务器进程重启：进行中的房间加载到 PAUSED_RECOVERY，只允许恢复身份和查看；不补算停机期间的回合，不因旧绝对截止时间立即让全员拒付或破产。
- 房间管理者恢复身份后明确点击“继续游戏”；管理者缺席时按第四节管理权转交规则由已恢复的存活玩家继续。
- 本版选择简单且明确的规则：恢复继续后，当前未完成行动/到期选择/下注阶段/危险状态获得该阶段配置的完整时限；当前未决私人请求重新获得 min(请求时限,所属窗口时限)。不声称保留断电那一刻的精确剩余秒数。
- 继续动作及新截止时间先保存再开始计时；已提交下注仍锁定，已转的钱不重转，已完成的计息/税收不重做，未决请求仍须双方真实批准。
- 恢复码摘要、sessionToken 摘要、玩家映射、稳定座位、房间管理者、已接受命令结果、未决请求和已锁定赌注均须随档恢复。
- ERROR_PAUSED 用于不变量/容量等故障，不能靠普通“继续游戏”绕过；修复并验证后才恢复最后一致状态。
- 整局所有人离线但服务器仍运行时，继续遵循正常超时规则；这与服务器重启暂停是两种明确行为，界面及说明应告知。

4. 备份与恢复边界
- 提供一致性备份：使用驱动的在线备份能力，或停止写入并正确关闭数据库后复制；不能在 WAL 写入期间只复制主 db 文件。
- 升级/迁移前备份。恢复操作不得自动覆盖唯一现存档，先保留原档并校验备份可读取。
- 存档损坏、不支持的 schemaVersion、磁盘已满、无写权限必须明确报错，保留诊断信息和恢复说明。
- 备份含玩家身份摘要与游戏数据，只保存于本机非公开目录；运行日志不得记录原始身份秘密。

============================================================
六、界面、教程、配乐与公网入口
============================================================

1. 自己的信息
- 桌面固定“我的财务”面板；手机底部导航“我的、玩家、债务、记录”，自己的关键金币和当前操作始终易找。
- 展示金币、总负债、可收回应收、信用、存活/危险、冻结合同和坏账分项。
- 银行普通贷款、赌博透支贷款、失信欠款分开显示；逐笔列本金、剩余本息、利率、生效轮、到期轮、状态。
- 私人债务列对方、剩余本息、利率、生效轮、是否可催收/还款，以及不可操作原因。
- 显示轮次、阶段、是否已行动、剩余时间，以及利息、税收、赌博和转账事件。
- 主面板与债务查询共用同一份服务端视图，不自行二次计息或独立维护总账。

2. 玩家与债务查询中心
- 玩家列表显示昵称、座位、存活、危险、离线、信用与失信当前欠款；信用使用图标、文字和颜色共同表达。
- 查询中心随时可开，不消耗行动；支持我借入、我借出、待我确认、已结清、冻结、坏账和公共信用。
- 按借款人/出借人/状态/轮次筛选，但结果不能越过第四节权限范围。
- 别人向我借钱时用明显通知和待办角标提示；可直接查看风险摘要及双方历史，再同意/拒绝。金额变化或请求失效时及时更新按钮。
- 请求等待、已锁定下注、存档故障、网络断开、恢复中、连接被替换、暂停待继续均有清楚状态，不能让玩家误以为已经操作成功。
- 不把“连接断开”武断地显示为“服务器已关闭”；浏览器未必知道是网络、隧道还是服务器故障。

3. 布局与触控
- 桌面：顶部房间/轮次/音频，中间阶段操作，左侧玩家，右侧财务与事件。
- 手机竖屏：顶部简要状态，中间当前操作，底部四个入口；主要按钮适合触控，不横向溢出。
- 转账、借款批准、锁定下注、放弃自救提供清楚确认摘要，避免层层重复弹窗。
- 动画不阻塞服务端结算；断线后禁用需要在线确认的操作，重连后以服务器状态重建界面。

4. 新手教程
- 首次进入最多 5 页，约 60 秒可读完，每页都有跳过，可随时重新查看。
- 内容：目标与流程；银行到期/失信；私人同意、还款/催债；赌博/杠杆与税收自救；财务/债务入口。
- 说明锁定后不能改注、失信还清不恢复信用、冻结/坏账含义；详细边界放随时可查的规则页，不把全部技术细节塞进教程。
- localStorage 记已读状态，换设备/换地址可能重新显示；教程状态不影响游戏权限和身份恢复。

5. 音频
- 大厅、正常回合、危险、结算配置循环 BGM；借款请求、转账、到期、破产、胜利配置短音效。
- 总静音、音乐音量、音效音量分别可调并保存到本机；首个用户点击后再尝试播放，正确处理浏览器自动播放限制。
- BGM 平滑切换，不因每次快照重启；锁屏、切后台、重连和回大厅不叠加播放器。
- 只使用自制或有明确兼容授权的素材，记录来源、作者、许可证和署名要求；加载失败不阻塞游玩。

6. 公网与个人恢复码
- Cloudflare Quick Tunnel 用于邀请试玩和测试；无在线时长保证，创建新隧道会换域名。固定域名/命名隧道可后续增加，不作为首版前置。
- 浏览器本地存储按 origin 隔离，从 LAN 切到公网或更换随机域名时，不能假定旧地址的 sessionToken 会自动可用。
- 新地址进入“恢复本局身份”，输入公开房间码和本人保存的个人恢复码，服务端验证后恢复原座位；不能只凭昵称认领。
- 旧页面可提示断线和“获取新的邀请地址”；不能保证自动获知新域名。新链接由开服者重新分享，个人恢复码不随公开邀请转发。
- 公网二维码只能含公开邀请地址/房间码，不能含个人恢复秘密；手机使用蜂窝网络测试时不能给它 LAN 二维码。
- /health 只能证明本地服务响应，公网验收必须在实际外网设备上打开网页并建立 WSS；不能仅凭隧道打印 URL 就写“公网通过”。

============================================================
七、分阶段实施与独立验收
============================================================

0～6 为大阶段；1A、1B 等为可以独立完成和交接的子阶段。每次 Harness 会话只执行一个子阶段，完成不了可分多轮；不要求一次调用包办整个大阶段。
顺序：0 → 1A → 1B → 1C → 2A → 2B → 2C → 3A → 3B → 3C → 3D → 4 → 5 → 6。
每个子阶段通用工作单：
[ ] 读取规则与最新交接，检查实际工程，列出要改的文件和验收场景。
[ ] 针对本次新增的关键行为/旧 bug 先写可失败的测试，确认失败原因正确。
[ ] 实现本次最小范围，不抢做后面的玩法或美术。
[ ] 运行对应测试、类型检查和构建，保存真实输出；接口变化要运行受影响的上下游检查。
[ ] Qorder 独立复核并修复阻塞项；需要真机的项目逐项记录，不能用多页面模拟冒充不同实机。
[ ] 写四类交接 TXT、更新当前状态、保存可回退提交，再判断能否进入下个子阶段。
实现、复核工具可按实际能力互换，但不得无协调地同时改同一批文件。

统一脚本在第 0 阶段建立：
- pnpm dev：本地开发，文档说明开发访问方式；不把前端开发端口当正式联机入口。
- pnpm build：构建全部包与静态客户端。
- pnpm start：运行构建后的同源 HTTP+/ws 服务，默认 PORT=8000。
- pnpm typecheck：全工程类型检查。
- pnpm test:core：规则测试，使用 Vitest 非 watch 模式。
- pnpm test:server：服务、权限、存储集成测试，非 watch 模式。
- pnpm test:e2e：Playwright 浏览器端到端测试。
- pnpm test：全部已建立的 core/server 自动化测试。
尚未到建设阶段的测试命令必须明确报告“尚未实现”，不能用空测试或 echo 成功伪装覆盖。第 0 阶段只验收其真实已有的 smoke/schema 测试、类型检查和构建。

阶段 0：规则决策表、接口和可启动骨架
目标：让后续 AI 能从同一个确定起点接手。
主要文件：根 package.json/pnpm-workspace.yaml/锁文件、共享类型与协议、game-core 接口、空前端、http.ts、handoff/规则决策表.txt。
工作：
- 根据第三节建立带来源标签的规则决策表，固定金额编解码、状态枚举、请求时限、版本检查分类和隐私矩阵。
- 明确阶段状态机、命令/视图/事件类型，写正常金额与非法输入的 schema smoke 测试。
- 验证 Windows 下 Node/pnpm/SQLite 驱动可安装及执行一个真实事务，记录版本。
- 建立 Git、忽略文件、脚本和最小 /health，不实现完整规则或页面。
验收：可按说明安装、构建并启动空服务和页面；健康检查正确；类型检查和已有 smoke 测试通过。
不存在上一阶段交接时，初始化当前状态和规则表，不要求读取不存在的文件。需要偏离本版的规则先列出具体影响，不让 AI 暗中修改。

阶段 1A：金额与银行贷款
主要文件：game-core/money.ts、bank.ts，shared 金额编解码与银行类型，tests/core/money.test.ts、bank.test.ts。
输入：阶段 0 的金额、玩家、贷款类型。输出：精确金额运算、银行借/还、计息、逐笔到期与失信转移。
工作：实现 bigint、基点、四舍五入、上限、当前/历史失信金额和贷款状态派生。
必测：
- bank_interest_50：第 1 轮借 50，第 2/3/4 轮债务为 55/60.50/66.55，第 4 轮计息后到期。
- rounding_and_limit：0.05 金币以 10% 计息得 0.01 金币利息；同轮不重复计息；奇数分的 50% 上限向下取整。
- default_repay_100_40：失信 100，还 40，当前为 60、历史仍 100、信用仍失信；总债务不重复叠加。
- multiple_bank_loans：一笔失信，另一笔仍按原计划计息和到期；全部还清才没有未结清银行贷款。
- amount_roundtrip：超过 Number 安全整数范围的合法金额往返编解码保持精确；非法/超长金额拒绝。
验收：pnpm test:core、pnpm typecheck、pnpm build 通过本阶段实际覆盖，无网络依赖。

阶段 1B：私人借款、债务状态与原子账务
主要文件：private-loans.ts、共享请求类型，tests/core/private-loans.test.ts、bankruptcy-ledger.test.ts。
输入：1A 的金额与账务基础。输出：创建/批准/拒绝/取消/过期请求、还款、催债、冻结/坏账转换。
必测：
- consent_required：没同意不转账、不生借条；非指定出借人不能批准。
- private_partial_40：A 借给 B 40，A=60/B=140；下一轮10%利息为44；B还10后A=70/B=130/欠款34。
- collect_partial：催收20只转20、债务只减20；借出当轮不能催，下一轮才可催；借款人负余额不能被催成更负。
- approve_deadline：行动剩5秒时新请求只有5秒；恰好到截止时间的同意不生效；批准时余额不足不出现半笔转账。
- borrower_bankrupt/lender_bankrupt：分别得到 BAD_DEBT/FROZEN，相关总账分项与可操作状态一致。
- concurrent_intents：在固定串行次序下依次喂入竞争操作，后一笔按更新后余额校验，不会超借；不同房间不串账。
验收：规则测试、类型检查、构建通过，转账账目能用每笔事件解释。

阶段 1C：完整轮次、赌博、税收、自救与胜负
主要文件：engine.ts、gamble.ts、tax.ts、views.ts，tests/core/round.test.ts、gamble.test.ts、tax.test.ts、views.test.ts。
输入：1A/1B 的账务能力。输出：applyCommand 完整规则状态机、getPlayerView 权限投影、自动阶段转移和定时目标。
必测：
- gamble_100：100本金下下注100；一倍输后0，一倍赢后200；二倍赢后300，二倍输后金币0并有透支贷款100。
- waiting_loan_blocks_next_phase：借款等待未结束不能进入赌博；赌博期间任何借款确认/还款/催债均无效。
- action_timeout_advances：普通行动超时后结束并清除关联待办，轮到下一名存活玩家；最后一名超时后进入下注，迟到操作不生效。
- danger_partial_rescue：税后-20，借到10后仍危险，再补到0立即结束；没有因多次尝试延长总时间。
- tax_all_due_before_win：纳税中暂剩一人，仍处理其应交税；全员破产无获胜者。
- system_once：每笔本轮利息、每名本轮税收、每次开奖语义上只执行一次，重复内部动作不重复生效。
- privacy_views：第三人看不到私人合同，锁定前他人猜测/金额/杠杆不进入任何玩家视图。
验收：使用固定时间和随机序列，脚本自动跑完至少一局2人和一局10人；覆盖到期、失信、透支、税收与破产分支。网络 commandId 持久化去重由后续服务层测试，不把数据库塞进规则引擎。

阶段 2A：同源服务器、大厅与房间
主要文件：http.ts、rooms/manager.ts、web 大厅与 net、tests/server/rooms.test.ts。
输入：完整规则引擎和共享协议。输出：HTTP+/ws、房间管理、服务端分配身份/座位的基础接口。
工作：创建/加入、房间码碰撞检查、2～10人容量、准备、管理者开始、开局名单冻结、专用静态根目录、LAN地址和二维码。
验收：本机与另一设备能打开同一服务；人数/座位/准备一致；满员、重复房间码、进行中新加入、伪造角色被明确处理；源码和data不能通过HTTP下载。
此时只做局域网开发验收，不开放公网，不宣称已支持稳定重连。

阶段 2B：稳定身份、基础重连、命令队列与内存去重
主要文件：rooms/session.ts、command-queue.ts、scheduler.ts，web/net/reconnect.ts、恢复入口，tests/server/session.test.ts、commands.test.ts。
工作：接通完整规则引擎、本人权限视图和计时调度，使全部规则命令可经真实WebSocket调用；完整实现第四节身份规则、个人恢复码、连接epoch、ping/pong失效关闭、退避重连、按命令分类校验和内存去重。此时完整操作可由集成测试客户端驱动，业务UI仍按后续阶段逐步补齐。
必测：
- refresh_same_seat：刷新后原金币、座位、行动和待办不变。
- replace_connection：旧连接被拒；旧close不把新连接置离线；旧标签页不自动争抢。
- ack_lost_retry：转账应答丢失，原ID重发只执行一次；相同ID换金额拒绝。
- ten_bets_same_version：10人持相同版本同时下注，各自一次合法提交均可被接受。
- recover_different_origin：以两个不同本地origin验证新origin不能直接使用旧存储，但个人恢复码可找回原身份。
验收：pnpm test:core、pnpm test:server、pnpm typecheck、pnpm build 通过；至少一次实机刷新/短断网恢复。界面明确此时服务重启仍会丢内存房间。

阶段 2C：最小可玩联机与首次试玩
主要文件：web 游戏页、最小操作面板、tests/e2e/lan-smoke.spec.ts。
工作：在2B已接通的规则命令和快照上完成最小 UI，提供银行借/还、结束行动、下注、自己状态、阶段和倒计时。到期/危险可先走已有默认超时路径，私人借贷的完整 UI 在3B完成。
验收：
- 两名真实浏览器玩家完成一整轮；再由服务器电脑、另一电脑/手机共同加入核对公共状态。
- 至少一次真实操作、刷新和断网恢复；前端不自行算金币，非当前玩家不能代操作。
- 10个自动化客户端验证排队和下注，不将其写成10名真人试玩。
- 记录一次真人短试玩的操作耗时、等待时长、理解困难和设备；可记录“尚无完整债务UI”，不能声称完整游戏体验已通过。
此阶段先证明可连接、可推进、可恢复；不做美术打磨。

阶段 3A：可靠存档与服务器重启恢复
主要文件：storage/sqlite-store.ts、migrations/、rooms/recovery.ts，tests/server/persistence.test.ts、crash-recovery.test.ts。
输入：2B 已统一的命令队列、稳定身份和内存Store。输出：第五节的持久化提交与暂停恢复机制。
工作：切换 SQLite Store，保存身份摘要/快照/事件/去重，系统命令同路保存，先提交后广播，重启暂停再继续；提供可验证的一致备份入口。
必测：
- crash_before_commit：提交前中止，恢复保持原账；无未提交成功消息。
- crash_after_commit_before_ack：提交后应答前中止，恢复后重发返回原成功，无重复转账。
- timeout_and_result_once：重复超时、重复开奖、重启后计息与税收不重复。
- restart_paused：旧deadline已过仍先暂停；继续后新时限按配置，已锁赌注不解锁。
- credentials_restored：恢复码能在进程重启后找回原身份；快照含精确的大额金额字符串。
- write_failure：磁盘/写入失败不广播成功，不改共享账；故障明确。
验收：实际启停独立服务进程完成故障注入；测试、类型检查和构建通过。没有此子阶段的证据，不进入完整公开试玩或美术阶段。

阶段 3B：完整借贷交互、风险通知与债务中心

八、DeepSeek Harness / Trae / Qorder 的执行与交接
============================================================

1. 角色与工作粒度
- DeepSeek Harness 每次选一个明确子阶段，核对输入文件、分配实现与复核、收集真实运行证据并检查交付。
- Trae 负责实现和测试；Qorder 独立检查规则偏差、并发/权限、持久化边界和测试缺口；实际工具不同可交换职责。
- 若一个子阶段仍超过单次上下文，拆为有名字的小任务，写明当前做到哪一步；子阶段只有全部必需项通过才完成。
- 不让两个 agent 无协调修改同一文件。复核发现问题后由一个明确负责人修复并重新运行受影响测试。
- 源码是规则来源之一，存在已记录的bug时以决策表为准；不为了“忠实移植”重新引入未经同意转账、失信清债和部分催债扣错账。

2. 固定工作顺序
读本版方案/规则表/当前状态/上个交接 → 检查真实工程 → 列本次范围、文件和验收 → 必需测试 → 实现 → 执行测试/构建 → 独立复核 → 修复和必要重测 → 所需真机验收 → 提交实现代码 → 写交接并提交文档。
- 记录实际被验证的实现提交号，禁止用后来改过但未验证的代码冒充同一版本。
- 测试日志放 artifacts/test-logs/，注明命令、时间、环境、退出码及日志路径；不复制token等秘密。
- 若测试后仅修改交接文本，文档提交另行保存，不要求文档中写入其自身尚未产生的提交号。
- 上游关键规则、协议或数据不一致时先修复阻塞项；其他非阻塞改进列待办，不以修复为名扩写新玩法。

3. 固定交付文件名
每个子阶段写四类TXT，例如阶段03A：
（1）handoff/阶段03A-成果报告.txt
    本次完成项、未完成项、改动文件、测试命令与真实结果、日志路径、复核结论、已知问题、被验证的实现提交号。
（2）handoff/阶段03A-运行与验收说明.txt
    环境/依赖版本、安装/启动/测试方式、访问地址、创建房间步骤、逐步操作与预期结果、真机验证记录及未验证项。
（3）handoff/阶段03A-下一阶段交接.txt
    最新架构与入口、数据流、协议/状态/数据库变化、迁移/回退方法、下一子阶段入口、禁止破坏的不变量。
（4）handoff/阶段03A-注意事项.txt
    限制、兼容问题、临时实现、风险、待办、绝不能重复的错误；未解决项写影响和验证办法。
编号统一：00、01A、01B、01C、02A、02B、02C、03A、03B、03C、03D、04、05、06。
共 14 个子阶段/单元；按这些编号执行，不用“预计一次完成”限制调用次数。

同时更新：
- handoff/项目当前状态.txt：只保留最新有效摘要；方案/规则/协议/schema版本、已完成编号、当前子任务、可运行状态、提交号、启动命令、验证状态、阻塞、下一入口和应读文件。
- handoff/规则决策表.txt：只在实际规则变化时更新，标注来源、影响范围与测试，不重复抄写多份互相矛盾的规则。
- 若本轮未做完，仍写四类TXT，特别指出中间代码是否可运行、哪些命令尚未验证，防止下次从错误假设继续。

4. 状态与完成定义
- “完成”：本子阶段必需功能实际运行，相关自动化测试/类型检查/构建通过；该阶段明确要求的真机/真人验收已记录；无未解决阻塞；交接齐全；已有可回退Git提交。
- “代码验证通过，人工验收待完成”：自动化通过但缺真实设备或试玩；列出最少需要的人/设备和具体操作，不虚构记录。
- “部分完成/被阻塞”：明确失败原因、已验证部分和下一步，不把未执行的命令标为通过。
- 纯规则子阶段无需机械地要求人拿手机验收；第2C、3D、4、6等明确涉及实机/真人时才要求对应证据。
- 上一单元的必要前置未通过，不开展依赖它的新功能；可继续处理本单元修复、文档和未完成验证。
- 一个大阶段的所有子阶段满足条件后才标大阶段完成。不能因“文件生成完了”直接宣布可发布。

5. 可直接复制给 Harness 的启动提示词
“请按《Richman分阶段联机开发方案_V1.2修订版.txt》只执行阶段00。先检查实际工作目录和环境，读取大富翁.cpp作为规则来源，按本方案建立规则决策表、共享类型、接口、测试入口与最小可启动骨架。V1.2明确补齐的默认规则优先于源码中的已知bug；不得自行增加玩法。首次执行时初始化handoff/项目当前状态.txt，不要求不存在的上一阶段交接。先列修改文件和验收，再实现并运行真实命令，安排独立复核，写齐阶段00四类交接TXT并保存Git提交。本次不实现完整游戏，不把尚未存在的测试标为通过。”

6. 可直接复制给 Harness 的后续提示词
“请只执行《Richman分阶段联机开发方案_V1.2修订版.txt》的子阶段【填编号，如03A】。先读方案、handoff/规则决策表.txt、handoff/项目当前状态.txt，以及当前状态指定的上一子阶段四类交接文件。检查真实代码、提交和测试记录，先列本次范围、修改文件、接口依赖和验收场景，再实现。不得暗改冻结规则，不得把账务逻辑塞进UI或Socket回调，不得伪造命令结果、使用空测试或假数据冒充完成。用Trae实现、Qorder独立复核，或按实际能力交换，但避免同文件并行修改。完成后运行相关测试、类型检查和构建；实机验收缺失如实写未验证。无论成功或失败，写齐本子阶段成果报告、运行与验收说明、下一阶段交接、注意事项四类TXT，并更新项目当前状态，记录真实实现提交号。发现上游阻塞先修复；一个子阶段可多轮完成，不抢做下一阶段。”

九、关键验收清单与边界场景
============================================================

本清单与各子阶段测试互相对应，后续不得以“难实现”为由删除。规则变更时更新预期并说明原因。

账务与金额：
[ ] 初始100、利息舍入、贷款50%上限、逐轮复利结果准确，跨JSON/SQLite精度不丢失。
[ ] 所有金币变化都有交易/结算事件解释；私人转账双方合计金币不变，赌博、银行与税收按各自规则解释资金变化，不错误要求全局金币恒定。
[ ] 总负债按借条汇总，不重复加失信派生额；可收回应收只统计ACTIVE，冻结/坏账单列。
[ ] 部分还/催只变实际金额，全部结清剩余为0；同轮重连不重复计息，同笔不重复转账。
[ ] 一笔银行失信不抹去其他笔；失信后还款减少当前欠款但保留历史和失信信用。
[ ] 未同意借款无转账；批准时余额不足无半笔交易；借款当轮不能催，下一轮才可催。
[ ] 负金额、超精度、超长字符串、非法利率、超额输入拒绝；内部越界保留一致状态，不截断或造钱。

阶段与竞争：
[ ] 普通借款有效发起即耗行动，等待期间不提前进入下一阶段；拒绝/取消不退行动。
[ ] 请求/行动/自救时间嵌套正确，截止时的同意无效；迟到消息不能向已破产者转账。
[ ] 十人同时下注不因全局版本变化被批量拒绝；每人只锁一次；下注期间没有其他资金挪动。
[ ] 杠杆透支独立成贷款；一倍下注不会因异步借款出现意外透支。
[ ] 危险自救多次操作不重置总计时，补到0立即结束；按座位完整收税后才判胜负。
[ ] 债权人先破产、借款人后破产的合同状态转换正确；已破产者不能被还款“复活”。
[ ] 游戏结束拒绝一切经济操作；普通离线有超时路径，服务器重启则按明确暂停规则处理。

身份与隐私：
[ ] 玩家不能替他人批准、下注、还款或结束行动；伪造seat/role/from无效。
[ ] 未参与私人合同者不能从快照、事件、响应、错误或重连补发读到其细节。
[ ] 未开奖时其他玩家看不到下注金额、猜测和杠杆；本人可恢复锁定内容。
[ ] 失信当前欠款对各玩家一致；历史金额不被当成当前欠款。
[ ] 换origin/换隧道域名可用个人恢复码回原座位；房间码和昵称不能恢复身份。
[ ] 新连接替换旧连接后旧消息无效，旧close不影响新连接；秘密不进URL、日志或公共数据。

保存与故障：
[ ] 同ID同载荷重试返回原结果，同ID换载荷拒绝；游戏ID不同不串用旧命令。
[ ] 提交前崩溃不出现已公布成功；提交后应答丢失可恢复原成功且不重做。
[ ] 超时、计息、开奖、税收有确定系统ID；重复计时器不能重复结算。
[ ] 恢复先暂停，不连续补算离线回合；继续后的新计时、已锁下注、请求状态均正确。
[ ] 写入失败不先改共享账/广播；损坏存档不覆盖；schema不兼容有明确处理。
[ ] 备份含完整一致数据与身份映射，可实际恢复；WAL模式不能只热复制主db。

体验与运行：
[ ] 教程可跳过/重看；债务中心随时可查，借款通知有风险信息和有效倒计时。
[ ] 手机可完成全部操作；信用不只靠颜色；加载和失败状态有清楚文字。
[ ] 静音生效，后台回来/重连不叠音，音频缺失不妨碍一局完成。
[ ] 真人试玩记录等待时长；自动化人数与真人数、模拟视口与真实手机分开报告。
[ ] LAN和真实外网都跑完一局；隧道变化后的恢复实测；启动/停止不误杀其他进程。
