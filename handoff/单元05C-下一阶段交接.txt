【架构与入口】
- 入口：apps/web/src/App.tsx。持有 RichmanClient、snapshot、events、连接状态。
- 游戏页：apps/web/src/GameView.tsx。只消费 snapshot + events + 本地 uiState。
- 引导推导：apps/web/src/game/steps.ts（纯函数）。deriveStep(view, uiState) 返回唯一 GuidedStep。
- 结算推导：apps/web/src/game/settlement.ts（纯函数）。deriveRoundSettlement(events, round, viewerId)。
- 网络：apps/web/src/net/client.ts（WS、重连、resume、命令方法、events 分支）。
- 形状与展示：apps/web/src/net/wire.ts（wire 类型、金额/利率/状态格式化）。

【数据流】
服务端 commit → 广播 snapshot（本人视图）→ App.setSnapshot → GameView deriveStep。
服务端同步发送 events（已按可见性过滤）→ client.onEvents → App 累积 → 结算卡展示。
客户端命令：GameView → client.sendCommand（commandId + protocolVersion + gameId + expectedGameVersion；
下注额外 roundId/phaseInstanceId）→ 服务端权威校验。
金额：wire 十进制字符串，界面只用 formatCents/rateLabel 格式化，不做加减乘除。

【引导顺序如何从快照推导】
1. GAME_OVER 或 winnerId 非空 → 游戏结束视图。
2. finance.incomingRequests 非空 → 收到的借款请求（同意/拒绝，不消耗行动）。
3. finance.pendingRequest 非空 → 等待出借人答复（可取消）。
4. ACTION：
   currentSeatId ≠ me.seatId，或 actedSeats 含 me.seatId → 等待；
   否则 → 本人行动，按本地 actionStage 依次问 Q1→Q4；
   actionStage=askDebt 且 debtOptions 为空 → 自动跳到 endAction。
5. BANK_DUE：pendingDueLoanId 命中本人银行贷款 → 到期决策；否则等待其他人。
6. TAX：me.status=DANGER 且存活 → 危险自救（本地 dangerStage）；
   否则若有其他存活 DANGER 玩家 → 等待对方自救；否则等待税费结算。
7. BETTING：finance.myBet 非空 → 已锁定；本人已破产 → 等待；否则按下注 stage 依次问。
8. 其他（INTEREST）→ 通用等待。

本地 uiState 只在“当前阶段内”记录点到了哪一问；phaseInstanceId 变化或命令成功时归零。
失败不推进 uiState，因此页面停留在原问题并显示失败原因。
