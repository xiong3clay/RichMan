一、本轮固定接口
apps/web/src/game/steps.ts
- GuidedStep.requestLender = { kind, request, pendingCount: number }
- deriveStep 收到请求时返回 incomingRequests[0] + pendingCount=incomingRequests.length；
  顺序严格按服务端数组，不排序；收到请求仍优先于自己发出的 pendingRequest。
apps/web/src/game/request-deadline.ts
- requestDeadlineIso(deadlineMs: unknown): string|null
  finite → new Date(ms).toISOString()；NaN/Infinity/非数字/越界 → null。
- isRequestExpired(deadlineMs: number|null|undefined, serverNow: string,
  receivedAtMs: number, nowMs = Date.now()): boolean
  用 calibrateServerClock 校准；deadline <= 服务端 now 即 true；非法输入 false、不抛错。
apps/web/src/game/use-request-expired.ts
- useRequestExpired(deadlineMs:number|null, serverNow:string, receivedAtMs:number): boolean
  250ms interval；卸载清理；serverNow/deadlineMs/receivedAtMs 变化重新校准。
apps/web/src/GameView.tsx
- 借款人卡/出借人卡“请求截止”只用 request.deadlineMs；
- 过期：固定文案“已截止，等待系统收口”，取消/同意/拒绝/确认按钮 disabled；
- acceptLoan 确认卡过期自动 setConfirmAction(null)，showConfirmation 对
  acceptLoan+requestExpired 返回 false；
- 出借人卡固定文案“待答复请求：共 {pendingCount} 个，当前第 1 个；答复后自动出现下一笔。”；
- actionWait 在 acted=true 且 seatId=null 时“本轮行动已结束”+“正在等待未答复的
  借款请求收口；全部答复或到期后自动进入下注。”；acted=false+seatId=null 的旧文案保留。

三、下一阶段若扩展
- 不要新增全局“待答复请求数”协议字段；当前 pendingCount 来自
  view.finance.incomingRequests.length，只用于出借人当前卡。
- 不要把 incomingRequests 展开成完整列表（隐私与手机溢出）。
- 若要改请求排序，必须先改服务端稳定顺序并在所有端一致；本轮禁止前端排序。
- 若引擎改变 request 截止语义（例如新状态），先更新 request-deadline 纯函数与
  T2/T3，再改 UI；不要在 JSX 里散落算时间/判过期。
- view.deadlineAt 仍是阶段/当前行动席截止，页头、BankDue、Danger、Betting 的
  倒计时来源不变；只允许请求卡使用 request.deadlineMs。
- 不要在过期时本地删除请求或本地收口；权威收口仍由服务端广播/推进。
