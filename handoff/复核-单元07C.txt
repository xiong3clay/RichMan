S2. collectLimitOf 遇到 collectLimits 数组里的 null/非对象元素会抛 TypeError，
    而不是规格要求的“字段缺失/非法返回 null”。

位置：apps/web/src/game/steps.ts:64-72
代码原文：
  export function collectLimitOf(view: WireSnapshotView, loanId: string): string | null {
    const limits = view.finance.collectLimits as
      | readonly { loanId: string; maxCents: string }[]
      | undefined;
    if (!Array.isArray(limits)) return null;
    const found = limits.find((entry) => entry.loanId === loanId);
    if (found === undefined || typeof found.maxCents !== "string") return null;
    return isNonNegativeCents(found.maxCents) ? found.maxCents : null;
  }

问题：
- Array.isArray 只保证外层是数组；find 回调对 entry 直接读 loanId。
- 旧快照“缺字段”会返回 null，不会崩；但字段存在且元素为 null（或非对象）时：
  实测 /tmp 探针：

- 这属于“字段非法”的输入；规格 A1.3 要求非法返回 null，UI 不能崩。

- collectLimitOf({ finance: { collectLimits: [null] } } as any, "p2p-1")；
- 或让 collectLimits: [42] 等；当前 null 直接抛错。
修复建议：
- `const found = limits.find((entry) => entry !== null && typeof entry === "object" &&
  typeof entry.loanId === "string" && entry.loanId === loanId);`
- 同步补 null/数字元素的测试；保持缺失字段 null 的旧快照回退不变。
说明：服务端正常 getPlayerView 不会发 null 元素，因此列为 should-fix，不是正常服务器路径的 must-fix。

    单个 send 异常还会中断后续 peer 的关闭。

位置：apps/server/src/ws.ts:251-260

建议：
