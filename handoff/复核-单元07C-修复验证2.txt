3. S-D 结论：“构造不出来”不成立（should-fix）
------------------------------------------------------------
3.1 修复记录/测试的声明
- apps/server/tests/destroy-room.test.ts:165-185 声称：
  “恢复码轮换后旧 socket 被 4001 关闭；不存在 OPEN 的 non-current 同房连接”，
  理由是 bind 会把旧连接 replaced/identity=null 并 close(4001)。
- bind 确实如此：apps/server/src/ws.ts:203-214
    previous.replaced=true; previous.identity=null;
    sendError(previous,"REPLACED"); previous.ws.close(4001,"REPLACED");

3.2 真实存在的路径
- 位置：apps/server/src/ws.ts:239-259（join/resume 成功后的发送与 bind）
    if (conn.closed || conn.replaced) { ... }        // 239
    const delivered = await new Promise<boolean>(... conn.ws.send(joined...) ...); // 248-250
    ...
    if (conn.closed || !delivered) {                 // 256
      await manager.transact(roomCode, () => sessions.disconnect(joined));
      return;                                        // 257
    }
    bind(conn, joined, epoch);                       // 260
- 对 resume（freshJoin=false，包括 token resume / recoveryCode resume）：
  1) manager.transact 把 session token/epoch 改成新值并提交；
  2) 新连接发送 joined，并 await send 回调；
  3) 如果新连接在 239 行检查之后、bind（260）之前/期间关闭，代码走 256 行
     sessions.disconnect(joined) 后直接 return；
  4) 256 行没有 detach(previous)，bind 也没有执行，所以旧连接：
       - 仍保留旧 identity（含旧 tokenDigest/epoch）
       - ws.readyState 仍可能是 OPEN（close 事件尚未完成/没有主动 close）
       - sessions.isCurrent 为 false（记录已是新 token/epoch，旧 tokenDigest 不匹配）
     即正是“identity 仍在 + OPEN + current=false”的同房连接。
- 这不是只在 mock 中成立；它是 resume 的发送确认窗口。join 新玩家（freshJoin）
  走 delivery/discardUndelivered，问题不同；但 resume/token resume 的上述分支存在。
- 若新连接在 239 行之前就关闭，分支会走 previous 处理并 detach（旧 identity null）；
  但 239 行之后的关闭没有被覆盖。

3.3 新测试覆盖不足
- “S-D 真实 ws.destroy_room：同房三条连接全部收到通知并 4002”
  destroy-room.test.ts:151-163：三条都是 current；没有 non-current。
- “S-D 恢复码轮换后旧 socket 被 4001 关闭”
  :165-185：fresh 连接保持打开并完成 bind，所以旧 socket 被 4001；
  它没有让 fresh 在 bind 前关闭，因此没有覆盖上面 256 行路径。
- 结果：S5 的 selectDestroyPeers 实现仍能选中该旧连接（identity.roomCode + OPEN），
  代码功能上会向它发 room_destroyed/4002；但“真实链路不存在”的声明是错的，
  该场景也没有测试。
- 建议（should-fix）：
  * 把 resume/token resume 后 bind 前关闭新连接做成真实测试；确认旧 socket
    在 host destroy 时收到 room_destroyed/4002，或修正代码在 256 分支 detach previous
    （更干净）。
  * 更新 S-D 说明：不是“不存在”，而是“存在一个 bind 前关闭窗口；当前由
    selectDestroyPeers 的 OPEN+identity 选择兜底”。
- 因 S5 实现已按“所有 OPEN + 同房 identity”选择，代码层面仍可提交；
