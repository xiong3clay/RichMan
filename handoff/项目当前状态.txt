【09A 不得回退的点】
- 默认阈值唯一来源是 apps/server/src/security.ts 的 DEFAULT_SECURITY_LIMITS（200/20/60/50/
  60s/60/20/10/10/5/10/10/10/20/5/10/30），不得复制进 rules.ts 或前端；改阈值必须同步测试。
- HTTP POST /api/rooms 判定顺序 Origin 403 → Content-Type 415 → 建房桶 429 → 房间上限 503 → 创建；
  API 命名空间必须用 decodedPath 路由且只接受原样路径：未知 /api/*、/api、%2F 等编码路径
  一律 JSON 404，不得回退 index.html（Qoder M1；测试 48）。
- WS upgrade 必须先 Origin 403 再 guard.admit 503，两者都不升级。
- guard.admit 之后必须有唯一归属：握手未完成时由 socket.once("close") 回收，
  handleUpgrade 成功回调认领（置 released、移除 close 监听）后交给 Connection；
  onUpgrade catch 用 releaseIfUnclaimed；403/503 不得新增释放。
  任何终止路径（含缺 Sec-WebSocket-Key 的 400）结束后 guard 必须归零
  （Qoder M3；测试 49）。
- 未认证超时独立 authClock（5s、unref、close 清理），不与 10s 心跳合并；
  超时先 sendError(INVALID_MESSAGE,"连接超时，请重新加入") 再 close(4003,"AUTH_TIMEOUT")。
- 命令限流必须在 processor 之前：全局桶 key=房间码|playerId（20/10s），
  经济桶 key=房间码|playerId|type（10/5s）；ECONOMIC_COMMANDS 九条不得增删；
  超限不得执行、不得 bump version。
- join 按 IP、resume 按 IP + 按房间，均在 manager.transact 之前；失败重试也计数。
- 满房 join 必须走 fullJoinBucket：前 joinBurst 次仍 ROOM_FULL，之后 RATE_LIMITED；
  rooms.test 第 11 人契约不得破（Qoder S2；测试 40）。
- ConnectionGuard release(ip, authenticated) 必须传真实 conn.authenticated 且幂等、
  不跨维度回退；bind 只 markAuthenticated 一次；init 必须把 Connection 创建（含 now）
  包进 try，conn 为 null 时 release(ip,false)，非 null 按 conn.authenticated 只释放一次；
  HTTP 与 WS 必须共享 startServer 创建的同一 SecurityRuntime（Qoder M2；测试 39）。
- TokenBucket 必须保留 tryTake 的惰性 prune：size>=1024 时清 10 分钟未用 key；
  不得退回只增不减（Qoder S1；测试 38）。
- 所有 JSON 与静态响应必须带 nosniff / no-referrer / X-Frame-Options DENY；新响应走
  sendJson/withSecurityHeaders，不要裸 res.writeHead。
- NicknameSchema 禁止 C0 与 DEL，文案固定"昵称不能包含控制字符"，码点 1～20；其余 schema/协议不变。
- Content-Type 只接受 application/json（空 body 按 {}）；NODE_ENV 不影响 allowedOrigins。
- 限流是单进程内存态、重启清零；trustProxy 默认关，直连公网开启会被伪造 XFF 绕过。

【06 不得回退的点】
- 提交顺序：tmp + fsync → 备份旧 snapshot 到 snapshot.bak.json → rename 才算出账；rename 成功后才发布内存/广播/回成功。
- 失败一律回滚旧内存 + paused=true + ERROR_PAUSED；rename 后失败要把已提交快照记入 durablePending，后续写入先对齐，禁止旧内存覆盖已提交账。
- 当前局命令结果（key [gameId,playerId,commandId]，payloadHash + 原 reply）必须与状态同一次 rename；WS 生产路径必须 atomicCommit:true。
- 存档只存 tokenDigest/recoveryDigest，禁止 token/sessionToken/recoveryCode 原文；快照是私有账务，不能整包下发或静态公开。
- 恢复后一律 paused、online=false、scheduler 不 arm；只有房主 resume_game 才换 phaseInstanceId 并重算当前窗口，不追旧 deadline、不补计息/税/开奖。
- TAX/INTEREST 这类 deadlineAt 为 null 的恢复态由 scheduler 立刻 wake 一次推进，不要因此把自动阶段改成需要玩家点击。
- 主快照坏用 bak，且先保留坏 current 再修复；不可恢复的目录移入 rooms/corrupt-* 并告警，绝不静默新建空局。
- 大厅/身份/epoch 也要走 manager.transact 与房间串行队列；await 期间不得提前暴露候选 token/epoch/座位。
- 5000 条上限按最旧淘汰、rematch 清旧局；审计 events.ndjson 只审计不重放。
- 身份 current 必须同时核 tokenDigest 与 epoch：session.ts isCurrent 的 tokenDigest 比较不能删；ws.ts reconcileOwners 不得再把旧 owner 的 epoch 升到权威记录的值。恢复码轮换后旧 socket 必须失效。
- 新 join 持久化时带 pendingDelivery=true，joined 送达并确认后才转 false；未交付的座位/会话在断线、durablePending 对齐、启动载入时一律撤销，房主被撤销要按最低座位重选，不能留无 token 房主。
- atomicCommit=true 时 version 未变化的拒绝/冲突不缓存、不进快照、不占 5000 容量；只有提交成功的结果才落盘（command-queue.ts 的提前 return 不能删）。
- GAME_OVER 恢复必须沿用原 lastEvents（含 BET_SETTLED.drawResult），不 bump version/eventSeq、不重开奖。
- rename 成功后任何异常（临时文件清理失败、publish/emit 失败）不得回滚已提交状态；transact 必须区分"存储失败"与"发布失败"。
- validateSnapshot 的 S2 清单（lenderId/时限有限数/座位与 pending 引用/roomState-game-host 一致性/摘要唯一/commands≤5000/lastEvents 结构）不得删减；pendingDelivery 只允许出现在 LOBBY。
