三、手工验收（真实服务 + curl.exe）
说明：服务用 `corepack pnpm -s start` 后台启动；以下命令在另一个终端执行。
Windows PowerShell 中必须用 curl.exe（curl 是 Invoke-WebRequest 别名）。

1) /health 安全响应头
   命令：
     curl.exe -s -i http://127.0.0.1:8000/health
   实际输出（节选）：
     HTTP/1.1 200 OK
     x-content-type-options: nosniff
     referrer-policy: no-referrer
     x-frame-options: DENY
     content-type: application/json; charset=utf-8
     {"ok":true,...,"rooms":0,...}
   预期：200 且三安全头齐全。PASS。

2) 跨站 Origin 建房被拒
   命令：
     curl.exe -s -i -X POST http://127.0.0.1:8000/api/rooms ^
       -H "Origin: https://evil.example" -H "Content-Type: application/json" --data "{}"
   实际输出（节选）：
     HTTP/1.1 403 Forbidden
     x-content-type-options: nosniff
     referrer-policy: no-referrer
     x-frame-options: DENY
     {"ok":false,"error":"ORIGIN_NOT_ALLOWED"}
   预期：403 ORIGIN_NOT_ALLOWED。PASS。

3) 未知 /api 路径
   命令：
     curl.exe -s -i http://127.0.0.1:8000/api/unknown
   实际输出（节选）：
     HTTP/1.1 404 Not Found
     content-type: application/json; charset=utf-8
     {"ok":false,"error":"NOT_FOUND"}
   预期：404 JSON，不是 index.html。PASS。

4) 同源建房（对照）
   命令：
     curl.exe -s -i -X POST http://127.0.0.1:8000/api/rooms ^
       -H "Origin: http://127.0.0.1:8000" -H "Content-Type: application/json" --data "{}"
   实际输出（节选）：
     HTTP/1.1 201 Created
     {"ok":true,"roomCode":"7375"}
   预期：201 并返回 4 位房间码。PASS。
   注：验收产生的空房间 7375 已从 apps/server/data/rooms 删除，避免污染运行态。

5) 非 JSON Content-Type
   命令：
     curl.exe -s -i -X POST http://127.0.0.1:8000/api/rooms ^
       -H "Origin: http://127.0.0.1:8000" -H "Content-Type: text/plain" --data "nickname=x"
   实际输出（节选）：
     HTTP/1.1 415 Unsupported Media Type
     {"ok":false,"error":"UNSUPPORTED_MEDIA_TYPE"}
   预期：415。PASS。

6) 复核修复 F3：text/plain + body "{}" 必须 415（旧兼容旁路已删除）
   命令：
     curl.exe -s -i -X POST http://127.0.0.1:8000/api/rooms ^
       -H "Origin: http://127.0.0.1:8000" -H "Content-Type: text/plain" --data "{}"
   实际输出（节选）：
     HTTP/1.1 415 Unsupported Media Type
     x-content-type-options: nosniff
     referrer-policy: no-referrer
     x-frame-options: DENY
     {"ok":false,"error":"UNSUPPORTED_MEDIA_TYPE"}
   对照（application/json + "{}"）实际输出：
     HTTP/1.1 201 Created
     {"ok":true,"roomCode":"8737"}
   预期：text/plain 415、application/json 201。PASS。

7) 第二轮 F6：编码 API 路径必须 404 JSON，不得回退 index.html
   命令（逐条执行，curl.exe 会原样发送 %2F）：
     curl.exe -s -i http://127.0.0.1:8000/api%2Funknown
     curl.exe -s -i http://127.0.0.1:8000/api%2Frooms
     curl.exe -s -i http://127.0.0.1:8000/api%2funknown
     curl.exe -s -i http://127.0.0.1:8000/api
   实际输出（四条均相同的关键行）：
     HTTP/1.1 404 Not Found
     x-content-type-options: nosniff
     referrer-policy: no-referrer
     x-frame-options: DENY
     content-type: application/json; charset=utf-8
     {"ok":false,"error":"NOT_FOUND"}
   预期：404 JSON，不是 200 text/html。PASS。
   说明：修复前 /api%2Frooms 返回 200 text/html（index.html SPA 回退），
   不是 200 JSON；现 API 命名空间只接受 url.pathname===decodedPath 的原样路径。

8) 第二轮 F7/F9：init 抛错归零、满房连续 join 限流（tsx 探针）
   说明：用临时脚本 %TEMP%\09Afix2-probe.mts，从 security-harness 起真实服务。
   F7：注入 now 第一次抛错后打开 /ws：
     initThrow guard stats = {"total":0,"unauthenticated":0,"perIp":{}}
     再正常加入：
     after normal join stats = {"total":1,"unauthenticated":0,"perIp":{"127.0.0.1":1}}
   F9：joinBurst=10、joinPerMinute=0，10 人填满房间后第 11 个连接连续 join：
     fullJoin codes = ["ROOM_FULL" ×10, "RATE_LIMITED"]
   预期：抛错不泄漏配额；满房先 ROOM_FULL、超出后 RATE_LIMITED。PASS。
   日志：artifacts/test-logs/09Afix2-manual-wsprobe.log

9) 第三轮 F13：无效握手配额回收（tsx 探针，真实 TCP + 真实服务）

五、建房到开局步骤（人工复验用）
1) 打开 http://localhost:8000/（同源页面）。
2) POST /api/rooms（页面按钮）得到 4 位房间码；跨站页面调用会 403。
3) 手机/第二浏览器打开同地址，输入房间码 + 昵称加入；
   昵称含换行/NUL 会收到 INVALID_NICKNAME（服务端昵称校验）。
4) 全员准备 → 房主开始；对局中连续超频点击会收到 RATE_LIMITED，
   状态与 gameVersion 不变。
5) 断线后用房间码 + 恢复码恢复；同一 IP 1 分钟内超过 10 次 resume
   会收到 RATE_LIMITED（默认阈值）。
