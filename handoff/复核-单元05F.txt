S4. withinLimit 对非规范数字字符串会误判为“超限”，与函数自己的注释不一致。

位置：apps/web/src/game/steps.ts:49-56
代码原文：
  /** 整数分字符串比较；空值或非法输入交给原有表单校验，不在这里判超限。 */
  export function withinLimit(value: string, limit: string | null): boolean {
    if (limit === null) return true;
    const parsed = Number(value);
    const max = Number(limit);
    if (!Number.isSafeInteger(parsed) || !Number.isSafeInteger(max)) return true;
    return parsed <= max;
  }

Number 会接受 "1e4"（10000）、"0x1389"（5001）、"+5001"（5001）、"5001.0"（5001）
这类非 isCanonicalCents 字符串。若上限为 5000，输入 "1e4" 会命中
parsed > max，按钮被禁用并显示“最多可借 5,000 分”，而不是让原有表单校验提示
“必须是整数分”。这与注释宣称的“非法输入交给原有表单校验”不一致，属于轻量误伤。
建议先做规范字符串判断：
  if (!/^(0|[1-9]\d*)$/.test(value)) return true;
再转 Number；或复用 isNonNegativeCents（注意它还会检查 <= MAX）。
补 steps.test.ts 用例："1e4"、"+5001"、"0x1389" 均不应判超限（交给表单报错）。
低优先级，不影响资金正确性。

  a/b/c 任一不成立时普通贷款必被拒，快照给 0 是正确的（包含 cents=1 的 cap=0）。

- 唯一分歧是引擎入账 MAX 上限，见 M1。

B. lenderLimits 覆盖 acceptLoanRequest 的两类金额失败
- 公式：views.ts:112-117
    Math.max(0, Math.min(player.cents, MAX_MONEY_CENTS - me.cents))
- 出借人余额不足：private-loans.ts:266-273 在 lenderCents < principal 时 FAILED；
  cap <= 对方 cents，因此上限以内的请求不会因出借人余额失败。
- 借款人超上限：private-loans.ts:275-279 在 borrower + principal > MAX 时抛
  INVALID_AMOUNT；cap <= MAX - 本人金币，因此上限以内不会触发。
- 自己/已破产：过滤条件 player.alive && playerId !== viewerId（views.ts:113），
  与 acceptLoanRequest 的 PARTY_NOT_ALIVE 一致；set 中不会出现自己。
- 负余额出借人：Math.max(0, ...) 归 0；引擎不允许负余额出借人（lender 侧
  assertBalanceCents 非负），0 是安全下限。
- 时间/轮次/待处理请求/2 秒间隔（private-loans.ts:238-257、engine.ts 的
  rescueRequestMinGapSec、同一借款人一个 PENDING）不是“金额上限”能表达的，
  由阶段与命令层处理；lenderLimits 没有对它们作出数值承诺，不构成错误。
- 注意：快照生成后出借人余额可能变化，接受请求仍可能失败（快照过期），
  这是服务端权威裁决的固有情况，不算本单元缺陷。
