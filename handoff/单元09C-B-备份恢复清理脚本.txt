F0-1（S1）CleanupResult 可见失败
- backup.ts 的 CleanupResult 增加：
    failed: { group: 'tmp' | 'logs' | 'backups' | 'corrupt'; path: string; message: string }[]
  （现有 tmpFilesRemoved/logsRemoved/backupsRemoved/corruptRemoved 保持不变）
- 四类删除的 catch（约 backup.ts:641-646、659-665、686-690、713-721）逐项 push 到 failed，
  不得再静默吞掉；单项失败不影响其余项清理，也不上抛。
- cleanupData 增加测试钩子（只供测试注入，生产默认走真实文件系统）：
    export interface CleanupHooks { removePath?: (target: string, options: { recursive: boolean }) => Promise<void>; }
    cleanupData(options & { hooks?: CleanupHooks })
  默认实现调用 fs.rm(target, { recursive, force: true })。除删除动作外，判定集合的逻辑不得变。
- F0-1 测试：T20 cleanup_reports_failed_removals
  用 hooks.removePath 对其中一个 logs/server-*.log 抛 EACCES，断言：
  (a) 其余可删项仍被删除；(b) failed 长度 1 且 group='logs'、path 指向该文件、
  message 含 EACCES；(c) 不抛异常。

F0-2（S2）写入后复校验/回滚的自动化回归
- restoreRoom 的 options 增加测试钩子：
    hooks?: { afterWrite?: () => void | Promise<void> }   // 在“复校验之前”调用
  生产代码不传；不得因钩子存在而跳过任何校验。
- 回滚失败时 BackupError.details 增加 rollbackError（字符串）与 keptPath（字符串），
  与 message 内容一致（S6）。
- T18 restore_post_write_failure_rolls_back_original：
  目标目录已存在 + force=false 不适用于本测试；做法：先放一个旧房间目录，调用
  restoreRoom({force:true, hooks:{afterWrite(){ throw new Error('INJECTED_AFTER_WRITE'); }}})
  断言抛 RESTORE_VERIFY_FAILED、目标目录已恢复为旧档（读旧 snapshot 的关键字段相等）、
  不残留新的半成品目录、rooms 下无多余的 restore-keep-*（旧档已 rename 回去）。
- T19 restore_rollback_failure_details：
  用 hooks 让 afterWrite 抛错，并让回滚（rename 回原位置）失败——可通过把 keptPath
  的父目录权限/占用制造，或在 restoreRoom 内部再开一个可注入 seam（如 hooks.rollback）。
  断言错误 details 同时含 rollbackError 与 keptPath，且 message 提示“回滚旧档失败”。
  若某一平台无法稳定制造回滚失败，允许用 hooks.rollback 注入，但必须在交接里写明
  “仅为测试 seam，不改变生产路径”。

二、scripts/backup.ps1
参数（全部 [CmdletBinding()]）：
  [string]$DataDir = ''      # 不传则 Resolve-DataDir（与 09B 一致）
  [string]$Out = ''          # 不传则 <DataDir>\backups\richman-backup-<yyyyMMdd-HHmmss>
  [int]$Keep = 0             # >0 时传给 CLI create --keep
  [switch]$WithAudit
  [switch]$Json
行为：
1. . (Join-Path $PSScriptRoot 'richman-common.ps1')；$dataPath = Resolve-DataDir $DataDir。
2. 数据目录不存在 → 输出 JSON/文本错误 code=DATA_DIR_MISSING，exit 1。
3. $Out 省略时生成全新时间戳目录；不允许复用已存在的空目录（09C-A nit）。
   显式 -Out 且已存在 → 交给 CLI，返回 BACKUP_OUT_EXISTS 时 exit 2。
4. 调 CLI：
   node --import tsx apps/server/src/storage/backup-cli.ts create --data <dataPath> --out <out> [--with-audit] [--keep n]
   用 & node ... 2>错误捕获；把 stdout 最后一行 JSON 解析；非 0 退出时按 JSON code 映射退出码
   （2 = BACKUP_OUT_EXISTS；其余 1），仍然只打印一行 JSON（-Json 时）。
5. 成功非 -Json 输出人话：备份目录、房间数、跳过数、保留（pruned）；-Json 输出单行
   {"ok":true,"script":"backup","out":"...","rooms":n,"skipped":n,"pruned":n}。
6. 失败 -Json 输出 {"ok":false,"script":"backup","code":"...","message":"..."}，退出码按上。
7. -Keep 传 0 表示不 prune；负数 → BAD_ARGUMENT exit 1。

三、scripts/restore.ps1（本单元的安全重点）
参数：
  [string]$DataDir = ''
  [string]$Backup = ''        # 必填（--backup 目录）
  [string[]]$Room = @()       # 房间码，可重复传
  [switch]$All                # 恢复 manifest 里全部房间
  [switch]$Force
  [int]$Port = 0              # 0 = 从 run/server.json 的 port 取值，取不到用 8000
  [switch]$Json
行为：
1. 参数校验：Backup 为空或目录不存在 → code=BAD_ARGUMENT exit 1；
   -All 与 -Room 同时给 → BAD_ARGUMENT；两者都不给 → BAD_ARGUMENT。
2. 服务运行检查（必须先于任何磁盘写）：
   - 读 <dataPath>/run/server.json，用 Get-RunStateProcess $state 'server'；
   - 若 status='running' 或该端口 /health 返回 ok=true 且 service='richman'
     → 输出 code=SERVICE_RUNNING（message 明确“请先运行 scripts/stop.ps1 并确认
     服务已退出”），exit 2，一个字节都不写。
   - status 为 mismatch/unknown/broken 时：若 /health 不通，允许继续但打印 WARN。
3. 先校验：node --import tsx ...backup-cli.ts verify --backup <Backup>；
   ok=false → code=VERIFY_FAILED exit 1，并把 problems 前 5 条带进输出。
4. -All 时从 <Backup>/manifest.json 读 rooms[].code（backupFormatVersion 必须为 1，
   否则 MANIFEST_INVALID exit 1）；按 code 升序逐个恢复。
5. 逐个执行：
   node --import tsx ...backup-cli.ts restore --data <dataPath> --backup <Backup> --room <code> [--force]
   目标已存在且无 -Force → RESTORE_TARGET_EXISTS exit 2，并提示 -Force 会保留旧档；
   其余失败 exit 1。逐个失败即停，输出已完成列表。
6. 成功输出（-Json 单行）：
   {"ok":true,"script":"restore","restored":[{"code":"0042","keptPath":null}],"pausedHint":true}
   pausedHint=true 固定表示“恢复后房间会以暂停态载入，需房主在界面点继续”。
7. 恢复完成打印下一步提示：先 start-lan.ps1，再进房间点“继续游戏”。

四、scripts/cleanup.ps1
参数：
  [string]$DataDir = ''
  [int]$KeepLogs = 20
  [int]$KeepBackups = 10
  [int]$KeepCorrupt = 5
  [int]$TmpHours = 24
  [switch]$DryRun
  [switch]$Json
行为：
1. 调 CLI cleanup --data ... --keep-logs n --keep-backups n --keep-corrupt n --tmp-hours n [--dry-run]。
2. JSON 解析后输出：removed 四类路径数量、failed 列表、wouldRemove 计数。
3. failed 非空 → 非 -Json 打印“警告：N 项删除失败”并列出前 5 条；退出码 1。
   failed 为空 → exit 0。参数非法（负数/小数）→ BAD_ARGUMENT exit 1。
4. -Json 单行：{"ok":true|false,"script":"cleanup","dryRun":bool,"removed":{...},
   "wouldRemove":{...},"failed":[{group,path,message}]}
5. 绝不允许脚本自己 rm -Recurse rooms/<code>；只经 CLI/核心库。
