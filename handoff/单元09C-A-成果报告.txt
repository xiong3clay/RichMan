三、备份目录格式（实现值）
<outDir>/
  manifest.json
  rooms/<code>/snapshot.json
  rooms/<code>/events.ndjson   （仅 withAudit 且源文件存在时）
manifest.json 字段：
  backupFormatVersion=1
  createdAt=now.toISOString()
  sourceRoot=path.resolve(root)
  roomCount=rooms.length
  rooms[]：code/savedAt(string)/gameId/paused/eventSeq/
           snapshotSha256/snapshotBytes/audit(null 或
           {file:'events.ndjson',bytes,sha256})
  skipped[]：{code, reason(前 200 字符)}
rooms 按 code 升序，skipped 按 code 升序；manifest 使用 2 空格缩进 + 末尾换行。
注意：现有 snapshot.savedAt 是 number，规格的 BackupRoomEntry.savedAt 是 string，
实现按规格写 String(snapshot.savedAt)，未改存档内容。

五、CLI
命令：
  create  --data <数据目录> --out <备份目录> [--with-audit] [--keep <n>]
  verify  --backup <备份目录>
  restore --data <数据目录> --backup <备份目录> --room <code> [--force]
  list    --dir <备份根目录>
  cleanup --data <数据目录> [--keep-logs n] [--keep-backups n]
          [--keep-corrupt n] [--tmp-hours n] [--dry-run]
stdout 恰好一行 JSON；进度/警告只走 stderr。
成功：{"ok":true,"command":"create","rooms":2,"out":"...","pruned":0}
失败：{"ok":false,"command":"restore","code":"RESTORE_TARGET_EXISTS",
      "message":"..."}；BackupError.details 存在时附 details。
退出码：0 成功；1 运行失败/参数错误（code=BAD_ARGUMENT）/VERIFY_FAILED；
        2 RESTORE_TARGET_EXISTS、BACKUP_OUT_EXISTS。
create --keep 成功后对 out 的父目录执行 pruneBackups。

九、已知边界
- Windows fsync 只保证文件内容落盘，目录项 rename 的持久性依赖文件系统；
  突然断电仍可能丢最后一次改名。
- 备份只含 snapshot.json 与可选 events.ndjson；身份摘要（tokenDigest/
  recoveryDigest）会随快照进入备份，备份目录不得公开或外传。
- 恢复不改 snapshot 内容；paused/online 仍由 loadAll 统一置位。
- 规格中的 BACKUP_FILE_INVALID/BACKUP_HASH_MISMATCH 已导出但 verifyBackup
  通过 problems 文本而不是抛这两个码（CLI 将 verify 失败映射为 VERIFY_FAILED）。
- cleanup --dry-run 按“removed 列表为空但计数保留”实现：数组为空，
  tmpFilesRemoved 为将删除数量；日志/备份/损坏目录只保留不删。
- force 保留目录名固定 restore-keep-<yyyyMMdd-HHmmss>-<code>（UTC）；
  同一秒重复 force 遇到同名保留目录会报 RESTORE_VERIFY_FAILED，不覆盖旧档。
