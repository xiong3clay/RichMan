12B 注意事项（2026-11-09）

一、Windows 路径含空格的坑（已修，必须保留）
- Start-Process -ArgumentList 不会自动给数组里的含空格路径加引号；发布包在
  “richman 12b 中文 空格”目录曾启动失败，报 Cannot find module '...\richman'。
- 修复：start-lan 发布模式把 serverEntry 包成 `"<abs path>"` 再传给 Start-Process；
  开发模式参数不变。以后新增任何 Start-Process 传文件路径，都要显式加引号。
- 用 Start-Process -Wait 跑 start-lan 会等待整棵进程树→挂起；用 -PassThru + WaitForExit。
  包内手工演练用单字符串 ArgumentList 调 powershell，避免数组拆路径。

二、PowerShell 5.1 原生参数引号
- 把多行 JS 用 `node -e $code` 传时，PS5.1 会剥掉内嵌双引号，导致
  `require.resolve(moduleName + /package.json)` 语法错。
- 修复：build-release 把 licenses 解析代码写到临时 .mjs 文件再 `node <file>`；
  不要在 PowerShell 里拼复杂 JS 作为 -e 参数。
- fetch 的 ZipArchiveEntry 没有 ExtractToFile 方法，仍用 Open()+CopyTo。

三、哈希与排序口径
- SHA256SUMS 必须是“64 位大写 hash + 两个空格 + 相对路径”，路径用 /。
- 排序必须是 UTF-16 序：构建用 .NET Ordinal，release-lib 用 JS 默认 sort()；
  不要一边 Ordinal 一边 localeCompare，否则合法包会被 verify 判“未排序”。
- SHA256SUMS 只覆盖目录内文件，不覆盖自身；zip 自身 hash 单独写
  release/SHA256SUMS.txt（一行 zip 名+hash）。
- builtAtUtc 每次构建不同 → zip hash 每次不同是预期；文件集合与 server.mjs 应稳定。
  发布时以最后一次构建的 zip hash 为准，并同步 release/SHA256SUMS.txt。

四、构建脚本行为
- stdout 必须只有最后那一行 JSON；所有进度/子命令输出走 stderr（Log 用 Console.Error）。
  Run-Native 会捕获并转 stderr；不要在构建脚本里随手 Write-Output。
- 只清 release/<name>/ 与 release/<name>.zip，不能递归清 release 根。
- 复制 scripts 时只复制包内 8 个 ps1，不要把 fetch/bundle/verify/test 脚本带进包。
- 包内 .bat 必须 ASCII 文件名、CRLF、chcp 65001、cd /d "%~dp0"、pause。
- build-release 的 verify 必须真实启动 server.mjs；不能为了快只查文件。
- verify 的 secret_scan 覆盖全部非二进制且 ≤2MB 的文件（含无扩展名 LICENSE 与
  licenses/**/LICENSE），跳过 .exe/.mp3/.wav 等二进制、>2MB 与含 NUL 的文件；
  正则同时覆盖 sessionToken/recoveryCode/token 的 JSON、key=value 与 plain 形态，
  并对 staging 与 zip 解压目录双向扫描（12B 第二轮复核后口径）。
  文档里出现“token”单词不算，但不能因此把真实凭据写进包。
- 12B 已把 start-lan 发布路径引号修复纳入包；若回退该行，含空格目录再次启动失败。
