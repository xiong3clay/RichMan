一、M2（must-fix）paused 时旧确认卡仍能发送经济命令
======================================================================
现象：
- apps/web/src/GameView.tsx:1683-1691 现在把 currentConfirmation 放在 paused 之前；
- apps/web/src/GameView.tsx:342-355 的 send 只检查 status/open 与 client.hasJoined，不检查 paused；
- confirmations.ts 的 confirmationIsCurrent 只看服务端待办，不看房间暂停标志；
- 于是：先打开 bankRepay/giveUp/abandonBet/acceptLoan 任一确认卡，再收到 paused=true，
  确认卡仍显示，点确认会真的发出命令（服务端会用 ERROR_PAUSED 拒绝，但 UI 已越权发送）。

修复要求（两条都做，双保险）：
1) 渲染顺序：只有 destroyRoom 确认卡在 paused/gameOver/!canSubmit 下保留优先权；
   其他确认卡在 paused 时必须让位给“等待继续对局”暂停卡。建议形式：
   currentConfirmation !== null && !(paused && currentConfirmation.kind !== "destroyRoom")
   ? renderConfirm(...) : paused ? 暂停卡 : gameOver ? ... : !canSubmit ? ... : renderStep(...)
2) send() 增加 paused 守卫：paused 时 setNotice("房间已暂停，继续后才能提交；本次未发送") 并 return null。
   destroyRoom 走 onDestroyRoom，不经 send，因此暂停时仍能销毁（M1 的用例必须继续通过）。

必测（apps/web/tests/gameview-07c.test.ts）：
- M2-bankRepay：BANK_DUE 打开“确认还款？”后 rerender paused=true → 显示“等待继续对局”，
  不显示“确认还款”，client.decideBankDue 调用次数为 0。
- M2-giveUp（危险自救放弃）、M2-abandonBet（放弃下注）、M2-acceptLoan（同意借款请求）
  各一条：确认卡打开后 paused=true → 确认卡消失/暂停卡出现，对应 client 方法 0 次。
  可用表驱动，但每条必须真实点击并断言行为，不允许只断言“不抛错”。
- M2-destroy-paused：paused 下 destroyRoom 确认卡仍可打开、返回不发送（保留 M1 覆盖）。
- M2-send-guard：paused 下调用任一确认按钮不会发出命令且出现已暂停提示（若走 send 守卫）。
