=====================================================================

危险从哪来、放弃会怎样、最后谁赢。不改规则、不改协议、不改引擎、不改步骤机语义。

  M  apps/web/src/styles.css          —— 新块样式

  - 不改协议、不新增依赖、不 commit、不删除/跳过/放宽任何旧测试（旧 548 条必须全绿）。
  - 不显示任何其他玩家的 coins / bets / delta / nextCents（见第六节隐私）。

  - 不臆造服务端没给的数字：利息金额、他人余额、税收比例一律不算。

二、下注步骤（BETTING，本人未锁定）
=====================================================================
位置：现有「猜点 → 金额 → 杠杆 → 锁定」步骤卡内，金额输入框下方加「本轮风险」摘要块
（class 建议 .bet-risk，role="group"，aria-label="本轮下注风险"）。随输入实时更新。

必须显示（数据只来自 view.finance.cents / 本人输入）：
  R1 当前金币：formatCents(finance.cents)。
  R2 若押注 B、杠杆 L：赢 = +B×L，输 = -B×L（两行分列，赢用 good 色，输用 bad 色）。
  R3 输后结果：若 B×L ≤ 金币 → “输后余额 X”；若 B×L > 金币 → “输后归零，差额 D 转为赌博透支贷款”
     并追加一句“该贷款按银行贷款计息，到期要还本息；逾期会失信”。D = B×L − 金币。
  R4 失信（me.credit === "DEFAULTED"）时：杠杆固定 1 倍，风险块写“失信玩家只能 1 倍杠杆”；
      现有 05D/05F 的一倍限制文案不能删。
  R5 0 注：写“押 0 即放弃本轮下注，输赢都为 0”，不显示透支警告。
  R6 金额非法/超上限/非规范串时：风险块显示“金额不合法，以服务端校验为准”，不显示任何预估数字
      （复用 steps.ts 已有的 CANONICAL_CENTS / withinLimit 判定，不要另写一套正则）。
  R7 预估超过 Number.MAX_SAFE_INTEGER 或超过 MAX_MONEY_CENTS 时只显示“金额过大，以服务端结算为准”。

三、已提交等待卡（BETTING，finance.myBet !== null）
=====================================================================
在现有“等待其他玩家”卡加一块“我的本轮下注”：
  W1 押注金额、猜点（猜 0 / 猜 1）、杠杆（1 倍/2 倍）、模式（正常下注 / 已放弃 0 注）。
  W2 进度：已提交人数 / 存活人数（betsSubmitted.length / aliveCount），文案“全员提交立即开奖”。
  W3 剩余时间：用 view.serverNow 与 view.deadlineAt 算（沿用 game/clock.ts 口径），≤0 显示“等待服务端开奖”。
  W4 未开奖前不显示他人押注、不显示“还差谁”——只给人数。
  W5 若上一轮开奖结果仍在本轮结算卡里，不重复贴在该卡（见第四节，开奖只出现一次）。

四、开奖结果（本轮结算卡内）
=====================================================================
结算卡已存在（GameView.tsx 约 1504 行，deriveRoundSettlement 驱动，关闭按钮 setSettlement(null)）。
本轮只增强 settlement.ts 的推导与展示，不改弹卡时机：
  S1 新增“开奖点”：从本轮 BET_SETTLED.payload.drawResult 取 0/1，显示“开奖：0 / 开奖：1”。
  S2 本人条目已有“猜 X · L 倍 · 押 Y；赢 +Z / 输 Z；结算后余额 W”，保留并确保：
     - deltaCents 为负时显示“输 -Z”（不要出现“输 -”叠两个负号或“输 负数”）。
     - 若本人条目 overdraftCents > 0，补一行“透支贷款 D（按银行贷款计息）”，tone bad。
  S3 本人本轮未押注（BET_SETTLED 里无本人条目）时显示“本轮未押注”，同时仍显示开奖点。
  S4 事件里没有 drawResult（旧快照/事件被裁）时不显示开奖行，也不显示“未知”。
  S5 结算卡出现 GAME_OVER 时也要显示（当前 GameView.tsx:1504 的 step.kind !== "gameOver" 条件
     会吞掉最后一轮结算，需改成 GAME_OVER 时仍显示，且“继续”按钮在 GAME_OVER 时文案为“关闭”）。
  S6 同一张开奖信息只出现一次：结算卡里出现后，事件通知架不再重复一条“开奖 0”（BET_SETTLED 目前
     没进 notices，保持不进）。

五、银行到期与危险自救
=====================================================================
5.1 银行到期卡（步骤 kind === "bankDue"，GameView.tsx 约 576-600 行）
  D1 欠款：formatCents(loan.remainingCents)（本金+已计息，口径就是 remaining，不要另算）。
  D2 明细行：发放轮 loan.issuedRound / 到期轮 loan.dueRound / 当前轮 view.round / 状态。
  D3 当前金币与“还清后余额”：金币 − 欠款；若不足，显示“金币不足，只能拒绝或等待超时”。
  D4 倒计时：view.deadlineAt 与 view.serverNow（bankDue 有窗口），≤0 显示“即将按超时处理”。
  D5 后果说明（固定文案，不得改写规则）：
      “拒绝或超时 = 永久失信：不能还这笔款、不能再用银行贷款、下注只能 1 倍；仍可向私人借款（对方会看到失信风险）。”
  D6 已有“还款 / 拒绝并失信”两个按钮与二次确认不得删；本卡不新增第三种操作。
5.2 危险自救卡（步骤 kind === "danger"）
  G1 负余额现状：formatCents(finance.cents)（负数照实显示，不要取绝对值）。
  G2 原因只从事件推断：本轮/Tax/下注导致（若有 BET_SETTLED 本人 delta<0 或 TAX_CHARGED 本人），
      推断不出就写“余额为负，需要在时限内自救”，不要编原因。
  G3 可动用资源摘要：应收 receivableCents、可借银行 bankBorrowLimitCents、可向他人借（lenderLimits 非空人数）。
  G4 三条出路与后果（固定文案）：
      - 向他人借款/催收应收：成功后余额转正即解除危险；
      - 放弃自救 = 破产：金币归 0、永久退出本局、私人债务转坏账、出借人应收冻结；
      - 超时同样按破产处理。
  G5 剩余时间用 danger 截止（deadlineAt/serverNow），已有 2 秒请求间隔提示不得删。
  G6 不做“自动还款/自动借款”，一切仍由玩家点现有按钮。

七、必测（≥10 条，全部真断言文本/属性，不用快照）
=====================================================================
  1 风险块：押 1000、2 倍、金币 10000 → 显示“赢 +2000”“输 -2000”“输后余额 8000”。
  2 风险块：押 6000、2 倍、金币 10000 → 显示透支 2000（或等价明确文案）与“计息/失信”提示。
  3 风险块：押 0 → 放弃文案，无透支提示。
  4 风险块：金额 "1e4" / "0x10" / " 5001 " → 只显示“金额不合法”，不显示预估。
  5 失信玩家（credit DEFAULTED）→ 显示“只能 1 倍杠杆”，杠杆按钮禁用 2 倍。
  6 等待卡：myBet 存在 → 显示押注/猜点/杠杆/已提交 x/y/“全员提交立即开奖”。
  7 开奖：BET_SETTLED drawResult=1、本人 won=true → 结算卡出现“开奖：1”“赢 +…”；delta 为负时文案为“输 500”而不是“输 -500”。
  8 开奖：本人条目 overdraftCents>0 → 出现“透支贷款”行。
  9 开奖：BET_SETTLED 无本人条目 → “本轮未押注”+开奖点。
  10 GAME_OVER 时结算卡仍显示（step.kind === "gameOver" 不再吞卡），按钮文案为“关闭”。
  11 bankDue 卡断言欠款=remaining、到期轮、后果固定文案含“永久失信”。
  12 danger 卡断言负余额原样显示、三条后果含“破产”“冻结”、剩余时间存在。
  13 终局卡断言胜者昵称、本人金币、信用；他人金币数字不出现在 DOM。
  14 隐私断言：他人 betCents 数字（如 777777）不出现在整个页面文本。
  15 360px CSS 契约：新块 min-width:0、overflow-wrap:anywhere；.bet-risk 无固定宽度。
