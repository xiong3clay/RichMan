修 RichMan「暂停时间线/归档」的落地缺口（Qoder 复核结论：handoff/审查/Qoder-修复方案复核-20261117.txt）

背景：上一轮已按方案实现 P0-1/P1-1。DSH 实测 pnpm test 1024 全绿、typecheck exit 0、build exit 0。但实现与方案仍有 8 个缺口，本轮只修这些，不重写整体，不改既有测试断言语义。

必做（每条都要行为测试，不许只断言 mock）：
1) N1 平移时机错：apps/server/src/ws.ts:311-322 在 sessions.resume/join（327-334）之前就平移，无效 token 或交付失败也会 version+1 并清掉暂停起点。改成身份恢复成功之后、与清 pausedByNoHuman 同一个持久化事务内平移；失败整体回滚，房间保持暂停。
2) N2 平移没落盘：apps/server/src/rooms/manager.ts:368-371 markPauseShifted 只改内存；commitTransition（manager.ts:280-295）候选快照只替换 game/lastEvents/commands。重启后 noHumanSinceMs 仍是旧值 → 二次平移。要求：shift 后的 game 与「暂停起点已消费」标志写进同一个 RoomSnapshot；重启不得二次平移；旧快照缺标志按未平移处理。
3) N3 归档计时被清掉：manager.ts:737-739 shouldArchive 依赖 noHumanSinceMs，而平移后它被清成 null，「平移成功但重连失败」的房间永远不归档。拆成两套时间：归档用 pauseStartedAt（只在真人真正上线时清），平移用单独标志。
4) N5 返回值没检查：apps/server/src/rooms/command-queue.ts:79-95 有多条 return false 路径，ws.ts:316 不检查。false 时必须不 schedule、不清暂停、记警告。
5) N7 归档不可靠：apps/server/src/storage/file-store.ts:146-165 只处理 EEXIST/EPERM/ENOTEMPTY，EXDEV 直接抛 → 跨盘永远归档失败；loadAll（167-170）只读 rooms/，归档后没有恢复入口；也没有保留期/容量上限。要求：EXDEV 走 copy→临时目录→原子 rename→校验→删源；archive/ 写清单；提供 restore-from-archive（管理员 CLI 或函数）能移回 rooms/ 并通过 validateSnapshot；归档保留 30 天后清理，常量集中定义。
6) N8 删内存没防御：manager.ts:419-426 archiveRoom 不复查 canArchive，store 没有 archiveRoom 时直接删内存丢档。要求：队列内复查 canArchive；无归档能力时拒绝归档并保持房间。
7) N4 请求时间只平移了 PENDING（packages/game-core/src/engine.ts:224-227），但 2 秒自救间隔用最近一条请求的 createdAtMs（engine.ts:1001-1003）；改为平移所有请求的 createdAtMs。
8) N6 平移无溢出校验（engine.ts:221-226）：结果必须是安全整数且 Date 有效，否则抛错、房间保持暂停。

不做：P2-4 完整 LRU（FIFO 保留即可）、P2-10 强安全（保留 schema 校验，不宣称防篡改）、P2-12 人格公开。

测试要求（假时钟 + 真实队列 + 真实文件）：
- 无效 token/交付失败：不平移、version 不变、房间仍暂停；
- 成功重连只平移一次；重启后再重连不二次平移（标志随快照持久化）；
- TAX/ACTION/BETTING 离线超过原 deadline 后重连不触发超时/破产/0 注结算（已有用例保留）；
- 平移成功但重连失败 → 到归档期仍会归档；真人上线后归档计时清零；
- EXDEV 跨盘归档、restore 后能 loadAll、30 天清理、archive 失败房间仍留在内存。
