二、M1（必须）：zip 顶层带额外文件/目录时仍 PASS
现状：
  scripts/verify-release.mjs:208-213
    const top = (await readdir(extracted, { withFileTypes: true })).filter(entry => entry.isDirectory());
    if (top.length !== 1 || top[0].name !== expectedTop) throw ...
  只过滤目录，顶层若还有 extra.txt（文件）就被忽略；
  scripts/release-lib.mjs:268-310 的 comparePackageDirs 只比较 expectedDir 内部，看不到顶层多余项。
复现（Lead 已跑通，作为验收基线）：
  1) 复制 release/RichMan-v0.9.0-win-x64 到临时目录 $base/RichMan-v0.9.0-win-x64；
  2) 在 $base 下写 extra.txt；
  3) Compress-Archive -Path @($base/RichMan-v0.9.0-win-x64, $base/extra.txt) -DestinationPath $base/RichMan-v0.9.0-win-x64.zip；
  4) 写 $base/SHA256SUMS.txt（该 zip 名 + hash，UTF8 无 BOM、CRLF）；
  5) node scripts/verify-release.mjs --dir <原始 staging> --zip $base/RichMan-v0.9.0-win-x64.zip
  实际：exit 0、12 项 PASS；期望：exit 1，zip_extract 报“zip 顶层多余项：extra.txt”。

修法（必须）：
1) scripts/verify-release.mjs 的 zip_extract 里，把顶层判定改为“整个根目录有且只有一个条目，
   且它是名为 expectedTop 的目录”：
     const rootEntries = await readdir(extracted, { withFileTypes: true });
     const expectedTop = "RichMan-v" + version + "-win-x64";
     const names = rootEntries.map(entry => entry.name + (entry.isDirectory() ? "/" : ""));
     if (rootEntries.length !== 1 || !rootEntries[0].isDirectory() || rootEntries[0].name !== expectedTop) {
       throw new Error("zip 顶层只允许 " + expectedTop + "/，实际：" + names.sort().join(","));
     }
   任何额外文件、额外目录、大小写变体、多个目录都必须变红。
   该判定必须在 record("zip_extract", ...) 之前，使 problems 里能看到这条。
2) 不要改 comparePackageDirs 的语义（它比较目录内部，仍然需要）；顶层约束在 verify 层做。
3) 保持正向仍 PASS：真实 release/RichMan-v0.9.0-win-x64.zip 顶层只有 RichMan-v0.9.0-win-x64/。
