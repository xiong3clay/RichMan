三、实现分层

3.1 服务端静态目录覆盖（apps/server/src/http.ts）
main 分支改为：
  startServer({
    dataDir: process.env['RICHMAN_DATA_DIR'] ?? path.resolve(HERE, '../data'),
    staticDir: process.env['RICHMAN_STATIC_DIR'],
  })
不改 DEFAULT_STATIC_DIR、startServer 签名、/health 字段。补一条测试（可加在 apps/server/tests/http.test.ts）：
startServer({ staticDir: <临时目录含 index.html> }) 的 GET / 返回该 index，GET /missing 走 SPA 回退；
若已有等价测试则不必重复，但要在交接里写明复用哪条。

3.2 服务端与 backup-cli 打平（新增 scripts/bundle-server.mjs，Node ESM）
- 用仓库内 vite 的 JS API：build({ configFile:false, root, logLevel:'warn', resolve:{ alias }, ssr:{ noExternal:true },
  build:{ ssr:<入口>, outDir:<staging>/app/server, emptyOutDir:false, rollupOptions:{ output:{ entryFileNames } } } })
  alias 与 vite.config.ts 相同：@richman/shared → packages/shared/src/index.ts，@richman/game-core → packages/game-core/src/index.ts。
- 两个入口分别产出 server.mjs（apps/server/src/http.ts）与 backup-cli.mjs（apps/server/src/storage/backup-cli.ts）；
  第一次构建前清空 app/server，第二次 emptyOutDir:false。
- 校验产物：两个文件均存在且 >50KB；server.mjs 含 "Sec-WebSocket-Key" 或 "WebSocketServer" 证明 ws 已内联；
  不得出现 "tsx" 运行时依赖；用便携 node 直接 node app/server/server.mjs 能启动。
- 参考实测：单入口 server.mjs 约 475KB、backup-cli.mjs 约 228KB，均可在无 node_modules 目录运行。

3.3 便携 Node 获取（新增 scripts/fetch-portable-node.ps1）
参数：-Version（默认 v24.21.0）、-CacheDir（默认 <repo>/artifacts/node-cache）、-ZipPath、-Sha256、-Dest。
- 默认从 https://nodejs.org/dist/<Version>/ 下载 node-<Version>-win-x64.zip 与 SHASUMS256.txt，
  必须校验 zip 的 SHA256 与 SHASUMS 中对应行一致；缓存 zip 与 SHASUMS，重复构建不再下载。
- 允许 -ZipPath 使用本地 zip，但仍必须与同目录/缓存的 SHASUMS256.txt 或显式 -Sha256 匹配；
  不提供“跳过校验”开关。
- 解压后只复制 node.exe 与 LICENSE 到 <Dest>，写 node/VERSION；临时解压目录必须清理。
- 网络失败时输出明确指引：手动把 node-v24.21.0-win-x64.zip 和 SHASUMS256.txt 放进缓存目录后重跑。
- 当前官方 v24.21.0 win-x64 zip 的 SHA256（供离线对照）：
  158f7685b44de51f6c0df1d153526cbcd3e1bc739a8dfc607721cef75de9e541

3.4 打包脚本（新增 scripts/build-release.ps1）
流程：
1) $root=Get-RichManRoot；读 package.json 的 version；读 apps/server/src/http.ts 的 VERSION 常量，不一致立即失败。
2) corepack pnpm -s build；要求 apps/web/dist/index.html 存在且 dist/audio 至少 1 个 mp3 与 4 个 sfx wav。
3) 清空 release/<name>/ 与 release/<name>.zip（只删这两个确定路径，不递归删 release 根）。
4) node scripts/bundle-server.mjs -Out release/<name>/app/server（或等价参数）。
5) fetch-portable-node.ps1 -Dest release/<name>/node（缓存命中则不联网）。
6) 复制 app/web/dist → app/web、scripts/*.ps1 → scripts/、LICENSE/CHANGELOG/README 片段等；
   生成 VERSION、build-info.json、使用说明.txt、故障排查.txt、第三方素材许可.txt、licenses/、data/README.txt、tools/README.txt、7 个 .bat。
   build-info.json 至少含：version、protocolVersion（从 packages/shared 读或写 1）、nodeVersion、builtAtUtc、gitCommit、gitDirty。
7) 生成包内 SHA256SUMS.txt：相对路径用 /，按路径排序，格式 "<64位大写hash>  <相对路径>"。
8) Compress-Archive -Path release/<name> -DestinationPath release/<name>.zip -CompressionLevel Optimal -Force；
   计算 zip 的 SHA256，写 release/SHA256SUMS.txt（一行 zip 名+hash）。
9) 调 node scripts/verify-release.mjs --dir release/<name> --zip release/<name>.zip；失败则保留现场并 exit 1。
10) 输出 JSON 摘要到 stdout：ok、version、staging、zip、zipSha256、files、bytes；同时写 artifacts/test-logs/release-build.txt。
脚本必须可重复：同一输入两次构建允许 builtAtUtc 不同，但文件集合与 server.mjs 大小稳定；zip 内含顶层目录名。

3.5 发布模式识别（改 scripts/richman-common.ps1，追加不改旧函数）
新增 Get-RichManLayout：若 <root>/app/server/server.mjs 存在则 Portable=true，返回
  nodeExe=<root>/node/node.exe（不存在时回退 'node'，由 start-lan 报错）、serverEntry、backupCli、
  webDir=<root>/app/web、webIndex、dataDir=<root>/data；否则 Portable=false，返回现有开发路径。
Resolve-DataDir 改为优先显式 -DataDir > RICHMAN_DATA_DIR > layout.dataDir。
Get-CloudflaredPath 在开发模式原有查找顺序前追加发布包查找：<root>/tools/cloudflared.exe、<root>/cloudflared.exe。
其它函数不动。

3.6 脚本发布分支（只改下列脚本，开发分支必须保持不变）
- start-lan.ps1：用 layout；node 检查执行 layout.nodeExe --version（要求 >=22）；webDistIndex=layout.webIndex；
  发布模式启动命令 = & nodeExe app/server/server.mjs，环境 RICHMAN_STATIC_DIR=layout.webDir、RICHMAN_DATA_DIR=dataPath、
  WorkingDirectory=root；开发模式仍 node --import tsx --no-warnings apps/server/src/http.ts。
  发布模式收到 -Build 时直接报错“发布包不含源码，不能构建前端”并 exit 1。
- backup.ps1 / restore.ps1 / cleanup.ps1：发布模式调用 node backup-cli.mjs，开发模式仍 node --import tsx .../backup-cli.ts；
  参数、JSON 输出、退出码语义完全不变。
- start-tunnel.ps1：只依赖上面的 cloudflared 查找变化；发布模式提示把 cloudflared.exe 放到 tools/ 或用 RICHMAN_CLOUDFLARED。
- stop.ps1 / status.ps1：路径来自 Resolve-DataDir，逻辑不变。
- .bat 统一：@echo off、chcp 65001>nul、cd /d "%~dp0"、powershell.exe -NoProfile -ExecutionPolicy Bypass -File "%~dp0scripts\<name>.ps1" %*、
  末尾 pause（便于双击看输出；服务已 detach，不会被 pause 关掉）。.bat 使用 ASCII 文件名与 CRLF。

3.7 校验脚本（新增 scripts/verify-release.mjs）
输入 --dir、--zip。必须做真实检查，不是只看文件存在：
- 目录结构、版本一致、SHA256SUMS 覆盖所有文件且 hash 正确；
- 禁止项：node_modules、apps/server/src、packages、handoff、docs、*.ts（licenses 除外）、data/rooms、data/run、data/logs、*.log、token/recovery 明文；
- 启动 app/server/server.mjs（用包内 node.exe，端口取空闲端口，RICHMAN_STATIC_DIR/RICHMAN_DATA_DIR 指向临时目录）：
  /health version 与 VERSION 一致、GET / 200 且含 <div id="root"、GET app/web/audio 下第一个 mp3 200、
  POST /api/rooms 返回 201 与 4–8 位房间码；结束后杀子进程并确认端口释放；
- 用包内 node.exe 跑 app/server/backup-cli.mjs create --data <空临时 data> --out <临时>，期望 exit 1 且 JSON code=BACKUP_EMPTY；
  再跑 cleanup --dry-run，期望 exit 0；
- 在包目录跑 powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-lan.ps1 -CheckOnly -Port <空闲端口> -DataDir <临时 data>，
  期望 exit 0、JSON ok=true、checks.node.version 以 v24 开头、checks.webDist.ok=true（证明便携模式识别成功）；
- 用 PowerShell Expand-Archive 把 zip 解压到临时目录，核对顶层文件夹名、VERSION、server.mjs hash 与 SHA256SUMS 一致。
- 全部通过 exit 0 并写 artifacts/test-logs/release-verify.txt；任一失败 exit 1，打印可直接定位的断言名与实际值。

六、风险与边界
- Vite SSR 打平可能把动态 import 或 __dirname 类代码打坏：必须真实启动两个 mjs 验证；不得只凭构建 exit 0。
- 便携 node.exe 约 90MB，zip 约 40–60MB；压缩使用 Optimal，不用分卷。
- 杀软可能对未签名 node.exe 报警：这是已知风险，写入故障排查，不绕过。
- cloudflared 不捆绑（体积/许可/更新），只检测；公网玩法仍受临时域名限制。
- 09D 真机矩阵未执行前，版本保持 0.9.0，不得在文档/包名写 1.0.0。
