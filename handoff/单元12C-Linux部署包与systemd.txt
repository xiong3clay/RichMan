一、本轮目标
- 为 Linux x64 云服务器提供与 Windows 便携包同源的发布物：自带 Node，解压后用 install.sh 注册 systemd 服务。
- 复用 1.0.1 版本号与协议版本 1；不升版本，作为 v1.0.1 的第二个资产发布。
- 不修改引擎、协议、server/web 生产代码；只新增发布构建/校验/部署脚本与文档。

五、WSL Ubuntu 26.04 端到端实测（systemd 已开启）
环境：WSL2 Ubuntu 26.04.1 LTS，/etc/wsl.conf 有 [boot] systemd=true；全程 root。
1) 解压到 /root/richman-test/RichMan-v1.0.1-linux-x64，install.sh --check 输出 node=v24.21.0、systemd=yes。
2) sudo bash scripts/install.sh --port 18080 --force：
   创建 richman 用户 → /opt/richman → /var/lib/richman → /etc/richman/richman.env →
   /etc/systemd/system/richman.service → enable/restart → 30 秒内 /health 通过 → 打印地址与命令。
3) systemctl is-active richman=active；GET / = 200；/health:
   {"ok":true,"service":"richman","version":"1.0.1","protocolVersion":1,...}
4) POST /api/rooms → 201 {"ok":true,"roomCode":"4443"}。
5) 双 WS 真实客户端（包内 node + ws 库）：建房 → join 两人（seat 1/2）→ ready → start →
   收到同一 gameId 与 snapshot（version=1、phase=ACTION、seat=1、cents=10000）→ WS_E2E_PASS。
6) backup.sh --out /root/backup1 → {"ok":true,"command":"create","rooms":1}；
   systemctl stop → 删 /var/lib/richman/rooms/4443 → restore.sh --backup /root/backup1 --all：
   {"ok":true,"command":"restore","code":"4443"} → 自动重启服务 → /api/rooms
   返回房间 4443、paused:true；/health rooms=1。
7) uninstall.sh：应用删除，数据与 /etc/richman 保留；再 uninstall.sh --purge：数据、配置、richman 用户
   全部删除，systemctl is-enabled richman=not-found。

六、实测发现并修复的两处真 bug
- M1（systemd 沙箱崩溃）：unit 的 RestrictAddressFamilies 只允许 AF_INET/AF_INET6/AF_UNIX。
  服务打印局域网地址时 Node 调 getifaddrs，Linux 下走 netlink，被沙箱拒绝 →
  "uv_interface_addresses returned Unknown system error 97"，进程退出、systemd 每 3 秒重启、
  /health 永远不通。修复：加入 AF_NETLINK；新增测试断言完整一行。
- M2（恢复必失败）：restore.sh 调 backup-cli restore 时漏传 --backup，CLI 返回
  BAD_ARGUMENT 缺少参数 --backup，房间未恢复且服务停着。修复：ARGS 增加 --backup "$BACKUP"；
  新增测试断言完整命令行。
- 这两个 bug 都是 Windows 侧单测/静态 verify 抓不到的，必须真 Linux + systemd 才能暴露。

七、已知限制与边界
- 只在 WSL2 Ubuntu 26.04 验证，未在真实云厂商 ECS/轻量服务器、Debian 12、Rocky/Alma 实测；
  脚本按 POSIX shell + systemd 编写，非 systemd 系统（容器/OpenRC）会以 SYSTEMD_MISSING exit 3。
- 只支持 x64；ARM64 需另做 Node 与构建目标。
- 包内不带 HTTPS/域名/反向代理；直接 http://公网IP:8000 可用但明文，绑域名走 HTTPS 需备案或反代。
- 云安全组/防火墙需自行放行端口；install.sh 只打印 ufw/firewalld 示例，不自动改防火墙。
- 恢复必须停服；restore.sh 会短暂停服，恢复后房间为暂停态，需房主点“继续游戏”。
- backup 含身份摘要与私有账务，不得公开；/var/lib/richman 权限归 richman，不要给 web 暴露。
- 首次构建需联网下载 Linux Node；离线可把 tar.xz 放入 artifacts/node-cache 并保证 SHASUMS256.txt 存在。
- 构建脚本在 Windows 上用系统 tar.exe 抽 node；该 tar 来自 Windows 10+。若在 Linux 上构建，可直接用系统 tar。
- 版本仍为 1.0.1，协议 1；本轮不涉及规则/协议/存档格式变化。
