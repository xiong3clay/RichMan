八、已知问题 / 风险
1) 限流全部是单进程内存态，重启清零；多进程/多实例部署需外部存储（09C 记录）。
2) TokenBucket 为惰性 prune：size 达到 1024 时才清 10 分钟未用的 key；
   “瞬时 1025”是推演值，测试 38 只直接断言清理后的 size，未断言 1025。
   活跃 key 若长期超过 1024，Map 仍可增长（Qoder N4），09C 可评估周期兜底。
3) 未认证超时扫描粒度 5s，实际关闭时间在 60-65s 之间。
4) Origin 只防浏览器跨站，不是身份认证；无 Origin 的非浏览器客户端仍放行。
5) trustProxy 默认关闭；若在公网直连上开启，客户端可伪造 X-Forwarded-For 绕过
   按 IP 限流，只能部署在可信反向代理后开启。
6) 满房 join 与普通 join 使用两个桶，额度独立；满房专用桶同样受 joinBurst/
   joinPerMinute 限制，不会无限刷。
7) ConnectionGuard.release 必须传真实 authenticated；漏传或传错会让
   unauthenticated 计数漂移，最终导致整 IP 新连接 503。
8) API 命名空间只接受原样路径：任何解码后改变路径的编码形式（如 %2F）一律 404；
   非 API 的编码静态路径仍走 SPA 回退（与规格一致）。
9) 握手阶段的配额已由 socket close 回收（F13）；不要再退回“只在 handleUpgrade
   抛错时释放”的写法，否则缺 Sec-WebSocket-Key 的 400 会永久泄漏（M3）。
