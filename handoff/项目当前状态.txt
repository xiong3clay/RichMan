【06 不得回退的点】
- 提交顺序：tmp + fsync → 备份旧 snapshot 到 snapshot.bak.json → rename 才算出账；rename 成功后才发布内存/广播/回成功。
- 失败一律回滚旧内存 + paused=true + ERROR_PAUSED；rename 后失败要把已提交快照记入 durablePending，后续写入先对齐，禁止旧内存覆盖已提交账。
- 当前局命令结果（key [gameId,playerId,commandId]，payloadHash + 原 reply）必须与状态同一次 rename；WS 生产路径必须 atomicCommit:true。
- 存档只存 tokenDigest/recoveryDigest，禁止 token/sessionToken/recoveryCode 原文；快照是私有账务，不能整包下发或静态公开。
- 恢复后一律 paused、online=false、scheduler 不 arm；只有房主 resume_game 才换 phaseInstanceId 并重算当前窗口，不追旧 deadline、不补计息/税/开奖。
- TAX/INTEREST 这类 deadlineAt 为 null 的恢复态由 scheduler 立刻 wake 一次推进，不要因此把自动阶段改成需要玩家点击。
- 主快照坏用 bak，且先保留坏 current 再修复；不可恢复的目录移入 rooms/corrupt-* 并告警，绝不静默新建空局。
- 大厅/身份/epoch 也要走 manager.transact 与房间串行队列；await 期间不得提前暴露候选 token/epoch/座位。
- 5000 条上限按最旧淘汰、rematch 清旧局；审计 events.ndjson 只审计不重放。
- 身份 current 必须同时核 tokenDigest 与 epoch：session.ts isCurrent 的 tokenDigest 比较不能删；ws.ts reconcileOwners 不得再把旧 owner 的 epoch 升到权威记录的值。恢复码轮换后旧 socket 必须失效。
- 新 join 持久化时带 pendingDelivery=true，joined 送达并确认后才转 false；未交付的座位/会话在断线、durablePending 对齐、启动载入时一律撤销，房主被撤销要按最低座位重选，不能留无 token 房主。
- atomicCommit=true 时 version 未变化的拒绝/冲突不缓存、不进快照、不占 5000 容量；只有提交成功的结果才落盘（command-queue.ts 的提前 return 不能删）。
- GAME_OVER 恢复必须沿用原 lastEvents（含 BET_SETTLED.drawResult），不 bump version/eventSeq、不重开奖。
- rename 成功后任何异常（临时文件清理失败、publish/emit 失败）不得回滚已提交状态；transact 必须区分"存储失败"与"发布失败"。
- validateSnapshot 的 S2 清单（lenderId/时限有限数/座位与 pending 引用/roomState-game-host 一致性/摘要唯一/commands≤5000/lastEvents 结构）不得删减；pendingDelivery 只允许出现在 LOBBY。
