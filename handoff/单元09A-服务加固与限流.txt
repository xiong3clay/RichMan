二、配置与阈值（写进 apps/server/src/security.ts，可被测试注入）
export interface SecurityLimits {
  maxConnectionsTotal: number;        // 200
  maxConnectionsPerIp: number;        // 20
  maxUnauthenticated: number;         // 60
  maxRooms: number;                   // 50
  unauthTimeoutMs: number;            // 60_000
  wsMessagesPerSecond: number;        // 60（粗粒度，保留现状）
  commandBurst: number;               // 20
  commandPerSecond: number;           // 10
  economicBurst: number;              // 10
  economicPerSecond: number;          // 5
  createRoomBurst: number;            // 10
  createRoomPerMinute: number;        // 10
  joinBurst: number;                  // 10
  joinPerMinute: number;              // 20
  resumeBurst: number;                // 5
  resumePerMinute: number;            // 10
  resumePerRoomPerMinute: number;     // 30
  allowedOrigins: readonly string[];  // 额外允许的完整 origin
  trustProxy: boolean;                // 默认 false
}
export const DEFAULT_SECURITY_LIMITS: SecurityLimits = {...};
export function loadSecurityLimits(env: NodeJS.ProcessEnv): SecurityLimits;
环境变量（都要写进交接文档）：
- RICHMAN_ALLOWED_ORIGINS：逗号分隔，如 https://abc.trycloudflare.com
- RICHMAN_TRUST_PROXY=1：只有显式设置时才读 X-Forwarded-For 第一段作为来源 IP
- RICHMAN_MAX_CONNECTIONS / RICHMAN_MAX_CONNECTIONS_PER_IP / RICHMAN_MAX_ROOMS：
  可选正整数覆盖默认值；非法值忽略并回退默认（不得抛错导致服务起不来）
来源 IP 判定：trustProxy=false 用 socket.remoteAddress（去掉 IPv4-mapped ::ffff: 前缀，
IPv6 归一化小写）；trustProxy=true 且 X-Forwarded-For 存在时取第一个非空段。
Origin 判定：Origin 不是身份认证，只防任意网页跨站建立已认证连接。

三、纯函数/类接口（security.ts，必须可单测、时间可注入）
1) class TokenBucket {
     constructor(capacity: number, refillPerMs: number, now: () => number);
     tryTake(key: string): boolean;
     prune(idleMs: number): void;   // 清掉长时间不用的 key，防止 map 无限增长
     size(): number;
   }
   语义：每 key 初始满桶；按经过毫秒线性回填，上限 capacity；tryTake 成功扣 1。
   同一毫秒内连续调用必须正确累计；不允许用 Date.now 直接读时钟。
2) export function isAllowedOrigin(
     origin: string | undefined,
     host: string | undefined,
     extra: readonly string[],
   ): boolean;
   - origin 缺失/空串 => true（非浏览器客户端、旧测试、smoke 脚本放行）
   - origin 必须是可解析的 http/https URL，否则 false
   - 与 Host 同源（host 头小写比较，含端口）=> true
   - 与 extra 中某一项规范化后完全相同 => true
   - 其余（含 http://evil.example）=> false
   - host 缺失且 origin 存在、又不在 extra => false
3) class ConnectionGuard {
     constructor(limits: SecurityLimits, now: () => number);
     admit(ip: string): { ok: true } | { ok: false; code: 'TOO_MANY_CONNECTIONS' | 'TOO_MANY_UNAUTHENTICATED' };
     markAuthenticated(ip: string): void;
     release(ip: string): void;
     stats(): { total: number; unauthenticated: number; perIp: Record<string, number> };
   }
   判定顺序：总数 -> 单 IP -> 未认证数；admit 成功即计数 +1，失败不计数。
   release 必须幂等（重复 release 不把计数减成负数）。
4) 常量经济命令集合：
   ECONOMIC_COMMANDS = BORROW_BANK, REPAY_BANK, REQUEST_PRIVATE_LOAN,
   ACCEPT_PRIVATE_LOAN, REFUSE_PRIVATE_LOAN, CANCEL_PRIVATE_LOAN,
   REPAY_PRIVATE, COLLECT_PRIVATE, SUBMIT_BET
   （BANK_DUE_DECISION、RESCUE_GIVE_UP、END_ACTION 不算经济命令，但受全局命令限流）

四、HTTP 改动（apps/server/src/http.ts）
1) 所有响应加安全头：x-content-type-options: nosniff、referrer-policy: no-referrer、
   x-frame-options: DENY。静态文件与 JSON 都要加（sendJson 与 serveStatic 统一走一个 helper）。
2) POST /api/rooms：
   - Origin 校验（isAllowedOrigin(origin, host, limits.allowedOrigins)），失败 403
     {ok:false,error:"ORIGIN_NOT_ALLOWED"}；
   - Content-Type：请求体非空且 content-type 不以 application/json 开头 => 415
     {ok:false,error:"UNSUPPORTED_MEDIA_TYPE"}；
   - 建房限流：按来源 IP 令牌桶（createRoomBurst / createRoomPerMinute），超限 429
     {ok:false,error:"RATE_LIMITED"}；
   - 房间上限：manager.roomCount() >= maxRooms => 503 {ok:false,error:"ROOM_LIMIT"}；
   - 判定顺序：Origin -> Content-Type -> 限流 -> 房间上限 -> 创建。
3) GET /api/rooms 保持只读；未知 /api/* 返回 404 {ok:false,error:"NOT_FOUND"}，
   不得回退到 index.html。
4) /health 返回字段不减少；可新增 limits 计数（可选）。
5) createRequestHandler / startServer 增加可选注入：
   security?: { limits?: SecurityLimits; guard?: ConnectionGuard; createRoomBucket?: TokenBucket;
                joinBucket?: TokenBucket; resumeBucket?: TokenBucket; resumeRoomBucket?: TokenBucket };
   测试用临时 limits 小值；缺省用 loadSecurityLimits(process.env)。
   注意：startServer 里创建的 guard/buckets 必须传给 ws 与 http 同一实例。

五、WebSocket 改动（apps/server/src/ws.ts）
1) upgrade 前（url.pathname === "/ws" 判定之后、handleUpgrade 之前）：
   - Origin 失败：直接写 HTTP/1.1 403 + Connection: close 并 socket.destroy()，不升级；
   - guard.admit(ip) 失败：HTTP/1.1 503，不升级；reason 用 code 字符串；
   - 未认证连接超时：连接满 unauthTimeoutMs 仍未 bind => sendError(conn,
     "INVALID_MESSAGE", "连接超时，请重新加入") 后 ws.close(4003, "AUTH_TIMEOUT")；
     用一个 5s 的 interval 扫描（与心跳共用方式，必须 unref 且 close 时清理）。
2) bind 成功后 guard.markAuthenticated(conn.ip)；ws close 时 guard.release(conn.ip)，
   确保幂等、异常重复 close 不重复扣减。
3) 认证玩家命令限流（在 handle 的 command.success 分支、进入 processor 之前）：
   - 全局：key = playerId，桶 capacity=commandBurst，refill=commandPerSecond/1000；
   - 经济命令：key = playerId + "|" + command.type，桶 capacity=economicBurst，
     refill=economicPerSecond/1000；
   - 任一失败 => sendError(conn,"RATE_LIMITED","操作过于频繁，请稍后重试") 并 return，
     不得执行命令、不得改状态。
   - 保留现有每连接 60 条/秒粗限流，不删除。
4) join / resume 限流（handleLobby 的 join/resume 分支、transact 之前）：
   - join：按 IP 的 joinBucket；
   - resume：按 IP 的 resumeBucket + 按房间的 resumeRoomBucket；
   - 超限 => sendError(conn,"RATE_LIMITED","尝试过于频繁，请稍后重试") 并 return。
   同一连接加入失败后重试也要计数。
5) 日志卫生：不得 console.log 原始消息、token、恢复码；错误信息只带 code。
6) 不改变已认证后的任何权限语义；Origin 通过不等于身份认证。

六、共享校验（packages/shared/src/protocol.ts）
NicknameSchema 增加：不得包含 C0 控制字符（\u0000-\u001F）与 DEL（\u007F），
错误信息“昵称不能包含控制字符”；仍按 Unicode 码点 1~20 计数。
