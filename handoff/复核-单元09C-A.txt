二、A. 一致性备份（PASS）
代码事实：
- createBackup 只读整个 snapshot.json 字节（backup.ts:290-297），先写每个房间的
  snapshot/events，再在最后写 manifest（:335-338）；manifest 用 writeFileAtomic。
- outDir 不存在时记录 outCreated=true；任何异常时只 rm 自己创建的 outDir
  （:229-244、:340-342）。outDir 已存在且非空 → BACKUP_OUT_EXISTS，不删除内容。
- roomCodes 指定时先校验全部 code/存在性（:246-265），不会先写一半再报缺房。
- 无任何房间成功 → BACKUP_EMPTY；指定码缺房 → RESTORE_ROOM_NOT_FOUND（规格如此）。
- T1/T2/T3/T4/T5 覆盖字节一致、audit、非空 outDir、空数据清理、坏房间 skip。
独立对抗：
  EMPTY_CREATE → BACKUP_EMPTY，out 不存在（false）。
  OUT_EMPTY_CREATE → rooms=1，manifest 存在（已有空目录允许）。
  OUT_NONEMPTY → BACKUP_OUT_EXISTS，keep.txt 仍为 "keep"。
  MIXED（0042 好 + 0099 坏）→ rooms=["0042"]、skipped=["0099"]。
结论：A PASS。边界 nit：outDir 是“已存在的空目录”时中途失败不会清理已写入的
部分文件；规格只要求清“本轮创建的 outDir”，当前行为与规格字面一致，但 09C-B
应提示用户不要复用已有空目录。

三、B. 校验强度（PASS）
代码事实：
- parseManifest（backup.ts:117-216）校验 backupFormatVersion=1、createdAt、
  sourceRoot、rooms/roomCount 一致性、code 正则、重复 code、snapshotSha256 格式、
  snapshotBytes/audit.bytes 非负安全整数、audit.file 固定 events.ndjson。
- verifyRoomFiles（:363-423）按 文件存在/普通文件 → 大小 → sha256 → JSON.parse
  → validateSnapshot → audit 声明则大小/sha 校验 的顺序；
  manifest 读取失败返回 manifest=null + problems，不抛。
- T6 改一字节 → sha256 problem；T7 改 cents 并同步 manifest hash → validate problem。
独立 manifest 矩阵（真实临时备份）：
  FORMAT_VERSION 2 → ok=false，“backupFormatVersion 必须为 1”
  DUPLICATE_CODE → ok=false，“manifest 中房间码重复：0042”
  ROOM_COUNT_MISMATCH → ok=false，“roomCount 与 rooms 数量不一致”
  SHA_UPPER → ok=false，snapshotSha256 非法
  BYTES_FRACTION / BYTES_NEGATIVE → ok=false，snapshotBytes 非法
  SNAPSHOT_BYTES=-1 → ok=false；SNAPSHOT_BYTES=1e9 → 大小不匹配
  AUDIT_MISSING（manifest 声明但文件删除）→ ok=false，读取 events.ndjson 失败
  AUDIT_BAD（file=other）→ ok=false，audit 字段非法
结论：B PASS。两个边界：
  (a) 空 manifest（rooms=[]、roomCount=0）当前 verifyBackup 返回 ok=true；
      规格未要求拒绝空备份，createBackup 也不会生成，故列为 nit；
  (b) parseManifest 不强制 rooms/skipped 已排序；规格格式要求排序，但校验清单
      没列排序，列为 nit。

八、G. 对抗场景汇总（真实临时目录，不碰 apps/server/data）

   1e9 → verify 大小不匹配（期望 1e9，实际 1314）。
