一、目标与不变量
1) 一致性备份：不暂停服务也能得到自洽快照——因为 snapshot.json 是 rename 替换的整文件，读到的要么是旧提交要么是新提交。禁止读一半再拼。
2) 恢复必须先校验后落地：对备份目录做完整校验（manifest、sha256、validateSnapshot），校验不通过一律不动目标目录。
3) 恢复绝不自动覆盖唯一现存档：目标房间目录已存在且没给 force 时返回 RESTORE_TARGET_EXISTS（CLI 退出码 2），目标一个字节都不改。
4) force 恢复必须先保留原档：把原房间目录 rename 到 rooms/restore-keep-<时间戳>-<code>，再写入；写入/复校验失败要回滚（把保留目录 rename 回去）。
5) 备份目录只包含：manifest.json、rooms/<code>/snapshot.json、可选 rooms/<code>/events.ndjson。不得写入 token/恢复码原文（存档里本来只有摘要，照抄即可）。
6) 所有写文件走“临时文件 + fsync + rename”，不允许直接覆盖半成品。
7) 不引入任何新依赖（只用 node:fs/promises、node:path、node:crypto、node:os、node:process）。

二、备份目录格式（精确）
<outDir>/
  manifest.json
  rooms/<code>/snapshot.json
  rooms/<code>/events.ndjson      （仅 --with-audit 时存在）

manifest.json（UTF-8、2 空格缩进、末尾换行；写成一行也行但必须可 JSON.parse）：
{
  "backupFormatVersion": 1,
  "createdAt": "2026-11-08T00:00:00.000Z",
  "sourceRoot": "<创建时传入的 root 绝对路径>",
  "roomCount": 2,
  "rooms": [
    {
      "code": "0042",
      "savedAt": "<snapshot.savedAt 原值>",
      "gameId": "<snapshot.gameId 或 null>",
      "paused": true,
      "eventSeq": 12,
      "snapshotSha256": "<sha256(snapshot.json 文件字节) 小写 hex>",
      "snapshotBytes": 12345,
      "audit": null | { "file": "events.ndjson", "bytes": 456, "sha256": "<hex>" }
    }
  ],
  "skipped": [ { "code": "0099", "reason": "存档无效：..." } ]
}
- rooms 按 code 升序；skipped 按 code 升序。
- eventSeq 取 snapshot.game?.eventSeq ?? null。
- 校验：backupFormatVersion 必须为 1；code 必须 ^\d{4,8}$ 且不重复；snapshotSha256 必须 ^[a-f0-9]{64}$；roomCount 必须等于 rooms.length。

三、backup.ts 契约（导出，全部 async）
export type BackupErrorCode =
  | 'BACKUP_OUT_EXISTS' | 'BACKUP_EMPTY' | 'BACKUP_MANIFEST_INVALID'
  | 'BACKUP_FILE_INVALID' | 'BACKUP_HASH_MISMATCH'
  | 'RESTORE_TARGET_EXISTS' | 'RESTORE_ROOM_NOT_FOUND' | 'RESTORE_VERIFY_FAILED'
  | 'PRUNE_KEEP_INVALID' | 'CLEANUP_BAD_ARGUMENT';

export class BackupError extends Error { readonly code: BackupErrorCode; readonly details?: unknown }

export interface BackupManifest { backupFormatVersion: 1; createdAt: string; sourceRoot: string; roomCount: number; rooms: BackupRoomEntry[]; skipped: { code: string; reason: string }[] }
export interface BackupRoomEntry { code: string; savedAt: string; gameId: string | null; paused: boolean; eventSeq: number | null; snapshotSha256: string; snapshotBytes: number; audit: { file: 'events.ndjson'; bytes: number; sha256: string } | null }

export async function createBackup(opts: {
  root: string;            // 数据目录（含 rooms/）
  outDir: string;          // 备份输出目录
  roomCodes?: string[];    // 省略=全部
  withAudit?: boolean;     // 是否复制 events.ndjson
  now?: Date;              // 注入时间，便于测试
}): Promise<BackupManifest>;
  - outDir 必须不存在或为空目录，否则 BACKUP_OUT_EXISTS（空目录允许，非空拒绝；不要自动删）。
  - 只处理 <root>/rooms 下 ^\d{4,8}$ 的目录；忽略 corrupt-*、restore-keep-*、.tmp 等。
  - 指定 roomCodes 时缺房间 → RESTORE_ROOM_NOT_FOUND。
  - snapshot.json 读不出来或 validateSnapshot 抛错：该房间不写入，记入 skipped（reason 带原始错误消息前 200 字符），继续其它房间。
  - 一个房间都没成功 → 删除刚创建的 outDir（如果本轮创建）并抛 BACKUP_EMPTY。
  - 每个房间：复制 snapshot 字节到 outDir/rooms/<code>/snapshot.json（先写 tmp 再 rename），算 sha256；withAudit 且 events.ndjson 存在才复制并记录 audit（不存在则 audit:null，不算失败）。
  - manifest 最后写（这样中途崩溃不会留下“看起来完整”的备份）；manifest 自身也 tmp+fsync+rename。
  - 返回 manifest。

export async function loadBackupManifest(backupDir: string): Promise<BackupManifest>;
export async function verifyBackup(backupDir: string): Promise<{ ok: boolean; manifest: BackupManifest | null; problems: string[] }>;
  - 校验顺序：manifest 可读且结构合法 → 每个 room 的文件存在/大小/sha256 → JSON.parse → validateSnapshot(snapshot, code) → audit 若声明则 sha256 匹配。
  - 任何一步失败：problems 里写清楚（房间码 + 原因），ok=false；不抛异常（CLI 用它给人类看）。manifest 读不出来时 manifest=null 且 problems 至少一条。

export async function restoreRoom(opts: {
  backupDir: string; root: string; code: string; force?: boolean; now?: Date;
}): Promise<{ code: string; keptPath: string | null }>;
  - 先 verifyBackup；不 ok → RESTORE_VERIFY_FAILED（details.problems 原样带上）。备份里没有该 code → RESTORE_ROOM_NOT_FOUND。
  - 目标 <root>/rooms/<code> 已存在且 !force → RESTORE_TARGET_EXISTS（不创建/不改任何东西）。
  - force：rename 目标到 <root>/rooms/restore-keep-<yyyyMMdd-HHmmss>-<code>，记录 keptPath。
  - 复制 snapshot（+audit 若备份里有）；复制后重新读取并 validateSnapshot，失败则：删掉刚写入的目标目录、把 keptPath rename 回原位置、抛 RESTORE_VERIFY_FAILED。
  - 不修改 snapshot 里的任何字段（paused 由服务启动时 loadAll 统一置 true，见 file-store.ts:154）；恢复出的目录不写 snapshot.bak.json（下次提交会自然生成）。
  - 不允许路径穿越：code 必须 ^\d{4,8}$。

export async function listBackups(dir: string): Promise<{ name: string; dir: string; createdAt: string; roomCount: number; ok: boolean }[]>;
  - 只列直接子目录且名字以 richman-backup- 开头；按 createdAt 倒序；manifest 坏的目录也返回（ok:false, roomCount:0）。

export async function pruneBackups(opts: { dir: string; keep: number; now?: Date }): Promise<{ removed: string[] }>;
  - keep 必须是 >=1 的整数，否则 PRUNE_KEEP_INVALID。
  - 按 createdAt 倒序保留前 keep 个，其余 rm -rf；目录不是 richman-backup-* 一律不碰；不删除 dir 本身。

export interface CleanupResult { tmpFilesRemoved: number; logsRemoved: string[]; backupsRemoved: string[]; corruptRemoved: string[]; }
export async function cleanupData(opts: {
  root: string; keepLogs?: number; keepBackups?: number; keepCorrupt?: number; tmpMaxAgeMs?: number; now?: Date;
}): Promise<CleanupResult>;
  - 默认 keepLogs=20、keepBackups=10、keepCorrupt=5、tmpMaxAgeMs=24*3600*1000。
  - 参数非法（负数/非整数）→ CLEANUP_BAD_ARGUMENT。
  - 日志：<root>/logs 下 server-*.log 与 tunnel-*.log 分别按 mtime 倒序保留 keepLogs 个，其余 unlink。
  - 备份：<root>/backups 下 richman-backup-* 用 pruneBackups 的同一套规则保留 keepBackups。
  - 损坏存档：<root>/rooms/corrupt-* 目录按名字里的时间戳降序保留 keepCorrupt 个，其余 rm -rf。
  - 临时文件：<root>/.tmp 下普通文件，mtime 早于 now - tmpMaxAgeMs 才删；不删目录、不删别的东西。
  - 任何一项失败都不要中断其它项；失败计数/错误不上抛（返回结果里能看出来）。目录不存在视为 0。

四、backup-cli.ts 契约
只被 PowerShell 脚本和验收调用，不 import 进服务端运行时。
命令（全部支持 --data/--backup/--dir 绝对路径）：
  create  --data <数据目录> --out <备份目录> [--with-audit] [--keep <n>]
  verify  --backup <备份目录>
  restore --data <数据目录> --backup <备份目录> --room <code> [--force]
  list    --dir <备份根目录>
  cleanup --data <数据目录> [--keep-logs n] [--keep-backups n] [--keep-corrupt n] [--tmp-hours n] [--dry-run]
- stdout 必须恰好一行 JSON（不打印别的；进度/警告走 stderr）：
  成功 {"ok":true,"command":"create","rooms":2,"out":"...","pruned":0}
  失败 {"ok":false,"command":"restore","code":"RESTORE_TARGET_EXISTS","message":"..."}
- 退出码：0 成功；1 运行失败（含 BACKUP_EMPTY、VERIFY 失败）；2 需要人类决定（RESTORE_TARGET_EXISTS、BACKUP_OUT_EXISTS）；参数错误 1 并在 JSON 里给 code=BAD_ARGUMENT。
- create 带 --keep n 时，成功后对该 out 的父目录执行 pruneBackups({dir: 父目录, keep:n})。
- cleanup --dry-run 只统计不删除（同一函数加 dryRun 选项，返回值里 removed 列表为空但计数保留）。
