二、S-B：resume 在 bind 前失败会留下 identity 在 + OPEN + non-current 的旧连接
----------------------------------------------------------------
现状：apps/server/src/ws.ts:239-259。resume/token resume 时 manager.transact 已把
session 换成新 token/epoch；新连接在 joined 的 send 回调失败或已关闭时：
- 239-246 分支：有 detach(previous) 但没有 close；且只 detach 不 close 仍留 TCP。
- 256-258 分支：直接 sessions.disconnect(joined) 后 return，**完全没有处理 previous**。
此时旧连接 identity 仍在、socket 可能 OPEN、sessions.isCurrent=false，正是
“同房、OPEN、non-current”的连接。destroy_room 的 selectDestroyPeers 当前能兜底，
但它不该依赖这层偶然性。

要求：
1. 抽出一个小函数（放在 ws.ts 内，导出以便单测）：
     export function shouldReleaseSupersededOwner(previousExists: boolean, previousIsCurrent: boolean): boolean {
       return previousExists && !previousIsCurrent;
     }
   并在 detach 附近新增内部函数：
     const releaseSupersededOwner = (joined: SessionIdentity): void => {
       const previous = owners.get(ownerKey(joined));
       if (!shouldReleaseSupersededOwner(previous !== undefined, previous !== undefined && current(previous))) return;
       detach(previous!);
       if (previous!.ws.readyState === 1 /* OPEN */) previous!.ws.close(4001, "REPLACED");
     };
2. 在两处失败分支调用它（顺序：先 await sessions.disconnect(joined) 成功后再 release；
   若 transact 抛错则不 release，保持现状）：
   - 239-246 的 else 分支（resume 且连接在 transact 后已关闭）
   - 256-258 的 if (conn.closed || !delivered) 分支
   注意：不要 close 当前新连接 conn（它已经关闭或由调用方关闭），只 close previous。
   不要把 4001 之外的 close code 用在别处。
3. 测试：
   a) 单测 shouldReleaseSupersededOwner 四种组合（true/true、true/false、false/true、false/false）；
   b) 修 apps/server/tests/destroy-room.test.ts:165-185 的说明文字：把
      “不存在 OPEN 的 non-current 同房连接”改为准确表述：
      “bind 正常完成时旧 socket 会被 4001 关闭；bind 前关闭的窗口由
       ws.ts 的 releaseSupersededOwner 分支 detach 并 4001 关闭，因此
       destroy 时不应再有同房 non-current OPEN 连接；selectDestroyPeers
       仍按 identity+OPEN 选择作为兜底”。断言不动。
   c) 不要写依赖毫秒级竞态的真实 WS 用例（会 flaky）；若你能用假 conn 直接
      调用导出的 helper 验证 detach+close 行为，可加一条，否则留单测即可。
4. 在 handoff/单元07C-注意事项.txt 末尾追加“S-B 边界”：说明该窗口存在过、
   现在由 releaseSupersededOwner 闭合；真实毫秒竞态未做端到端测试，
   selectDestroyPeers 仍是兜底。
