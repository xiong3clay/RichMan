单元 05C：引导式操作界面规格（V1.3.3）
依据：docs/plans/Richman分阶段联机开发方案_V1.3精简施工版.txt 第六节 3.1
现状：05A 的 GameView 把所有操作堆在一页，用户实测认为“没有游玩性”；05C 重写游戏页交互，服务器与协议不改。

============================================================
一、目标与验收
============================================================
- 任何时刻页面只问一个问题；玩家点“提交/跳过”后才出现下一个。
- 页面随阶段整块切换：行动阶段、下注阶段、等待答复、银行到期、危险自救、本轮结算、游戏结束各自有独立视图。
- 不允许“所有操作按钮常驻一页”。
- 数据只来自 snapshot；金额只做展示格式化，不本地计算余额、利息、税、赔率。
- 桌面与手机竖屏同一套顺序；主按钮触控高度 ≥ 44px。
- 现有命令通道（apps/web/src/net/client.ts + wire.ts）已支持 05A 用到的命令；05C 需要补的命令按下面第五节，字段沿用服务端 handler 的真实契约。

============================================================
二、页面结构
============================================================
顶栏（固定）：
- 左：第 i 轮 · j 用户操作阶段（或 j 用户下注阶段）
- 右：剩余时间 mm:ss（来自 snapshot.deadlineAt，服务器时间校正）
- 右下角：连接状态（在线/重连中/已替换/离线）

主区域（按阶段只显示其中一块）：
A. 玩家自身信息区：金币、总负债（银行/透支/失信欠款分项）、可借额度、信用、存活/危险
B. 其他玩家信息区：一行“查看其他玩家（不消耗行动）”→ 抽屉列表（昵称/座位/存活/危险/离线/信用/失信欠款）
C. 本轮操作区（核心）：一次一个问题 + 是/否（或选项）+ 金额输入 + 可用范围 + 确认/跳过
D. 结果条：最近一次提交的成功/失败（成功显示变化，失败显示 code + 中文原因），可关闭

============================================================
三、行动阶段（ACTION）
============================================================
仅当 currentSeat 是自己、且没有待处理私人请求时显示“轮到你了”。
待处理请求（自己发出或收到）优先于其他步骤：
- 借款人视角：等待 XX 确认 → 显示倒计时 → “取消请求”（CANCEL_PRIVATE_LOAN，取消不退行动）
- 出借人视角：收到 XX 的借款请求（金额/利率/期限/对方信用与失信欠款）→ 同意 / 拒绝（同意/拒绝都不消耗出借人行动）
- 第三人视角：显示“等待 XX 处理请求”，其余操作禁用

按顺序的引导步骤（每步三选一：提交 / 跳过 / 结束行动）：
Q1 是否向其他玩家借款？
  - 是 → 选择出借人（存活玩家，排除自己；可选列出信用与失信欠款）→ 输入金额（0～可填上限，服务端额度为准）→ 提交 REQUEST_PRIVATE_LOAN
  - 否 → 进入 Q2
Q2 是否向银行借款？
  - 是 → 显示“可用额度 0～X”（X 来自快照可借额度；无资格时显示原因并禁用）→ 输入金额 → 提交 BORROW_BANK
  - 否 → 进入 Q3
Q3 是否还款或催收？
  - 列出可操作项：银行贷款（逐笔，显示剩余/到期轮）→ REPAY_BANK；
    私人合同：我欠别人 → REPAY_PRIVATE；别人欠我 → COLLECT_PRIVATE（显示可催收上限）
  - 没有可操作项时自动跳到 Q4
Q4 结束行动 → 确认 → END_ACTION
  - 任何一步“提交成功”都消耗行动，直接进入“等待其他玩家”状态，不再显示后续步骤
  - 提交失败不消耗行动，停留在当前问题并显示原因

银行到期（BANK_DUE 且 pendingDueLoanId 指向自己）：
- 显示“有一笔银行贷款已到期：金额 X，余额 Y” → 还款（REPAY_BANK）或 拒绝还款（BANK_DUE_DECISION）→ 说明失信后果
- 余额不足时后端会直接判失信，界面仍要显示原因（读 command_result / error）

危险自救（DANGER，dangerSeatId 是自己）：
- 显示“金币为负 X，自救剩余时间”；操作：紧急借款（同 Q1 流程，截止=自救截止）、催收、放弃（RESCUE_GIVE_UP）
- 补到 >=0 时显示“已解除危险”，等待下一座位
- 05C 只做最小可用版；07 再补完整风险摘要

============================================================
四、下注阶段（BETTING）
============================================================
未锁定时按顺序：
Q1 猜哪个点？ → 0 或 1（二选一，大按钮）
Q2 下注金额？ → 0～当前金币；失信者显示“只能一倍”；0 表示不押
Q3 杠杆？ → 1 倍 / 2 倍；失信者只能 1 倍
Q4 确认锁定 → 提交 SUBMIT_BET → 显示“已锁定，等待其他玩家”
锁定后：只显示自己的锁定内容与其他人的“已提交/未提交”，不可改。
提示：别人看不到你的金额/猜测/杠杆（服务器已保证，界面也不得展示他人未开奖内容）。
全员提交或超时后：显示开奖结果卡（自己的输赢与余额变化），然后等下一阶段。

============================================================
五、需要补的命令（05A 未覆盖的）
============================================================
按服务端实际契约补 client 方法（字段以 apps/server 与 game-core handler 为准，别猜）：
- REQUEST_PRIVATE_LOAN（出借人、金额、利率、期限）
- ACCEPT_PRIVATE_LOAN / REFUSE_PRIVATE_LOAN / CANCEL_PRIVATE_LOAN
- REPAY_PRIVATE / COLLECT_PRIVATE
- BANK_DUE_DECISION
- RESCUE_GIVE_UP
已有（05A 已实现，复用）：BORROW_BANK、REPAY_BANK、END_ACTION、SUBMIT_BET。
金额一律十进制字符串，上限 10^12 分；客户端先做本地格式/范围校验，最终以服务端结果为准。

============================================================
六、阶段切换与结算卡
============================================================
- 阶段变化（phase 改变或 round 增加）时，主区域整块替换，并短暂显示“进入 X 阶段”提示。
- 每轮结束显示“第 i 轮结算”：利息、税、下注结果、余额变化；玩家点“继续”后再进入下一轮（若阶段已自动推进，则作为可关闭的摘要卡）。
- 游戏结束显示胜负与最终余额，不再显示操作区。
