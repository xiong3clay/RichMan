一、M1 必须修：StrictMode 开发环境被 dispose，dev 永不发声
位置：apps/web/src/App.tsx:185 "useEffect(() => () => audio.dispose(), [audio]);"
      main.tsx:9 是 React.StrictMode；audio.ts:167-168 unlock 见 disposed 直接 return。
现象（Qoder 已实测）：Vite dev 下 mount→cleanup→mount 后 controller 永久 disposed，
首次 pointerdown 的 unlock() 直接 return，所有 Audio 都不创建；production build 正常。
修法：不要用 React unmount cleanup 调 dispose。改为真实页面离开时释放：
  useEffect(() => {
    const onHide = () => audio.dispose();
    window.addEventListener("pagehide", onHide);
    return () => window.removeEventListener("pagehide", onHide);
  }, [audio]);
要求：不得在 StrictMode 的 cleanup 里 dispose；dev 下 pointerdown 后必须真的 new Audio + play BGM
（可用 window.Audio 探针自查，或写一条渲染 App 后两次 effect 的测试证明未 disposed）。

二、M2 必须修：bgm-loop.wav 直流偏移 -21.626
位置：apps/web/scripts/make-audio.mjs:51-58 addNote、:71-96 renderBgm、:111-134 encodeWav。
原因：主旋律 25% 占空比方波均值 = 2*0.25-1 = -0.5，乘 amplitude=45 得约 -22.5；
低音 50% 与沙锤抵消不了。
修法（推荐，保留 25% 音色）：在 addNote 内做逐样本直流补偿
  const dc = 2 * duty - 1;
  buffer[target] += (square(time, frequency, duty) - dc) * amplitude * envelope(index, lengthSamples);
补偿会把正向峰值抬高 1.5 倍（45*1.5=67.5），叠加低音 30 与沙锤 10 = 107.5 会撞
MAX_AMPLITUDE=100 的钳位。必须同时下调振幅让补偿后峰值仍 ≤100（例如 melody 30、
bass 20、shaker 6，或等价组合），并在脚本里输出/自检实际峰值与均值。
也可改用 50% 占空比或整轨去均值 + 两端重新淡入，但必须满足下面的硬指标。
硬指标（脚本跑完用解码后的 8-bit 数据核）：
  - |PCM 均值| ≤ 2.0（当前 -21.626）；
  - 峰值偏差 ≤ 100（不得靠钳位硬切）；
  - 首样本、末样本均在 128±3（循环接缝不跳）；
  - 时长仍为 16.000s、字节仍为 352844；
  - 连跑两次 sha256 完全一致；
  - 5 个 sfx 的均值也 ≤2.0（当前已合格，不得改坏）。
随后：更新 apps/web/src/audio/manifest.ts 的 AUDIO_SHA256.bgm / AUDIO_BYTES.bgm，
同步四份交接里的 sha256 表；audio.test.ts 增加均值断言（所有 6 个文件）。

三、M3 必须修：事件去重窗口 50 < 事件窗口 300，旧音效反复重播
位置：apps/web/src/App.tsx:204-213（每次 events 变化都 derive 整个 300 条数组）+
      apps/web/src/audio/audio.ts:257-271 takeNewSfx（recent 只保留 50 个 seq）。
现象（Qoder 用仓库外探针复现）：第 52 批起，仍留在 300 条窗口里但已滑出 50 个 seq 的音效
会被当成新事件重播；60 批累计重播 45 次。真实对局超过 50 个音效事件后 win/lose/alert 会乱响。
修法（二选一，推荐 B）：
 A. takeNewSfx 改为不按 50 截断，而是保留至少 300 个 seq 的 Set（覆盖 App 的事件窗口）；
 B. App 维护 playedSfxSeqRef: Set<number>（或 lastSfxSeqRef），derive 仍传完整 300 条
    （LOAN_REQUESTED→CLOSED 的 requestId 映射需要历史），只播放尚未见过的 seq；
    events 清空/新局/房间销毁时清空该 Set（seq 会从 1 重新开始）。
验收：新增回归测试——连续喂 60 批递增事件，同一 seq 只播一次；300 条窗口滚动后旧音效不重播；
新局（events=[] 后再来 seq 1）能重新播。

四、S1 should-fix：持久化 muted=true 时 unlock 仍播 BGM
位置：audio.ts:167-183 unlock 里创建后无条件 safePlay(bgm)。
修法：创建并设置 volume 后只在未静音时播放（if (!current.muted) safePlay(bgm);）；
配合 setMuted(false) 仍能恢复播放。
测试：muted=true → unlock → FakeAudio.playCalls=0；setMuted(false) → playCalls=1。

五、S2 should-fix：SFX play() 被 reject 后 active 数组不清理
位置：audio.ts:135-144 safePlay 只 markUnavailable；:233 active.push 后调用；
reject 不会触发 onended，失败 Audio 留在 active 直到第 4 个或 dispose。
修法：让 safePlay 返回是否启动成功（同步 throw 或 promise reject 都算 false），
playSfx 在 false 时 removeEnded(audio) 并 markUnavailable；补 SFX reject 测试，
断言 active 不再增长/后续 playSfx 返回 false。
