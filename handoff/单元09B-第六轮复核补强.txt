F1 stop：Stop-Process 失败必须失败（Qoder S-2）
现状：stop.ps1 的 catch 只把 warning 加入 $warnings，没有置 $hasUnresolved；
      最终仍打印“已全部停止”、ok=true、exit 0（stop.ps1:69-71、:132-141）。
要求：
  1) catch 中置 $hasUnresolved = $true（复用现有“需人工确认”态），保留 warning。
  2) 存在停止失败时走与 mismatch 相同的失败出口：逐条 WARN、最后一行单行 JSON
     {ok:false, reason:"STOP_FAILED", stopped, warnings, dataDir}、exit 2；
     不得打印“已全部停止”；不得删除该状态文件（进程可能仍在跑）。
  3) 其它 target 已正常停止的结果仍保留在 stopped 数组里。
测试 T13（不允许为测试在生产脚本加开关）：
  用 PowerShell 函数遮蔽 cmdlet 注入失败：
    powershell -NoProfile -Command "function Stop-Process { throw 'ACCESS_DENIED_TEST' }; & '<repo>\scripts\stop.ps1' -DataDir '<dir>'; exit $LASTEXITCODE"
  准备：真实无关 node（setTimeout 120s）+ 真实 StartTime 写入 <dir>/run/server.json。
  断言：exit 2；json.ok=false；json.reason=STOP_FAILED；stdout 不含“已全部停止”；
        状态文件仍存在；dummy 仍存活。
  说明：PowerShell 函数优先于同名 cmdlet，能稳定命中 catch，不需要改生产代码。

F2 status：状态文件不可信时仍探测健康（Qoder S-1）
现状：status.ps1:37-45 在 broken/stale/mismatch 时直接写 reason，只有 else 才请求
      /health；服务实际健康但状态文件过期时误报 ok=false、exit 1（诊断失真）。
要求：
  1) 先算 stateStatus（missing/running/stale/mismatch/unknown/broken）与生效端口
     （显式 -Port > server.json.port > 8000），逻辑与现状一致。
  2) 无论 stateStatus 如何，只要端口 >0 就探测 http://127.0.0.1:<port>/health，
     仍按 ok===true 且 service==='richman' 判定。
  3) 健康时 server.ok=true、rooms/connections 取自健康响应、exit 0；JSON 的
     server 下新增 stateNote（健康时为 ""，否则 stale/mismatch/unknown/broken）；
     非 JSON 输出在 OK 行后追加“注意：状态文件已过期/损坏，进程归属无法确认，
     但端口上的 RichMan 服务健康”。健康时 server.reason 为空串。
  4) 不健康时保持原有 reason 与 exit 1；broken 且不健康时 reason 仍为
     “状态文件损坏，无法确认进程归属”。
  5) status 仍只读，不修改/删除状态文件。
测试：
  T14：起一个返回 {"ok":true,"service":"richman","rooms":0,"connections":0} 的 node
       HTTP 服务（随机端口），写 stale 状态（pid=999999、port=该端口）到临时 dataDir；
       status -Json -Port <port> -DataDir dir → exit 0、server.ok=true、stateNote='stale'。
  T15：同一服务 + 坏 JSON server.json → exit 0、server.ok=true、stateNote='broken'。
  两条都必须用真实 HTTP，不允许源码字符串 smoke。
