二、M1（必须）：停止脚本会杀掉“复用了旧 PID 的陌生进程”
现状事实（已复核）：
- scripts/richman-common.ps1:110-131 Get-ProcessInfo 只校验 pid 存活 + 进程名，
  完全不读 state.startedAtUtc；
- scripts/start-lan.ps1:156-163 的 startedAtUtc 是在健康检查通过之后才取 [DateTime]::UtcNow，
  并不是真实进程启动时间；
- Qoder 实测：写出 startedAtUtc=2020 的状态指向一个无关 node 进程，stop.ps1 仍然把它杀了。

F1.1 状态文件记录“真实进程启动时间”
- start-lan 与 start-tunnel 都改为：Start-Process 之后立刻读取真实启动时间，
  health 检查与写状态都使用这一个值：
    $process = Start-Process ... -PassThru
    $startedAtUtc = ''
    try {
        $procInfo = Get-Process -Id $process.Id -ErrorAction Stop
        $startedAtUtc = $procInfo.StartTime.ToUniversalTime().ToString('o')
    } catch {
        # 读不到说明子进程立刻退出了，走失败清理
    }
  写状态时 startedAtUtc = $startedAtUtc（不要再用 [DateTime]::UtcNow）。
  若 $startedAtUtc 为空：视为启动失败，清理子进程后 exit 1。

F1.2 新增 Get-RunStateProcess，替换 Get-ProcessInfo 的全部 4 处调用
（start-lan.ps1:57、start-tunnel.ps1:27、stop.ps1:36、status.ps1:42）。
返回一个有序字典（PS 5.1 支持 [ordered]@{}），字段：
  status：missing | stale | running | mismatch | unknown
  reason：给用户看的中文原因
  process：存活且身份匹配时的 System.Diagnostics.Process，否则 $null
  pid：状态里的 pid（无效则 0）
判定顺序：
  1) State 为 null → missing（没有状态文件或为空）。
  2) pid 解析失败或 <= 0 → unknown，reason='状态文件中的 pid 无效'。
  3) Get-Process -Id 为空 → stale，reason='进程已退出'。
  4) 进程名不是期望值（server=node，tunnel=cloudflared）→ mismatch，
     reason='pid 现在属于 <名字>，不是 <期望>'。
  5) State.startedAtUtc 缺失/空白 → unknown，
     reason='状态文件缺少 startedAtUtc，无法确认进程归属'。
  6) 解析 startedAtUtc（InvariantCulture + AdjustToUniversal）失败 → unknown，
     reason='startedAtUtc 无法解析'。
  7) 与 $process.StartTime.ToUniversalTime() 比较，绝对差 > 2 秒 → mismatch，
     reason='进程启动时间与状态文件相差 N 秒，pid 可能已被复用'。
  8) 否则 status='running'，process=$process。
可以保留 Get-ProcessInfo 作为薄包装（内部调用新函数），也可以直接删掉它，
但四个脚本里不允许再出现“只看进程名就 Stop-Process”的路径。

F1.3 各脚本的语义
- stop.ps1：
  * missing：保持现状（跳过；最终 stopped 为空则打印“未在运行”）。
  * stale：打印 WARN，清理状态文件，继续（原有行为）。
  * running：CheckOnly 时进 planned；否则 Stop-Process 后删状态。
  * mismatch / unknown：绝不 Stop-Process、绝不删状态文件，
    追加 warning：'状态文件 <path> 与进程不匹配（<reason>），未杀进程，'
    '请人工确认后删除状态文件或手动停止。'；
    该轮 ok=false，脚本最终 exit 2（即使其它进程已成功停止，也要 exit 2）。
  * CheckOnly 的 planned 项要带 port（见 F6）。
- start-lan.ps1：alreadyRunning 只在 status==='running' 且 Wait-HttpHealth 通过时为 true。
  mismatch/unknown 时只打印一行提示，不要停进程、不要删状态（后续端口检查会兜底）。
- start-tunnel.ps1：alreadyRunning 只在 status==='running' 且有 url 时为 true。
- status.ps1：processRunning 只在 status==='running' 时为 true；
  状态文件存在但 mismatch/unknown/stale 时，在 server.reason / tunnel.reason 里
  写清楚（tunnel 增补 reason 字段，保持向后兼容的字段名）。
