二、M1：zip 缺文件仍 PASS
现状：scripts/verify-release.mjs:228-249 的 zip_extract 只核对 zip 顶层目录、VERSION、server.mjs 三项；
scripts/release-lib.mjs:159-161 的 REQUIRED 只约束 staging，没有约束解压后的 zip。
复现：复制 release/RichMan-v0.9.0-win-x64，删除 app/server/backup-cli.mjs，重新压 zip，
      写临时 SHA256SUMS.txt，再跑
      node scripts/verify-release.mjs --dir <原始 staging> --zip <临时 zip>
实际：exit 0、12 项 PASS；期望：exit 1，指出 zip 缺 backup-cli。
修法（必须）：
1) release-lib.mjs 新增并导出：
   export async function comparePackageDirs(expectedDir, actualDir)
   - 递归列出两边全部文件（相对路径、/ 分隔、排序）；
   - 缺文件 -> problems.push("缺少文件：" + rel)
   - 多文件 -> problems.push("多余文件：" + rel)
   - 两边都有：先比 size，再比 SHA256（大写），不一致分别 push
     "文件大小不一致：" + rel / "文件内容不一致：" + rel；
   - 返回 { ok, files: actualFiles.length, bytes, problems }。
2) verify-release.mjs 的 zip_extract 改为：
   - 期望顶层目录名由版本推导：const expectedTop = "RichMan-v" + version + "-win-x64";
     不再用 path.basename(options.dir)（这样 --dir 指向副本时也能正确校验）。
   - Expand-Archive 后：
     const extractedCheck = await validateStaging(extractedDir, { version, nodeVersion });
     若 !ok，抛 "zip 内容不完整：" + problems 前 10 条。
   - const diff = await comparePackageDirs(options.dir, extractedDir);
     若 !ok，抛 "zip 与 staging 不一致：" + problems 前 10 条。
   - 记录 detail 包含 topName、extractedCheck.files、extractedCheck.bytes、server.mjs 前 12 位 hash。
   - 这样 zip 缺 backup-cli、缺 index.html、缺 bat、多文件、hash 被替换都会红。

三、M2：无扩展名 LICENSE 写 token 仍 PASS
现状：verify-release.mjs:182-188 只扫扩展名白名单，secretPattern 只匹配 JSON 键值。
复现：复制 staging，向根 LICENSE 追加 {"sessionToken":"ABCDEFGH12345678"}，只更新副本
      SHA256SUMS.txt 中 LICENSE 的 hash，再跑
      node scripts/verify-release.mjs --dir <副本 RichMan-v0.9.0-win-x64> --zip <原 zip>
实际：exit 0、secret_scan PASS；期望：exit 1，报 LICENSE 疑似明文。
修法（必须）：
1) release-lib.mjs 新增并导出：
   const BINARY_EXTENSIONS = new Set([".exe",".dll",".node",".zip",".gz",".7z",".mp3",".wav",".ogg",".png",".jpg",".jpeg",".gif",".ico",".woff",".woff2",".ttf",".otf",".eot",".pdf"]);
   const MAX_SCAN_BYTES = 2 * 1024 * 1024;
   const SECRET_PATTERN = /(?:sessionToken|recoveryCode)["']?\s*[:=]\s*["']?[A-Za-z0-9_-]{8,}|(?:^|[^A-Za-z0-9_])token["']?\s*[:=]\s*["']?[A-Za-z0-9_-]{8,}/i;
   export async function scanSecrets(dir)：
   - 遍历全部文件；扩展名在 BINARY_EXTENSIONS 的跳过；size > MAX_SCAN_BYTES 跳过；
   - 读 Buffer，含 0 字节跳过（二进制兜底）；
   - 转 utf8，SECRET_PATTERN.test 命中则 push 相对路径；
   - 返回命中数组。
2) verify-release.mjs：
   - 删除旧 textExtensions/secretPattern 块；
   - 在 zip_extract 之后统一做：
     let secretHits = await scanSecrets(options.dir);
     if (extractedDir !== null) secretHits = secretHits.concat((await scanSecrets(extractedDir)).map(x => "zip:" + x));
     if (secretHits.length > 0) record("secret_scan", false, "疑似明文 token/恢复码：" + secretHits.join(","));
     else record("secret_scan", true, "staging 与 zip 均未发现 token/recovery 明文");
   - 包内真实数据必须仍然 PASS（Lead 已预扫：扩展名+无扩展名全部文件，命中 0）。
